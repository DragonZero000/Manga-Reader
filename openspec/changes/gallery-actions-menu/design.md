## Context

- Сетка (`galleryGrid`) — `widget.GridWrap` с переиспользуемыми `galleryCard`; нажатие обрабатывается через `OnSelected`.
- «Открыть в браузере» уже реализовано колбэком `Details.SetOpenURL`, который Shell настраивает под платформу (Firefox на Windows, GeckoView на Android, системный браузер иначе).
- Интерфейс `storage.Storage` только читает (`Name`, `Walk`, `Open`). На Android удаление документа через SAF есть только в Kotlin (`DownloadManager`, для `.part`); Go-часть SAF (`saf_android.go`) работает через JNI и кэширует id документов после `Walk`. Проверка доступа на запись есть (`Services.NeedsWriteAccess`, диалог в `shell.setupMobileBrowser`).
- Архивы не удерживаются открытыми: `Source.OpenPage` открывает zip только на время чтения страницы.
- Слои: страница произведения и читалка перекрывают вкладки, поэтому сейчас из сетки нельзя вызвать удаление открытого в читалке произведения.

## Goals / Non-Goals

**Goals:**
- Меню на карточке и странице произведения, удаление в корзину / через SAF, «Показать в папке», копирование названия.
- Основа для проверки «произведение открыто».

**Non-Goals:**
- Множественный выбор и массовое удаление.
- Переименование, перемещение между папками, «Отменить» после удаления.
- Удаление файлов из вкладки «Ошибки» (требование `library-errors` «Ошибочные файлы не удаляются» не меняется: меню есть только у галерей).
- «Показать в папке» на Android.

## Decisions

### Кнопка и меню

- `menuButton` — свой виджет (`Tappable`, `Hoverable` на ПК): `canvas.Circle` с цветом фона темы и альфой ≈ 0x99, поверх `theme.MoreVerticalIcon()`. Размер круга ≈ 28 dp, область нажатия ≥ 40 dp (прозрачная рамка). Располагается в `Stack` обложки через раскладку «правый верхний угол».
- Касание вложенного `Tappable` внутри элемента GridWrap: Fyne доставляет событие самому глубокому объекту под точкой, поэтому `OnSelected` сетки не срабатывает. Это проверяется тестом (`test.Tap` по кнопке → меню, а не `onOpen`).
- Меню — `widget.ShowPopUpMenuAtPosition` с `fyne.Menu`. Пункты строятся при открытии по галерее и платформе.
- `galleryCard` реализует `SecondaryTappable`: правый клик на ПК и долгое нажатие на телефоне (Fyne на мобильных превращает долгое нажатие во вторичное касание) открывают то же меню в точке касания.
- Карточка переиспользуется, поэтому кнопка берёт галерею из сетки по текущему `id` в момент нажатия, а не запоминает её при создании.

### Колбэки действий

`galleryGrid` получает структуру `actions` (open, read, openURL, copyTitle, showInFolder, delete). Её собирает Shell: у него есть читалка, страница произведения, toast и сервисы. `nil` — пункта нет (например, `showInFolder` на Android, `openURL`, если нет браузера). `Details` получает тот же набор для своего «⋮».

### Удаление

```
UI (UI-поток)                          фон                                  UI (fyne.Do)
─────────────                          ───                                  ────────────
inUse(key)? ─да─► toast «открыто»
NeedsWriteAccess? ─да─► диалог «нужен доступ на запись» → ChooseFolder
Trashable(rel)?  (Windows: корзина на диске)
Confirm(текст по способу) ──ок──► go src.Delete(rel, permanent) ──► ok  ─► Details.Close (если открыта эта)
                                                                       grid.Remove(key) в библиотеке и поиске
                                                                       updateCount, RequestScan
                                                            └─ err ─► toast(errText(err))
```

- `storage.Storage` расширяется необязательным интерфейсом `Deleter { CanTrash(rel) (bool, error); Delete(rel string, permanent bool) error }`. Необязательным — чтобы тестовые и будущие хранилища без удаления не ломались. `library.Source.Delete(key, permanent)` проверяет, что хранилище умеет удалять (иначе `ErrUnsupported`), удаляет файл и помечает его в кэше сканера (`Invalidate`).
- **Windows** (`internal/storage/trash_windows.go`): проверка наличия корзины — `SHQueryRecycleBinW` для корня диска папки (ошибка → корзины нет), дополнительно `GetDriveTypeW` ∈ {REMOTE, REMOVABLE} → корзины нет. Удаление: `SHFileOperationW(FO_DELETE, FOF_ALLOWUNDO | FOF_NOCONFIRMATION | FOF_SILENT | FOF_NOERRORUI)`; безвозвратное — `os.Remove`. Ошибка совместного доступа (`ERROR_SHARING_VIOLATION`, `ERROR_LOCK_VIOLATION`) → `ErrBusy`. Альтернатива `IFileOperation` (COM) гибче, но сложнее при том же результате.
- **Android** (`saf_android.go`): JNI `DocumentsContract.deleteDocument(cr, documentUri)`; URI документа строится из дерева и id документа, известного после `Walk` (если id нет — поиск по пути от корня). `CanTrash` → false.
- **Прочие** (`*_other.go`): `ErrUnsupported`.
- Проверка пути: `rel` очищается (`path.Clean`), пути с `..` и абсолютные отклоняются — так же, как в `FS.path`.

**Немедленное обновление экранов.** `galleryGrid.Remove(key)` убирает элемент из `items` и вызывает `Refresh`; библиотека и поиск обновляют счётчики и активность кнопки 🎲. Затем `RequestScan` приводит в порядок каталог, индекс, ошибки и ссылки (`PruneLinks` вызывается после сканирования). На Windows изменение также заметит `Watcher` — повторный скан безвреден.

### «Открыто в читалке»

`Shell.inUse(key) = Reader.Visible() && Reader.Gallery().Key == key`. Сейчас условие недостижимо из интерфейса (читалка перекрывает сетку и страницу произведения), но проверка выполняется перед каждым удалением и покрыта тестом через прямой вызов. Страница произведения не считается «открытым произведением»: при удалении с неё она закрывается после успеха.

### «Показать в папке» (Windows)

`internal/ui` не вызывает Win32 напрямую. Функция `storage.Reveal(root, rel)`: `ILCreateFromPathW` + `SHOpenFolderAndSelectItems` (повторно использует открытое окно Проводника). Альтернатива `explorer.exe /select,<path>` проще, но каждый раз открывает новое окно и хуже работает с путями, где есть запятые. На остальных платформах `Reveal` → `ErrUnsupported`, пункт не показывается.

### Копирование названия

`fyne.CurrentApp().Clipboard().SetContent(g.Title)` + toast.

### Потоки

Меню, диалоги, `Remove`, toast — UI-поток. `Delete`, `CanTrash` (может опрашивать сетевой диск), `Reveal` — в горутине, результат через `fyne.Do`.

## Risks / Trade-offs

- [`SHQueryRecycleBinW` на некоторых дисках отвечает успехом, но `FOF_ALLOWUNDO` всё равно удаляет безвозвратно] → дополнительная проверка типа диска; в худшем случае это как «Удалить» в Проводнике без корзины. Проверить на флешке FAT32 и сетевом диске.
- [Файл заблокирован потоком миниатюр в момент удаления] → доли секунды; `ErrBusy` → toast, пользователь повторяет.
- [Браузер ещё докачивает файл с тем же именем] → `.part` — другой файл; сам архив создаётся переименованием после загрузки, конфликт маловероятен.
- [Долгое нажатие на телефоне конфликтует с прокруткой] → Fyne отменяет вторичное касание при начале перетаскивания; проверить на устройстве.
- [Кнопка «⋮» перекрывает часть обложки при 4 в ряд] → полупрозрачный фон, 28 dp; проверить на 360 dp.

## Platforms

| | Windows | Android | Прочие (Linux — в планах) |
|---|---|---|---|
| Меню, «Открыть», «Читать», «Скопировать» | да | да | да |
| «Открыть в браузере» | Firefox | GeckoView | системный браузер |
| «Показать в папке» | `SHOpenFolderAndSelectItems` | нет пункта | нет пункта (заглушка) |
| Удаление | корзина / безвозвратно, если корзины нет | SAF, безвозвратно, нужен доступ на запись | `ErrUnsupported`, пункт скрыт |
