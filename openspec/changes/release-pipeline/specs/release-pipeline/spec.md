## ADDED Requirements

### Requirement: Проверка на каждый push и pull request
Репозиторий SHALL запускать проверку (GitHub Actions) на каждый push в любую ветку и на каждый pull request: `go vet ./...` и `go test ./...` на Windows, а также сборку APK без подписи на Linux-раннере. Проверка MUST NOT требовать секретов, поэтому работает и для pull request из форков. Упавший шаг MUST отмечать проверку как неуспешную.

#### Scenario: Сломанный тест
- **WHEN** в pull request есть изменение, из-за которого падает `go test`
- **THEN** проверка pull request неуспешна, и в журнале видно, какой тест упал

#### Scenario: Pull request из форка
- **WHEN** pull request открыт из форка без доступа к секретам репозитория
- **THEN** проверка выполняется полностью и не пытается подписать APK

#### Scenario: Сломанная Android-сборка
- **WHEN** изменение ломает сборку `libmangareader.so` или Gradle-проекта
- **THEN** проверка неуспешна, хотя `go test` проходит

### Requirement: Релиз по тегу версии
Push тега вида `vX.Y.Z` SHALL запускать сборку релиза. Сборка MUST сначала сверить тег с `Version` из `FyneApp.toml` (без префикса `v`) и остановиться с понятной ошибкой, если они не совпадают. Затем она MUST выполнить `go vet` и `go test` и только после их успеха собирать пакеты. Теги другого вида MUST NOT запускать сборку релиза.

#### Scenario: Тег совпадает с версией
- **WHEN** в `FyneApp.toml` указано `Version = "0.2.0"` и в репозиторий отправлен тег `v0.2.0`
- **THEN** запускается сборка релиза `0.2.0`

#### Scenario: Тег не совпадает
- **WHEN** в `FyneApp.toml` указано `0.2.0`, а отправлен тег `v0.3.0`
- **THEN** сборка останавливается до компиляции с сообщением, что тег `v0.3.0` не совпадает с версией `0.2.0` в `FyneApp.toml`

#### Scenario: Посторонний тег
- **WHEN** отправлен тег `test-build`
- **THEN** сборка релиза не запускается

### Requirement: Состав релиза
Релиз `X.Y.Z` SHALL содержать файлы:
- `MangaReader-X.Y.Z-windows-x64.zip` — портативная папка `MangaReader\` с `mangareader.exe`, `browser\firefox\` (Firefox ESR закреплённой версии), `LICENSE` и `THIRD_PARTY_NOTICES.md`;
- `MangaReader-X.Y.Z-android-arm64.apk` — release-APK, подписанный постоянным ключом проекта;
- `SHA256SUMS.txt` — SHA-256 обоих файлов в формате `sha256sum`.

Версия внутри пакетов MUST совпадать с `X.Y.Z`.

#### Scenario: Проверка файлов релиза
- **WHEN** пользователь скачивает все три файла и выполняет `sha256sum -c SHA256SUMS.txt`
- **THEN** проверка обоих файлов проходит

#### Scenario: Windows-пакет
- **WHEN** пользователь распаковывает zip и запускает `MangaReader\mangareader.exe`
- **THEN** приложение запускается в портативном режиме с версией `X.Y.Z` в логе, а кнопка «Браузер» открывает встроенный Firefox без дополнительных загрузок

#### Scenario: Android-пакет
- **WHEN** на телефоне установлен APK релиза `0.2.0`, и пользователь устанавливает APK релиза `0.3.0`
- **THEN** установка проходит как обновление, без удаления приложения и с сохранением настроек и выбранной папки

### Requirement: Черновик релиза
Сборка релиза SHALL создавать GitHub Release в состоянии черновика с названием `MangaReader X.Y.Z`, приложенными файлами и заметками, которые GitHub генерирует из изменений с предыдущего тега. Публикация черновика MUST выполняться автором вручную. Если хотя бы один пакет не собрался, черновик MUST NOT создаваться.

#### Scenario: Успешная сборка
- **WHEN** все пакеты собраны
- **THEN** в разделе Releases появляется черновик `MangaReader X.Y.Z` с тремя файлами, невидимый для посетителей до публикации

#### Scenario: Сбой одного пакета
- **WHEN** Windows-пакет собран, а сборка APK упала
- **THEN** черновик не создаётся, а в журнале видна причина сбоя

### Requirement: Ключ подписи хранится только в секретах
Ключ подписи APK и его пароли SHALL храниться только в зашифрованных секретах GitHub (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`). Во время сборки ключ MUST восстанавливаться во временный файл вне рабочей копии и MUST NOT попадать в файлы релиза, кэши и журналы. Если хотя бы один секрет не задан, сборка релиза MUST останавливаться с сообщением, какого секрета нет.

#### Scenario: Нет секрета
- **WHEN** секрет `ANDROID_KEYSTORE_BASE64` не задан, и отправлен тег `v0.2.0`
- **THEN** сборка APK завершается ошибкой «не задан секрет ANDROID_KEYSTORE_BASE64», черновик не создаётся

#### Scenario: Журнал сборки
- **WHEN** сборка релиза завершилась
- **THEN** в журнале нет содержимого ключа и паролей (GitHub маскирует значения секретов)

### Requirement: Лицензии внутри пакетов
Пакеты для всех платформ SHALL содержать `LICENSE` и `THIRD_PARTY_NOTICES.md` из того же коммита, из которого собран пакет: в zip для Windows — в корне папки `MangaReader\`, в APK — в `assets/`. То же MUST выполняться и для локальных сборок `make package-windows` и `make build-android`.

#### Scenario: Windows
- **WHEN** выполнен `make package-windows`
- **THEN** в `dist/MangaReader/` лежат `LICENSE` и `THIRD_PARTY_NOTICES.md`

#### Scenario: Android
- **WHEN** выполнен `make build-android`, и APK открыт как zip-архив
- **THEN** в нём есть `assets/LICENSE` и `assets/THIRD_PARTY_NOTICES.md`
