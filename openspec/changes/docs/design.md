## Context

Сейчас вся документация — `README.md` на русском (215 строк): скачивание, требования, команды, Android-сборка, выпуск релиза и ключи, папка библиотеки, переход со старых версий, браузер Windows и Android, формат архива (без заголовка), ошибки, структура пакетов. Читалка, поиск, страница произведения и настройки не описаны, но подробно специфицированы в `openspec/specs/` (`reader`, `search-syntax`, `search-screen`, `gallery-details`, `library-view`, `app-shell` и др.). Это главный источник фактов для руководства пользователя наравне с кодом `internal/ui`.

`openspec/config.yaml` уже фиксирует раскладку документации (`README.md` en + `README.ru.md`, `docs/en` + `docs/ru`) и правило обновлять оба языка.

Платформы: документация описывает Windows и Android, Linux упоминается как неподдерживаемый. Код приложения не меняется, добавляется только тест.

## Goals / Non-Goals

**Goals:**
- Англоязычный посетитель понимает проект по `README.md`.
- Пользователь находит в руководстве ответ про любую функцию приложения.
- Разработчик собирает проект и выпускает релиз только по `building.md`.
- Расхождение языков и битые ссылки ловятся тестами, а не читателями.

**Non-Goals:**
- Перевод UI, сайт документации, перевод `THIRD_PARTY_NOTICES.md`, Linux.

## Decisions

### D1. Раскладка
```
README.md          README.ru.md          ← витрина
CONTRIBUTING.md    CONTRIBUTING.ru.md
docs/
├── en/  user-guide.md  building.md  architecture.md
├── ru/  user-guide.md  building.md  architecture.md
└── images/  *.png                       ← общие скриншоты
```
Параллельные папки `docs/en`/`docs/ru` с одинаковыми именами: относительные ссылки между документами совпадают в обоих языках, перевод не требует правки путей. В корне — суффикс `.ru.md`, потому что GitHub показывает на главной только `README.md`.
Переключатель — первая строка каждого файла: `**English** | [Русский](README.ru.md)` и зеркально.

### D2. Английский — основной язык витрины, русский — полноценный
`README.md` на английском: GitHub и поиск показывают его первым. Оба языка полные, без «см. английскую версию». Порядок работы при реализации: сначала пишется русский текст (источник фактов — нынешний README и спецификации), затем английский перевод, после чего оба сверяются по структуре заголовков.

### D3. Названия элементов интерфейса
Интерфейс на русском, поэтому в английских документах элементы называются так, как их видит пользователь, с переводом при первом упоминании: «**Библиотека** (Library)», дальше — «the **Библиотека** tab». Иначе пользователь не найдёт на экране кнопку «Library». Когда появится i18n, названия заменяются на английские.

### D4. Что куда переезжает из нынешнего README
| Раздел README | Куда |
|---|---|
| Скачать, установка APK | README (кратко) |
| Требования, Команды, Сборка Android | `building.md` |
| Выпуск релиза, ключ и секреты | `building.md` — подробная пошаговая инструкция (создание ключа, проверка, таблица секретов, `gh secret set` и веб-интерфейс, проверка по SHA-256, резервная копия) |
| Папка библиотеки ПК/Android | `user-guide.md` |
| Переход со старых версий | **удаляется**: публичных версий до `0.1.0` не было |
| Переход с `fyne package` (в Android-разделе) | **удаляется** по той же причине |
| Браузер Windows/Android | `user-guide.md` (поведение), `architecture.md` (устройство: мост, профиль, реестр, JNI) |
| Формат архива (потерянный заголовок) | `user-guide.md`, раздел «Формат архива» с таблицей полей `meta.json` |
| Ошибки | `user-guide.md` |
| Структура | `architecture.md` (расширенно: границы, теги, потоки) |

Новые разделы `user-guide.md` — библиотека, страница произведения, читалка, поиск с синтаксисом, настройки — пишутся по спецификациям и проверяются по коду `internal/ui`. Спецификация описывает требования, но текст на кнопке берётся из кода.

### D5. Проверка — тест в `internal/archtest`
`internal/archtest/docs_test.go` запускается в `go test ./...`, а значит, и в `make test`, и в CI без правок workflow. Отдельная утилита в `tools/` потребовала бы отдельного шага в CI и не запускалась бы локально в `make test`. Описание пакета меняется: «проверяет архитектурные границы и структуру документации».

Тест:
- находит корень репозитория (поднимается от рабочей папки до `go.mod`);
- **парность**: множества имён `*.md` в `docs/en` и `docs/ru` равны; есть `README.ru.md` и `CONTRIBUTING.ru.md`;
- **переключатель**: в первых 5 строках документа есть ссылка на его пару (для `docs/en/x.md` — `../ru/x.md`, для `README.md` — `README.ru.md` и т. д.);
- **ссылки**: разбирает `[текст](цель)`, `![alt](цель)` и `<img src="цель">` вне блоков кода (```` ``` ```` и строки с отступом не учитываются). Пропускает цели со схемой (`http:`, `https:`, `mailto:`) и чистые якоря (`#…`). У остальных отбрасывает `#якорь` и `?…`, декодирует `%xx` и проверяет существование файла или папки относительно документа (цель с `/` в начале — относительно корня репозитория).
- Ошибка содержит путь документа, номер строки и цель ссылки.

Проверяются корневые `README*`, `CONTRIBUTING*` и всё в `docs/`. `THIRD_PARTY_NOTICES.md` тоже проверяется на ссылки: он ссылается на файлы проекта, и они могут переехать.

*Альтернативы:* markdown-link-check или lychee в CI — внешняя зависимость и сеть, локально не запускается; проверка якорей заголовков — у GitHub своя схема slug для кириллицы, риск ложных срабатываний, отложено.

### D6. Скриншоты
Файлы в `docs/images/`, имена по смыслу: `library-windows.png`, `reader-windows.png`, `details-windows.png`, `search-windows.png`, `library-android.png`, `browser-android.png`. PNG, ширина ≤ 1600 px (Windows) и ≤ 1080 px (Android), без личных данных: тестовая библиотека из свободных изображений или `testdata/example.zip`. Делает автор: для снимков нужны реальный экран Windows и телефон. В README — 2–3 снимка, остальные в `user-guide.md`. Если к моменту реализации скриншотов нет, README пишется без них, а задача остаётся открытой.

### D7. Описание репозитория на GitHub
Не файл, а настройки: About — «Offline manga reader for Windows and Android with a built-in Firefox-based browser (Go + Fyne)», Topics — `manga`, `manga-reader`, `comic-reader`, `go`, `fyne`, `android`, `windows`, `geckoview`, `firefox`. Автор вставляет сам: `gh repo edit DragonZero000/Manga-Reader --description … --add-topic …`.

## Risks / Trade-offs

- [Документация отстанет от кода] → правило в `openspec/config.yaml` (задача на документацию в каждом изменении), тест ловит пропущенный перевод и битые ссылки, но не устаревший текст — это остаётся на ревью.
- [Большой объём перевода] → структура заголовков обоих языков одинакова, что упрощает сверку; при реализации — задача на сверку.
- [Регулярки для ссылок ошибаются на экзотическом Markdown] → проверяются только наши документы, формат простой; при ложном срабатывании правится текст или тест.
- [Скриншоты устаревают при изменении UI] → их немного, а имена файлов отражают экран, так что устаревший снимок легко найти.
- [Русские названия кнопок в английском тексте выглядят непривычно] → осознанный компромисс до i18n (D3).

## Migration Plan

Только документация и тест. Старый README заменяется целиком. Внешних ссылок на его разделы нет: репозиторий только что опубликован.
