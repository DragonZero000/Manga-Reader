## Context

Сейчас `readEntry` (`internal/library/scanner.go`) принимает только файлы с расширением `.zip`, а чтение страниц (`Source.openGallery`, `source.go`) работает прямо с `*zip.Reader`. Тип файла по содержимому уже умеет определять `Sniff` (`sniff.go`), но используется только для текста ошибки. Метаданные читает один `meta.json` (`meta.go`, `applyMeta`). Пример для разработки: `testdata/cbz-example.cbz` (5 jpg, `meta.json`, `ComicInfo.xml`) и zip с 28 `.webp` без метаданных (`temp/`, уже открывается).

## Goals / Non-Goals

**Goals:**
- Открывать `.cbz` и любой zip независимо от расширения.
- Читать `ComicInfo.xml` как второй источник метаданных с приоритетом `meta.json`.
- Подготовить чтение страниц к другим контейнерам и добавить RAR/7z после решения пользователя.

**Non-Goals:**
- PDF, EPUB, AVIF/JXL, папки как галереи, `Manga`/`AgeRating`, изменение названий из имён файлов.

## Decisions

**1. Тип по содержимому, а не по расширению.** `readEntry` вызывает `Sniff(f)`; `KindZip` ведёт в `ReadArchive` независимо от расширения. Расширение `.zip` больше не требуется, ветка «zip с другим расширением» в `UnsupportedError` удаляется. Альтернатива — добавить список расширений `.zip/.cbz`: отвергнута, потому что `.cbz`-файлы бывают переименованными, а `Sniff` уже есть и тестируется. Платформы: код общий для Windows и Android, build-тегов не требует.

**2. Метаданные: слияние, а не выбор.** Новый разбор `ComicInfo.xml` (стандартный `encoding/xml`, лимит чтения тот же `maxMetaSize` = 4 МиБ) даёт промежуточную структуру. `applyMeta` вызывается сначала для `meta.json`, затем `ComicInfo.xml` заполняет только пустые поля: название, японское название, ссылку, дату, число страниц и теги, которых нет в `meta.json` (сравнение тега по `type:name` без учёта регистра). Если `meta.json` нет или он некорректен, галерея строится только из `ComicInfo.xml`. `HasMeta` истинно, если применён хотя бы один источник (от этого зависит `missing:meta`). Некорректный XML даёт предупреждение сканирования, как некорректный `meta.json`. Если в архиве несколько `ComicInfo.xml`, берётся наименее вложенный, как у `meta.json`.

**3. Соответствие полей** — по `proposal.md`: `Title`/`Series`+`Number` → название, `AlternateSeries` → японское, `Tags` по запятой (обрезка пробелов, пустые пропускаются) → `tag`, `Characters` → `character`, `LanguageISO` → `language` (код в название языка, неизвестный код сохраняется как есть), `Format` → `category`, `Writer`/`Penciller` → `artist`, `Publisher` → `group`, `Year`/`Month`/`Day` → дата загрузки (UTC, отсутствующие месяц/день = 1), `PageCount` → число страниц, `Web` → ссылка, только если URL содержит непустой путь (кроме `/`). `Manga` и `AgeRating` игнорируются.

**4. Абстракция контейнера для RAR/7z.** Выделяется интерфейс архива (список записей с именем, размером, CRC/идентификатором, открытие записи), которым пользуются `ReadArchive` и `Source.openGallery`; для zip — тонкая обёртка над `archive/zip`, поведение не меняется. Отпечаток (`fingerprint`) сейчас опирается на CRC32 и размер из оглавления zip; для RAR и 7z тоже есть CRC32 в заголовках, поэтому формула остаётся той же. Если CRC недоступен, запись получает нулевое значение, а отпечаток всё равно считается.

**5. Solid-архивы RAR/7z.** Страницу нельзя достать, не распаковав всё перед ней. Такие архивы при первом открытии распаковываются во временную папку кэша (`os.UserCacheDir` на Windows, каталог кэша приложения на Android), общий лимит размера кэша — константа (решает пользователь на этапе RAR/7z), очистка при выходе и при превышении лимита (самые давние первыми). Обычные (не solid) архивы читаются напрямую. Альтернатива — распаковывать всё при сканировании: отвергнута, потому что сканирование должно оставаться быстрым и не писать на диск.

**6. Этап RAR/7z с проверкой пользователем.** Сначала отдельная проверка (не часть релиза): подключить `nwaples/rardecode/v2` (BSD-2) и `bodgit/sevenzip` (BSD-3) в отдельной ветке, собрать под Windows (amd64) и Android (x86_64 эмулятор, arm64), измерить прирост размера APK/exe и проверить RAR5 и solid на реальных файлах. Результат сообщается пользователю, он решает по каждой библиотеке отдельно. Без решения код RAR/7z не мёржится; сообщения об ошибке для RAR/7z остаются прежними («RAR/7z — поддерживаются только zip-архивы» заменяется на актуальный текст, только если формат принят).

**7. Thread safety.** Изменения только в сервисных пакетах (`internal/library`), виджетов нет; `fyne.Do` не требуется. Скан остаётся в фоновой горутине, как сейчас.

## Risks / Trade-offs

- [Ложные срабатывания `Sniff`: не-zip файл с zip-сигнатурой, например `.docx`/`.apk`/`.epub`] → такие файлы разберутся как zip, не найдут изображений и дадут `ErrNoImages` («нет изображений»); текст ошибки это покрывает. EPUB — тоже zip, у него сейчас причина «нет изображений» или, если внутри есть картинки, он откроется как галерея; принимается, EPUB как формат не поддерживается.
- [`ComicInfo.xml` в разных кодировках (UTF-8 с BOM, UTF-16)] → читаем с BOM-обработкой; нераспознанная кодировка = предупреждение, галерея строится без XML.
- [Слияние тегов даёт дубли] → сравнение по `type:name` без регистра.
- [Размер: RAR/7z + зависимости увеличат бинарник] → решение пользователя по результатам измерений; `golang-lru` (MPL-2.0, зависимость `sevenzip`) требует записи в `THIRD_PARTY_NOTICES.md`.
- [Solid-кэш на диске] → лимит размера и очистка; на Android — каталог кэша приложения, который система может очистить.
- [Каталог `library.db`] → ключ галереи строится из пути, `.cbz` не требует миграции; при смене логики разбора уже сохранённые записи об ошибках `.cbz` (если были) исчезают при следующем скане, так как identity записи — путь+размер+время, а новый результат — галерея.

## Migration Plan

Миграции данных нет. `user.db` привязан к отпечатку страниц и не зависит от расширения файла, поэтому переименование `.zip` ↔ `.cbz` сохраняет теги и прогресс. Откат — вернуть прежнюю проверку расширения; библиотека пересканируется.
