## Context

Экран поиска (`internal/ui/screens/search.go`) сейчас устроен так: `OnChanged` запускает `time.AfterFunc(300ms)`, а `OnSubmitted` и кнопка 🔍 вызывают `Run()`. `Run()` всегда берёт текущий `entry.Text`: пустое поле показывает справку, ошибка разбора пишется в статус, поиск идёт в горутине, а результат применяется через `s.do` (`fyne.Do`) с проверкой номера запуска `seq`. Оболочка (`internal/ui/shell.go`) вызывает `Rerun()` при открытии вкладки и после сканирования, а `SearchFor` вызывает `SetQuery(text)`.

Изменение затрагивает только UI и настройки. Индекс (`search.Index`) и разбор (`search.Parse`) не меняются. Платформы — Windows и Android, код общий, build-теги не нужны.

## Goals / Non-Goals

**Goals:**
- два режима запуска запроса и выбор между ними в настройках;
- кнопка ✕, которая не трогает результаты;
- справка только до первого выполненного запроса;
- `Rerun` повторяет последний выполненный запрос;
- тесты не ждут настоящую задержку.

**Non-Goals:** настраиваемая задержка, кнопка справки, изменения индекса и синтаксиса.

## Decisions

### D1. Состояние экрана

В `Search` появляются поля, которые меняются только в UI-потоке:

| Поле | Смысл |
|---|---|
| `mode` | `app.SearchModeDynamic` или `app.SearchModeSubmit` |
| `delay` | задержка режима «При вводе»; по умолчанию `500 * time.Millisecond`, в тестах подменяется через `SetDelay` |
| `last` | текст последнего выполненного запроса (`""` — запросов ещё не было) |
| `timerGen` | номер ожидания таймера; устаревшие срабатывания отбрасываются |
| `filling` | флаг программного изменения поля (`SetQuery`, ✕): `OnChanged` не запускает таймер |

«Выполненный запрос» — это любая попытка выполнения непустого текста, в том числе с ошибкой разбора. `last` обновляется при каждой такой попытке. Поэтому `Rerun` после ошибки снова покажет ту же ошибку, а прежние результаты останутся на экране. Это совпадает с требованием «результаты остаются до исправления». Если бы `last` запоминал только успешные запросы, `Rerun` молча заменял бы сообщение об ошибке результатами старого запроса, а в поле при этом стоял бы другой текст.

### D2. Разделение `Run` на «взять текст» и «выполнить»

- `execute(text)` — внутренняя функция. Пустой текст — ничего не делать. Иначе: `last = text`, `seq++`, разбор, поиск в фоне и применение через `s.do`, как сейчас.
- Кнопка 🔍 и Enter в режиме «По кнопке» вызывают `execute(entry.Text)`. Срабатывание таймера вызывает `execute(entry.Text)`.
- `Rerun()` вызывает `execute(last)`; если `last == ""`, остаётся справка.
- `SetQuery(text)`: `filling = true`, `SetText`, `filling = false`, отмена таймера, `execute(text)`.

Справка показывается только в конструкторе. `showHelp` больше не вызывается из `execute`. Первый вызов `apply` или `setStatus` с ошибкой скрывает справку навсегда: появляется флаг `helpDone`. Альтернатива «показывать справку при пустом поле, пока нет результатов» проще, но не соответствует решению «после первого запроса всегда последний результат».

### D3. Таймер без гонок

`time.AfterFunc` срабатывает в чужой горутине и передаёт работу через `s.do`. `Stop()` не отменяет функцию, которая уже стоит в очереди `fyne.Do`: в текущем коде это латентная гонка. Поэтому при каждом `schedule` и каждой отмене увеличивается `timerGen`, а в замыкание захватывается его текущее значение:

```go
gen := s.timerGen
s.timer = time.AfterFunc(s.delay, func() {
	s.do(func() {
		if gen == s.timerGen {
			s.execute(s.entry.Text)
		}
	})
})
```

Отмена (`cancelTimer`) — это `Stop` плюс `timerGen++`. Её вызывают ✕, `SetQuery`, `SetMode` и `execute`.

### D4. Enter в режиме «При вводе» снимает фокус

`OnSubmitted` в режиме «При вводе» вызывает `Unfocus()` у канваса поля (`fyne.CurrentApp().Driver().CanvasForObject(entry)`, для тестов — с проверкой на nil). На Android снятие фокуса закрывает клавиатуру, на ПК только убирает курсор. Таймер не трогается.

Альтернатива — выполнять запрос по Enter сразу. Отклонена решением пользователя: в этом режиме запрос уходит только по таймеру.

### D5. Кнопки у поля

Раскладка: `Border(nil, nil, nil, buttons, entry)`, где `buttons = HBox(clear, search)`.
- ✕ — `widget.NewButtonWithIcon("", theme.ContentClearIcon(), s.Clear)` — видна всегда.
- 🔍 — существующая кнопка; `Hide()` в режиме «При вводе», `Show()` в режиме «По кнопке».

`Entry.ActionItem` не используется: он один на поле, а кнопок две.

`Clear()`: `cancelTimer`, `filling = true`, `SetText("")`, `filling = false`. Статус и сетка не меняются, фокус остаётся в поле, чтобы можно было сразу печатать.

### D6. Настройка и её применение

- В `internal/app`: `KeySearchMode = "search.mode"`, `SearchModeDynamic = "dynamic"`, `SearchModeSubmit = "submit"` и функция `SearchMode(s storage.Settings) string` с разбором по умолчанию: любое неизвестное значение → `dynamic`. Там же лежат остальные ключи, и это место без виджетов.
- `NewSearch` читает режим из `svc.Settings`.
- Экран «Настройки»: новая карточка «Поиск» с `widget.NewRadioGroup([]string{"При вводе", "По кнопке"})` и подписью «При вводе — поиск через 0,5 с после ввода; по кнопке — по кнопке поиска или Enter» (без эмодзи: шрифт Fyne их не рисует». Из двух взаимоисключающих вариантов радиокнопки видны сразу, без раскрытия списка. `Select` используется в разделе браузера для списков длиннее.
- Связь: `NewSettings` получает колбэк `onSearchMode func(string)`. Оболочка передаёт `s.search.SetMode`. `OnChanged` радиогруппы сначала сохраняет значение, потом вызывает колбэк.
- `SetMode(m)`: `cancelTimer`, `mode = m`, показать или скрыть 🔍. Поле и результаты не меняются.

### D7. Потоки

Всё состояние из D1 меняется только в UI-потоке. Из горутин приходят только два пути, оба через `s.do`: результат поиска (проверка `seq`, как сейчас) и срабатывание таймера (проверка `timerGen`). Колбэки виджетов (`OnChanged`, `OnSubmitted`, кнопки, радиогруппа) Fyne вызывает в UI-потоке.

### D8. Тесты

- `SetDelay(d)` — тестовый хук, как `SetDispatcher`. Тесты ставят 50 мс.
- `SetMode` и `Clear` — публичные методы, ими пользуются тесты и оболочка.
- Текущий `TestSearchScreen` проверял справку через `SetQuery("")`. Теперь справка проверяется сразу после создания экрана, а `SetQuery("")` ничего не меняет.

## Risks / Trade-offs

- [Enter на экранной клавиатуре Android может не вызывать `OnSubmitted` для однострочного `Entry`] → проверить на устройстве; при необходимости ловить `TypedKey(KeyReturn)` через обёртку поля.
- [0,5 с — компромисс: при медленном наборе между символами возможны промежуточные запросы] → задержка — одна константа, её легко поменять; для полного контроля есть режим «По кнопке». Изначально обсуждались 2 с; после проверки на устройстве выбрано 500 мс.
- [Справки больше нет после первого запроса] → синтаксис описан в user-guide; кнопку справки можно добавить отдельным изменением.
- [`Rerun` после сканирования, пока поле содержит неотправленный текст, показывает результаты для `last`, хотя в поле другой текст] → это ожидаемо (сценарий «Неотправленный текст не выполняется»), строка «Найдено: N» относится к последнему выполненному запросу.

## Migration Plan

Настройки `search.mode` нет у существующих пользователей → действует значение по умолчанию «При вводе». Откат — вернуть прежний `search.go`, ключ в настройках просто игнорируется.
