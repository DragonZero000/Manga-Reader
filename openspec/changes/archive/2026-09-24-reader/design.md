## Context

После `local-library` есть `library.Source` (`Get`, `OpenPage` — страница читается целиком в память, архив не остаётся открытым), `thumbs.Cache` (декодирование + уменьшение + LRU + пул) и оболочка `Stack(AppTabs, Toast)`. Читалка должна работать на Windows и Android (Fyne 2.8, `fyneDo`).

Ограничения Fyne 2.8, найденные при исследовании:
- нет жестов двумя пальцами (pinch) — масштаб только двойным тапом;
- `DoubleTappable` задерживает одиночный `Tapped` на время ожидания второго тапа (~300 мс);
- кнопка «Назад» на Android приходит в `Canvas.OnTypedKey`; если обработчик задан, Fyne сам **не** сворачивает приложение (`internal/driver/mobile/driver.go`);
- у `widget.List` нет события прокрутки (есть только `GetScrollOffset`), у `container.Scroll` есть `OnScrolled`;
- размер текстуры GPU ограничен (на телефонах часто 4096–8192 px).

Сеть, API и rate limiting в этом изменении не используются.

## Goals / Non-Goals

**Goals:** постраничный режим и лента на ПК и Android; плавное листание без блокировки UI; ограниченная память; корректная кнопка «Назад».

**Non-Goals:** прогресс чтения, pinch-zoom, RTL, разворот, переход между книгами (см. proposal).

## Decisions

### D1. Пакеты

```
internal/pages/            — без виджетов (добавить в archtest)
  loader.go   Loader: Load(req, cb) — OpenPage → Decode → уменьшение, LRU по байтам, пул, отмена устаревших
  slice.go    Slice(img, maxH) — резка высоких изображений на куски
  fit.go      чистая геометрия: Fit, FitWidth, Zoom (фокус), ClampOffset, TopPage (префиксные суммы)
internal/ui/reader/
  reader.go   Reader: слой, Open(g)/Close()/Visible(), режим, панель, клавиши
  paged.go    pagedView: одна страница, тап-зоны, свайп, двойной тап, перетаскивание
  strip.go    stripView: лента на container.Scroll с собственной виртуализацией
  panel.go    панель: название, «N / всего», ползунок, переключатель, «Закрыть»
internal/library/source.go — PageSizes(key) ([]PageSize, error)
```

Геометрия вынесена в `pages/fit.go` как чистые функции — это покрывается unit-тестами без UI.

### D2. Слой поверх вкладок

Содержимое окна: `Stack(tabs, reader, toast)`. Читалка — непрозрачный фон + текущий вид; по умолчанию скрыта. Toast остаётся верхним слоем (ошибки видны и в читалке). Вкладки под скрытой/показанной читалкой не пересоздаются, поэтому положение прокрутки сетки сохраняется. При открытии вызывается `Canvas().Unfocus()`, чтобы клавиши не уходили в поле поиска.

*Альтернатива:* `Window.SetContent(reader)` и обратно — отклонено: пересоздание дерева и потеря состояния вкладок (ошибка старого проекта с toast).

### D3. Клавиши, «Назад» и Esc

Единый обработчик `Canvas().SetOnTypedKey` в оболочке:

```
key ──▶ читалка видима? ──да──▶ Esc / Back → Close
                         │        остальное → reader.TypedKey (← → PgUp PgDn Home End Space)
                         └нет──▶ Back → driver.GoBack() (через интерфейс { GoBack() }), иначе игнор
```

`GoBack` есть у мобильного драйвера (`internal/driver/mobile.driver`) как экспортируемый метод; вызывается через утверждение интерфейса `fyne.CurrentApp().Driver().(interface{ GoBack() })`. На ПК утверждение не проходит — Back там не бывает.

*Риск:* `GoBack` — не часть публичного API Fyne; при изменении драйвера сворачивание перестанет работать. Покрывается ручной проверкой на эмуляторе и отмечается в Risks.

### D4. Постраничный вид

`pagedView` — собственный виджет (`Tappable`, `DoubleTappable`, `Draggable`, `Scrollable`), рендерит один `canvas.Image` с ручной раскладкой (позиция и размер из `scale`, `offset`).

- **Тап-зоны:** левая треть — назад, правая — вперёд, центр — панель. Из-за `DoubleTappable` одиночный тап срабатывает с задержкой ~300 мс; для листания это приемлемо (клавиши и свайп без задержки).
- **Свайп:** в `Dragged` накапливается смещение; в `DragEnd`, если масштаб = вписанный, `|dx| > max(48 dp, 15% ширины)` и `|dx| > |dy|` — смена страницы.
- **Колесо:** `Scrolled`, dy < 0 → вперёд; не чаще раза в 250 мс (тачпады шлют серии событий).
- **Смена страницы** сбрасывает масштаб; изображение предыдущей страницы сразу убирается (показывается индикатор), чтобы не показывать «чужую» страницу.

### D5. Масштаб ×2 и перетаскивание

- Вписанный масштаб `fit = min(W/w, H/h)`; увеличенный — `2·fit`.
- Фокус: точка тапа `p` остаётся на месте: `offset' = p − (p − offset)·2`, затем `ClampOffset` — изображение не отходит от краёв (если оно меньше области по оси — центрируется).
- Перетаскивание при увеличении меняет `offset` на `DragEvent.Dragged`, с тем же ограничением.
- Резкость: страница грузится в разрешении «вписать × плотность экрана». При увеличении запрашивается версия ×2 (не больше оригинала); до её готовности показывается растянутая текущая.

### D6. Лента: `container.Scroll` + собственная виртуализация

Содержимое прокрутки — виджет `stripContent` с `MinSize = (W, Σhᵢ)`. Его раскладка по `offset` из `Scroll.OnScrolled` размещает **только** страницы, пересекающие окно `[offset − H, offset + 2H]`; объекты страниц берутся из пула и переиспользуются.

- Высоты: `hᵢ = W · (heightᵢ / widthᵢ)` по `PageSizes`; страница с неизвестным размером — высота `W · 1.414` (A-формат) до загрузки, затем пересчёт.
- Текущая страница: `TopPage(offset)` — бинарный поиск по префиксным суммам; обновляет номер на панели.
- Переход к странице: `Scroll.Offset = prefix[i]` + `Refresh`.
- Смена ширины (поворот, ресайз окна): пересчёт высот с сохранением текущей страницы вверху.
- Тап без прокрутки по `stripContent` переключает панель.

*Альтернатива:* `widget.List` + `SetItemHeight`. Отклонено: нет события прокрутки (номер страницы пришлось бы опрашивать таймером), нет контроля над переиспользованием для страниц из нескольких кусков.

### D7. Загрузка страниц (`pages.Loader`)

- Запрос: `{key, page, targetW, targetH (физ. px)}`; ключ кэша округляет размер до шага 64 px, чтобы мелкий ресайз окна не порождал новых декодирований.
- `OpenPage` → `image.Decode` → уменьшение `draw.ApproxBiLinear` до цели (не больше оригинала).
- Кэш LRU **по байтам**: 160 МБ на ПК, 80 МБ на мобильных. Пул 2 воркера (декодирование тяжёлое, важнее очередность, чем параллельность).
- Приоритет: сначала текущая страница, затем ±1. Запросы несут номер «поколения»; при смене страницы/режима устаревшие ещё не начатые запросы отбрасываются.
- Результат применяется в UI через `fyne.Do` с проверкой, что вид всё ещё ждёт эту страницу.
- `Reader.Close` очищает кэш страниц (требование «память освобождается»).

### D8. Резка длинных страниц

После уменьшения по ширине изображение выше `2048` физ. px режется `Slice(img, 2048)` на куски (`SubImage` + копия в отдельный `NRGBA`, чтобы каждая текстура была независимой); в ленте страница — вертикальный стек кусков точной высоты. 2048 выбрано с запасом ниже минимального реального лимита 4096. В постраничном режиме резка не нужна: «вписать» даёт высоту ≤ высоты экрана; при ×2 высота ≤ 2 × экран — для экранов выше 2048 физ. px (телефоны ~3000) применяется та же резка.

### D9. `Source.PageSizes`

Один `openZip`, для каждой страницы `f.Open` → `image.DecodeConfig` (читает только заголовок). Для WebP/JPEG/PNG/GIF декодеры уже зарегистрированы в `thumbs`; `pages` импортирует их сам (не полагаться на побочный импорт). Ошибка страницы → нулевой размер + ошибка в результате, обработка продолжается.

### D10. Потоки UI (явно)

- `PageSizes`, загрузка и декодирование — в горутинах; в UI только через `fyne.Do`.
- Состояние читалки (текущая страница, масштаб, режим, видимость) меняется только в UI-потоке.
- Проверка «устаревшего» результата — сравнение `(gallery key, page, generation)` в UI-потоке.

### D11. Сохранение режима

`App.Preferences().StringWithFallback("reader.mode", "paged")`, запись при переключении. Других данных читалка не сохраняет.

## Risks / Trade-offs

- [`GoBack` не публичный API] → при изменении Fyne «Назад» вне читалки перестанет сворачивать приложение; проверка на эмуляторе в задачах, при поломке — оставить системное поведение, не задавая обработчик вне читалки (переустанавливать `OnTypedKey` при открытии/закрытии).
- [Задержка одиночного тапа ~300 мс из-за двойного тапа] → листание тапами чуть медленнее; свайп/клавиши без задержки. При жалобах — собственное распознавание двойного тапа.
- [Большие страницы на телефоне] → уменьшение до экрана, LRU по байтам 80 МБ, 2 воркера; пик ≈ оригинал одной страницы (2000×3000 ≈ 24 МБ) × 2.
- [Высоты неизвестны для битых страниц] → условная высота и пересчёт; возможен небольшой «прыжок» только у битых страниц.
- [Резка на куски 2048 px] → на стыке кусков возможна полоска в 1 px при нецелом масштабе; размещать куски по целым физическим пикселям.

## Implementation notes (2026-09-24)

**Найдено при реализации:**
- **`Container.Show()` в Fyne 2.8 не перерисовывает** (в отличие от `Hide()`), а `Refresh()` объекта, который был скрыт с момента создания, не доходит до canvas: драйвер ещё не связал объект с окном. Симптом — панель читалки «показывалась», но не рисовалась; битая страница оставляла на экране изображение предыдущей. Решение: `Reader.repaint(o)` — `o.Refresh()` + `Window.Canvas().Refresh(o)`; рендереры вида и ленты тоже обновляются через canvas окна. Тот же приём добавлен в toast и пустое состояние библиотеки.
- **Тестовый драйвер Fyne выполняет `fyne.Do` в вызывающей горутине** — UI-тесты читалки ловили гонки. У `Reader` есть подменяемая функция `do` (по умолчанию `fyne.Do`); в тестах колбэки выполняются в горутине теста через очередь. Тесты `internal/ui/reader` проходят под `-race`.

**Отклонения от решений выше:**
- D8: в постраничном режиме изображения не режутся — целевой размер ограничен `4096` физ. px по каждой стороне (`maxTexture`), что проще и укладывается в лимит текстур.
- D6: нечитаемая страница в ленте сжимается до полосы 120 единиц с сообщением (вместо условной высоты A-формата), чтобы не оставлять пустой экран.
- Остановленный индикатор загрузки скрывается (в Fyne он остаётся точкой).

**Память (7.4):**
- Windows, лента из 100 страниц 1200×1700 до конца: библиотека 192 МБ → лента ~509 МБ (плато, не растёт) → после закрытия 195 МБ. Возврат памяти обеспечивает `debug.FreeOSMemory()` при закрытии (без него оставалось ~510 МБ).
- Android (эмулятор, программный OpenGL — текстуры считаются в памяти процесса), лента с полосой 800×20000: 462 МБ PSS → **312 МБ** после `debug.SetMemoryLimit(192 МБ)` на мобильных.

**Проверено на эмуляторе Android 15:** свайп листает, двойной тап ×2, перетаскивание, панель, лента с длинной полосой, «Назад» в читалке закрывает её, «Назад» в библиотеке сворачивает приложение (верхняя активность — лаунчер, процесс жив). Реальное устройство не проверялось.

**Не воспроизведено:** однажды процесс ПК-версии исчез без записи в лог во время ручной проверки; повтор той же последовательности действий и последующие проверки падения не показали. Вероятнее всего, процесс завершил инструмент запуска, а не приложение.
