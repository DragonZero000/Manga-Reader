## Context

Читалка — пакет `internal/ui/reader`: `Reader` (слой, режимы, загрузчик), `pagedView` (постраничный вид), `stripView` (лента), `panel` (панель). Клавиши приходят из `Shell.typedKey` (`internal/ui/shell.go`), который также закрывает слои по Esc/«Назад». Страницы грузит `pages.Loader` (2 воркера, LRU по байтам, поколения запросов для отмены).

Откуда задержка листания тапом (проверено по исходникам Fyne v2.8.0):

```
pagedView реализует fyne.DoubleTappable
   └─▶ драйвер откладывает Tapped до истечения DoubleTapDelay():
         glfw/Windows: GetDoubleClickTime()  (по умолчанию 500 мс)
         mobile:       tapDoubleDelay = 500 мс
```

Если виджет не реализует `DoubleTappable`, драйвер вызывает `Tapped` сразу при отпускании. Прочие задержки: `wheelInterval = 250ms` в `pagedView.Scrolled`; предзагрузка только ±1.

Клавиатура в Fyne: пока на canvas есть фокус, `TypedKey` (в том числе Esc и `mobile.KeyBack`) получает только сфокусированный виджет; `Canvas.OnTypedKey` оболочки не вызывается. Это используется для поля ввода номера страницы.

## Goals / Non-Goals

**Goals:**
- тап по боковой зоне листает за ≤ 250 мс на Windows и Android без отказа от двойного тапа;
- навигация: ввод номера, «Домой», ползунок вживую, направление чтения, завершение произведения;
- точка расширения «произведение дочитано» для будущего `reading-progress`.

**Non-Goals:** плавный зум и пинч (`reader-zoom`), сохранение прогресса (`reading-progress`), настройка скорости листания, зум в ленте, кэш оглавления zip (только замер).

## Decisions

### 1. Собственное распознавание двойного тапа

`pagedView` перестаёт реализовывать `fyne.DoubleTappable`; `Tapped` приходит сразу, а двойной тап распознаёт небольшой автомат:

```
           Tapped(p)                       Tapped(p2), |p2-p| < 40dp
  idle ───────────────▶ pending(p, timer) ──────────────────────────▶ doubleTap(p) → idle
                              │
                              │ timer tapWindow (250 мс) истёк
                              ▼
                        singleTap(p) → idle      (боковая зона → step, центр → панель)
```

- Таймер — `time.AfterFunc`, обработка в UI-потоке через `r.do` (fyne.Do); устаревшее срабатывание отбрасывается по счётчику `tapSeq` (таймер мог сработать уже после второго тапа).
- `tapWindow` — константа 250 мс (меньше системных 500 мс). Её же в будущем может настраивать «скорость листания».
- Альтернатива (запасной вариант, если 250 мс окажется мало): двойной тап только в центральной трети; тап по боковой трети листает сразу, без автомата. Переключение — в одной функции `onTap`, остальной код не меняется. Решение принимается после ручной проверки (задача в tasks.md).
- Отклонено: листать на первом тапе и «откатывать» при втором — мигание страницы и лишняя загрузка.
- Отклонено: `desktop.Mouseable`/`mobile.Touchable` для тапов — пришлось бы повторять порог перетаскивания Fyne; `Tapped` без `DoubleTappable` уже мгновенный.

### 2. Единый ограничитель «потока» перелистываний

`Reader.throttled(limited)` — интервал `flipInterval = 150ms` с момента последнего перелистывания, действует для колеса и автоповтора клавиш. У `TypedKey` нет признака автоповтора, поэтому оболочка передаёт нажатия из `desktop.Canvas.SetOnKeyDown` (GLFW вызывает его только при нажатии, не при повторе) в `Reader.KeyDown`: `TypedKey` без предшествующего `KeyDown` той же клавиши — автоповтор. На Android `KeyDown` не приходит — клавиши не ограничиваются. Тапы и свайпы не ограничиваются. Колесо без Ctrl в `Scrolled` листает всегда, в том числе при увеличении (увеличение сбрасывает `showPage`). Ctrl+колесо в этом изменении игнорируется — его займёт `reader-zoom`.

Отклонено: «жест колеса» с паузой тишины — сложнее и хуже для мыши с дискретными щелчками; интервал проще и проверяется тестом.

### 3. Предзагрузка по направлению

`pagedView` хранит `dir` (+1/−1, последнее перелистывание, по умолчанию +1). `showPage` запрашивает текущую с `PriorityCurrent`, затем `page+dir`, `page+2·dir`, `page−dir` с `PriorityNeighbor` (порядок постановки = порядок выполнения внутри приоритета). Число воркеров не меняется (2). Объём: на телефоне страница ≈ 10 МБ RGBA, 4 страницы ≈ 40 МБ при кэше 80 МБ — помещается.

Направление в индексах, не на экране: при чтении справа налево «вперёд» — тоже `page+1`.

### 4. Направление чтения

Ключ `reader.direction` (`ltr`/`rtl`) в `internal/app/app.go` рядом с прочими (`ReaderDirection`, `SetReaderDirection`); `Reader` читает его в `Open` (пока читалка закрыта, настройки меняются только на экране настроек — перечитывать на лету не нужно). Переворот — в одной точке: `forward := r.rtl ? -1 : +1` для зон, свайпа и стрелок. Ползунок Fyne не умеет инвертироваться, поэтому в RTL значение отображается как `total+1−page` (`panel.toSlider`/`fromSlider`). В `internal/ui/screens/settings.go` — новая карточка «Читалка» с `RadioGroup`.

### 5. Панель: «Домой», ввод номера, ползунок вживую

```
┌────────────────────────────────────────────────┐
│ english name                               [✕] │
└────────────────────────────────────────────────┘
               ┌────┐
               │ 34 │   ← подсказка над бегунком (только во время перемещения)
               └────┘
┌────────────────────────────────────────────────┐
│ [⌂]  12 / 87  ━━━━━━━━●━━━━━━━━━━━━━━━━━━━━━━  │
│            ( ) Страницы  (•) Лента             │
└────────────────────────────────────────────────┘
```

- **«Домой»**: `Reader.SetOnHome(func())`; `Shell` передаёт функцию, закрывающую `Reader` и `Details`. Вкладка не переключается: слои лежат поверх `AppTabs`, под ними уже та вкладка, с которой пришёл пользователь.
- **Ввод номера**: `pageField` — виджет из надписи и `pageEntry` (наследник `widget.Entry`), видно одно из двух. `pageEntry` фильтрует `TypedRune` (только цифры), обрабатывает в `TypedKey` Enter (переход), Esc и `mobile.KeyBack` (отмена), `FocusLost` (отмена); реализует `mobile.Keyboardable` → `mobile.NumberKeyboard` (на ПК интерфейс не вызывается). Клавиша G приходит в `Reader.TypedKey` → показать панель и `Canvas.Focus(entry)`. После перехода или отмены — `Canvas.Unfocus()`, чтобы клавиши снова шли в читалку.
- **Ползунок вживую**: `OnChanged` (во время перемещения) → `scrubbing = true`, `view.preview(page)`, подсказка; `OnChangeEnded` → `scrubbing = false`, `goTo`, обновить счётчик, скрыть подсказку. Пока `scrubbing`, `Reader.pageChanged` не обновляет надпись. `pagedView.preview`: из кэша — сразу; иначе показать индикатор и отложить запрос таймером 80 мс (новое движение перезапускает таймер), `loader.NewGeneration()` отменяет запросы пройденных страниц; соседей при перемещении не грузить. Лента: `preview` = прокрутка к странице (виртуализация сама ограничивает загрузку).
- **Подсказка**: отдельный объект в `panel.layer` без раскладки (позиционируется вручную): `x = slider.Position().X + pad + (value−min)/(max−min)·(width−2·pad)`. Точность в несколько пикселей допустима.

### 6. Завершение чтения

`Reader.tryFinish()` — общий для обоих видов автомат:

```
idle ──next на последней──▶ armed(t) + r.notify(«Конец…»)
armed(t0) ──next, t−t0 < 400мс──▶ armed(t)  (продление: инерция колеса / автоповтор)
armed(t0) ──next, 400мс ≤ t−t0 ≤ 3с──▶ finish(): Close(); onFinished(g)
armed(t0) ──next, t−t0 > 3с──▶ armed(t) + снова подсказка
armed ──смена страницы──▶ idle
```

- Подсказка — существующий тост оболочки (`notify`).
- `onFinished func(model.Gallery)` — точка расширения (`SetOnFinished`), в этом изменении не задаётся оболочкой; `reading-progress` подключит к ней отметку «дочитано».
- Лента: в `stripContent` после последней страницы — блок фиксированной высоты (надпись «Конец» + кнопка «Завершить чтение», которая вызывает `finish()` сразу). Высота блока добавляется к сумме высот (`prefix`), страницы виртуализации не затрагиваются. PgDn/пробел/↓, когда прокрутка уже у нижнего края, вызывают `tryFinish()`.

### Потоки

Всё состояние читалки меняется только в UI-потоке. Таймеры (`tapWindow`, отложенный запрос ползунка, истечение `armed` проверяется по времени при следующем событии, без таймера) возвращаются в UI-поток через `r.do` и проверяют счётчик/токен открытия. Колбэки загрузчика — как сейчас, через `r.do`.

### Платформы

Windows и Android — одинаковое поведение, build tags не нужны. Отличия: `mobile.Keyboardable` действует только на Android; клавиша G и колесо — только на ПК; на Android «Назад» в поле ввода сначала закрывает системную клавиатуру (системное поведение), следующее «Назад» доходит до поля и отменяет ввод.

## Risks / Trade-offs

- [250 мс всё ещё ощутимы] → ручная проверка на ПК и телефоне; при неудаче — запасной вариант (двойной тап только в центре), заложенный в `onTap`.
- [Тачпад даёт длинную инерцию, 150 мс листают несколько страниц] → основной ввод — мышь и тач; если будет мешать, порог станет частью будущей настройки скорости листания.
- [`TypedKey` после сочетания клавиш без своего `KeyDown`] → может быть принят за автоповтор и ограничен 150 мс; на практике незаметно.
- [Позиция подсказки над бегунком зависит от внутренних отступов `widget.Slider`] → расчёт через тему (`theme.InnerPadding`), проверка глазами в обеих темах и на телефоне.
- [Изменение поведения последней страницы может удивить] → двухшаговое подтверждение и подсказка; документация.
- [Задержка декодирования на больших страницах остаётся] → замер (задача); кэш оглавления zip — отдельным изменением по результатам.

## Open Questions

- Окно двойного тапа 250 мс — окончательное значение после ручной проверки (возможен откат к варианту «двойной тап в центре»).
- Что именно будет регулировать будущая настройка скорости листания: `tapWindow`, `flipInterval` или оба.
