## Context

- `ReadArchive` (`internal/library/archive.go`) строит список страниц из сырых `zip.File.Name`, а `Source.OpenPage` и `Source.PageSizes` открывают страницы через `zip.Reader.Open` — реализацию `io/fs`. Она требует `fs.ValidPath`: UTF-8, без `/` в начале, без сегментов `.`/`..`, а разделителем считает только `/`. Проверено экспериментом: `open ch1\001.jpg: file does not exist`, `open ./002.jpg: invalid argument`, имя в Shift-JIS — `invalid argument`.
- Классификация записей (`isServicePath`, `path.Base` для `meta.json` и расширения, `depth`) делит имя только по `/`. Сегмент `.` считается скрытым, поэтому архив из записей `./NNN.jpg` получает «нет изображений»; `__MACOSX\._001.jpg` становится страницей.
- Сканер хранит галереи в `library.db` (`files.gallery`) как JSON `model.Gallery`. `encoding/json` заменяет байты не в UTF-8 на U+FFFD — проверено: `"\x8d\xec/001.jpg"` и `"\x8e\xed/001.jpg"` после сохранения и загрузки оба становятся `"��/001.jpg"`.
- Каталог пересоздаётся только при смене `schemaVersion`, и тогда библиотека сканируется целиком. Для больших библиотек это дорого, а прерванный полный скан сейчас теряет весь прогресс (отдельная находка аудита).
- Сканер пропускает файл, если размер и время изменения совпадают с сохранёнными (`scanFile`); `Invalidate` ставит флаг `transient`, но `Scanner.Cached()` скрывает такие записи из библиотеки при запуске.

## Goals / Non-Goals

**Goals:** любую страницу, попавшую в список, можно открыть; имена переживают сохранение в каталог; классификация записей не зависит от разделителя; уже сохранённые затронутые результаты исправляются без полного пересканирования.

**Non-Goals:** перекодировка имён не в UTF-8 для показа; изменение порядка страниц; прочие находки аудита; форматы, отличные от zip.

## Decisions

### D1. Страница открывается по записи оглавления, а не через `io/fs`

Новая функция `library.findEntry(zr *zip.Reader, name string) *zip.File` возвращает первую запись (не папку) с `f.Name == name`; страница читается через `f.Open()`. `OpenPage` ищет одну запись линейно (оглавление — сотни записей, стоимость несравнима с распаковкой и декодированием). `PageSizes` один раз строит `map[имя]*zip.File` (первая запись выигрывает) и берёт записи из неё; `pageSize` принимает `func(string) (io.ReadCloser, error)`.

- Отклонено: нормализовать имя и звать `zr.Open` — не решает имена не в UTF-8 (`fs.ValidPath` их отвергает) и допускает совпадения разных записей после нормализации.
- Отклонено: хранить в `model.Page` индекс записи в оглавлении — меняет модель и формат каталога ради редкого случая повторяющихся имён, который решает D3.

### D2. Классификация по нормализованному пути, хранение — по сырому имени

`entryPath(name)`: в имени в UTF-8 считать `\` разделителем наравне с `/`, разбить, отбросить пустые сегменты и `.`, собрать через `/`. В имени не в UTF-8 разделитель только `/`: в Shift-JIS второй байт символа бывает `0x5C` («ソ», «表», «能»), и `\` разрезал бы имя посреди символа. Архивы с `\` пишут инструменты Windows с именами в UTF-8 или ASCII, так что это ограничение их не затрагивает. По результату работают `isServicePath` (сегмент `__MACOSX` или начинающийся с `.` — в том числе `..`), базовое имя (`meta.json`, расширение страницы) и `depth` (выбор наименее вложенного `meta.json`). `Page.Name`, сортировка страниц и отпечаток используют сырое имя.

- Для обычных архивов `entryPath(name) == name`, поэтому их страницы, порядок и отпечатки не меняются.
- Файл на Linux с `\` в имени будет классифицирован как путь с папкой — это влияет только на поиск `meta.json` и служебных файлов, открытие по сырому имени не страдает.
- Отклонено: разрешать `..` — читалке не нужно, запись с `..` остаётся служебной, как и сейчас.

### D3. Повторяющиеся имена: первая запись — страница

При разборе множество уже встреченных сырых имён страниц; повтор пропускается с предупреждением `"<rel>: duplicate entry <name> skipped"` (попадает в `ScanResult.Warnings` и журнал). Выбор первой записи совпадает с `findEntry`. Отпечаток считается по оставшимся страницам. У таких архивов отпечаток меняется; запись `user.db` остаётся за файлом: сверка обновляет отпечаток файла, который найден на месте (шаг 1 `Reconcile`).

### D4. `model.Page` сериализуется в JSON без потерь

`Page.MarshalJSON`: имя в UTF-8 → `{"Name":"…"}` (как сейчас, старые записи каталога читаются без изменений); иначе → `{"NameRaw":"<base64 сырых байтов>"}`. `Page.UnmarshalJSON` принимает оба вида. Это единственное место, где имена страниц сериализуются (`files.gallery` в каталоге); индекс поиска, обложки и `user.db` имён страниц не хранят.

- Отклонено: хранить галерею в gob или отдельной таблице страниц — смена формата, `schemaVersion` и полный скан библиотеки.
- Отклонено: угадывать кодировку (Shift-JIS, CP866) и хранить имя в UTF-8 — ненадёжно, и для открытия всё равно нужны исходные байты.

### D5. Ревизия правил разбора и однократная перепроверка

- `library.ParseRevision = 1` — ревизия правил этого изменения (0 — до него). Будущие исправления разбора повышают её и дополняют предикат.
- `ScanStore` получает `ParseRevision() (int, error)`; `ScanDelta` — поле `ParseRevision int` (0 — не менять), `Empty()` его учитывает. Каталог хранит значение в `meta` под ключом `parse_rev` и пишет его в той же транзакции, что и остальную дельту. `Reset` значение не трогает: после очистки проверять нечего.
- `NewScannerWithStore`: если сохранённая ревизия меньше `ParseRevision`, записи, для которых `needsRecheck(entry)` истинно, получают флаг `recheck`, сканер запоминает `revPending`. Предикат ревизии 1: ошибка `ErrNoImages`; галерея, у которой есть страница с `\` в имени в UTF-8 или с U+FFFD в имени, или повторяющиеся имена страниц. Записи с `/` в начале не нужны: их классификация не меняется, а D1 открывает их без повторного разбора. Частичные галереи из архивов, где `./`-записи смешаны с обычными, по сохранённому результату не отличить — они исправятся при изменении файла.
- `recheck` — отдельный флаг, а не `transient`: `Cached()` продолжает показывать такие записи при запуске. `scanFile` пропускает неизменённый файл, только если нет ни `transient`, ни `recheck`. Если файл занят и остаётся прежний результат, флаг сохраняется; если занятый файл превращается в ошибку (`BusyAsError`), новая запись наследует `recheck`.
- В конце успешного `Scanner.Scan`: если `revPending` и в кэше не осталось записей с `recheck` (удалённые файлы уходят из кэша), `delta.ParseRevision = ParseRevision`; после успешного `Save` — `revPending = false`. Любая ошибка `Save`, пока ревизия не записана, сбрасывает `revPending` до конца запуска: результаты перепроверки могли не попасть в каталог, и последующий скан не должен записать ревизию поверх них. Следующий запуск перепроверит файлы заново.
- Без каталога (`store == nil`) перепроверки нет: всё в памяти и разбирается заново при каждом запуске.

- Отклонено: повысить `schemaVersion` — пересоздание каталога и полный скан ради немногих затронутых файлов.
- Отклонено: перепроверять по предикату при каждом запуске без ревизии — после исправления имена с `\` остаются, и такие файлы перечитывались бы всегда.

### Платформы, потоки

Windows и Android ведут себя одинаково; платформенного кода и тегов сборки нет. Всё выполняется в горутинах сканирования, загрузчиков страниц и миниатюр; виджеты не затрагиваются, `fyne.Do` не нужен. Новых сторонних компонентов нет — `THIRD_PARTY_NOTICES.md` не меняется.

## Risks / Trade-offs

- [Библиотека из архивов в Shift-JIS на Android перепроверяется целиком: открытие через SAF медленное] → разово и только для затронутых файлов; остальные не открываются.
- [Выход из приложения во время перепроверки] → ревизия не сохранена, перепроверка повторится при следующем запуске; объём ограничен затронутыми файлами.
- [U+FFFD в законном UTF-8-имени] → лишняя однократная перепроверка, без вреда.
- [Старая версия приложения прочитает `{"NameRaw":…}` как пустое имя] → у неё эти страницы не открывались и раньше; ревизию `parse_rev` она игнорирует.
- [Смешанные архивы с `./` не перепроверяются] → редкий случай; исправляется при изменении файла.
- [Архив с повторами меняет отпечаток; если его переименовали до первого сканирования новой версией, перенос по отпечатку не сработает] → запись пользовательских данных станет сиротой; случай двойной редкости, принимается.

## Migration Plan

Автоматически: первое сканирование после обновления перепроверяет затронутые файлы и сохраняет `parse_rev = 1`. Откат: прежняя версия работает с тем же каталогом (схема не менялась), затронутые архивы снова не открываются.
