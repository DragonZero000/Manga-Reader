## Context

Как Fyne 2.8.0 работает с текстурами изображений (проверено по исходникам модуля):

- **Отсечение.** `gl.painter.Paint` не рисует объект, который не пересекает текущую область отсечения. Текстура `canvas.Image` создаётся (`TexImage2D` в UI-потоке) только при первой отрисовке объекта внутри видимой области.
- **Кэш текстур по объекту.** Ключ кэша — сам `canvas.Image`. Текстура освобождается при `canvas.Refresh(img)`, в том числе из `img.Refresh()` и `img.Resize()` с новым размером, а также если объект не рисовался `cache.ValidDuration` = 1 мин. `img.Move()` текстуру не трогает (только `SetDirty`). `Canvas.Refresh(контейнер)` освобождает текстуры всех потомков, кроме `canvas.Image`.
- **Поиск получателя ввода.** `FindObjectAtPositionMatching` идёт сверху вниз и берёт первый объект с нужным интерфейсом (`Tappable`, `Scrollable`, `Hoverable`…). Объект без интерфейса для события «прозрачен».
- **GridWrap.** При прокрутке вызывает `UpdateItem` только для новых видимых ячеек. `GridWrap.Refresh()` вызывает его для всех видимых.
- **Такт.** Оба драйвера рисуют по таймеру 60 Гц (`glfw/loop.go:132`, `mobile/driver.go:198`), на ПК без vsync (`SwapInterval(0)`). Это не исправляется в этом изменении (этап 2).

Что из этого следует для нашего кода:

1. **Слои.** Фон страницы произведения — `canvas.Rectangle` ([details.go:117](../../../internal/ui/details/details.go)). Для нажатий он «прозрачен», и нажатие попадает в карточку сетки под ним. Нижние слои стека оболочки рисуются под закрывающим их слоем.
2. **Лента.** Страница декодируется заранее, пока ниже экрана, но её куски (до 1440×2048 ≈ 12 МБ) загружаются в GPU в том кадре, когда впервые попадают в видимую область.
3. **Сетка.**
   - Новая карточка на экране — это `img.Refresh()` и загрузка текстуры в кадре прокрутки. Несколько карточек строки — несколько загрузок в одном кадре.
   - Любое полное обновление сетки (каждое сканирование, в том числе при возврате на передний план, повтор поиска при открытии вкладки, `Remove`) заново присваивает ту же миниатюру и вызывает `Refresh`, то есть заново загружает все видимые обложки.
4. **Постраничный режим.** Один `canvas.Image` на все страницы, поэтому каждое перелистывание — это загрузка текстуры в кадре перелистывания.
5. **Дисковый кэш.** Миниатюры на диске уже есть: таблица `covers` в `library.db` (JPEG, ключ галереи и размер области). В grill-сессии решение «дисковый кэш миниатюр» сформулировано до того, как это выяснилось; новый кэш не нужен. Остаётся размер и очистка этой таблицы из настроек.

## Goals / Non-Goals

**Goals:**
- исходный замер по воспроизводимым сценариям до правок, повторный замер после;
- ни одной загрузки текстуры обложки или страницы сверх бюджета в одном кадре, кроме того, что уже на экране;
- бюджеты по времени, а не по кадрам (экраны 60–500 Гц);
- нажатия не проходят сквозь слои;
- поиск и сетка не перерисовываются без изменений;
- плавное колесо на ПК;
- кэш обложек в настройках.

**Non-Goals:** патч драйвера Fyne (этап 2), Vulkan, размер миниатюр и лимиты кэшей в памяти, браузер.

## Decisions

### D1. Слои: скрывать закрытые

`Details` и `Reader` получают `SetOnVisibility(func())`. Колбэк вызывается в `Open`/`Close` после смены видимости. Оболочка в колбэке вызывает `updateLayers()`:

```
reader открыт   → Tabs.Hide(), Details.layer.Hide()
details открыт  → Tabs.Hide()
иначе           → Tabs.Show()
```

Слой страницы произведения при закрытии читалки показывается снова, если `Details.Visible()`. `Show` после `Hide` сохраняет выбранную вкладку, смещение прокрутки GridWrap и текст поля. Stack-раскладка меняет размер скрытых объектов, так что поворот экрана при открытой читалке не ломает вкладки.

Альтернатива — невидимый `Tappable`/`SecondaryTappable`/`Hoverable`/`Scrollable` «поглотитель» под каждым слоем. Отклонено пользователем: чинит ввод, но нижние слои по-прежнему рисуются в каждом кадре.

### D2. Замер: сценарии автопрокрутки под тегом `frameprobe`

- `internal/ui/probe_on.go` (`//go:build frameprobe`) и `probe_off.go`.
- Через 5 с после старта оболочка запускает сценарии один за другим.
- Каждый сценарий — `fyne.Animation`, которая на каждом кадре сдвигает смещение с постоянной скоростью по времени (1500 логических px/с), 8 с вниз и 8 с вверх. Через `ScrollToOffset` двигаются сетка и лента; постраничный режим листается по шагу каждые 300 мс.
- Сценарии:
  - `grid` — библиотека;
  - `search` — поиск `*`;
  - `details` — прокрутка страницы произведения;
  - `settings`;
  - `strip`;
  - `paged`;
  - `tabs` — переключение вкладок каждые 500 мс;
  - `density` — на телефоне смена колонок 2→3→4, на ПК размеров карточек, с прокруткой на каждом значении.
- Замер кадров из `frameprobe_on.go` пишет сводку по каждому сценарию: `frameprobe[grid]: n=… p50=… p95=… max=… >25ms=… gc=…`. Поле `gc` — суммарная пауза GC за сценарий (`runtime/metrics` `/sched/pauses/total/gc:seconds`), по нему решается D8.
- Порог «рывка» `frameSlow` — 1,5 × медианы интервала, а не фиксированные 25 мс, чтобы цифры имели смысл на экране любой частоты. Поле `>25ms` остаётся для сравнения с прошлыми замерами.
- Данные: ~200 галерей из копий `testdata/*.zip` в папке-песочнице (не в репозитории). ПК — портативная сборка в песочнице с папкой `manga/`. Эмулятор — `Download/Manga`.
- Дополнительно на эмуляторе: ручные свайпы через `adb shell input swipe` для пути касаний.

Сценарии программные, путь обработки касаний они не нагружают. Зато они одинаковые «до» и «после» и одинаковые на ПК и Android.

### D3. Обложки: показ по бюджету и пул изображений

Новый тип `coverPresenter` в `screens` (UI-поток, общий для сеток библиотеки и поиска):

- **Пул.** `imagePool` — LRU `*canvas.Image` по ключу миниатюры (`thumbs.CacheKey` + область). Ёмкость — 3 экрана карточек (`колонки × видимые строки × 3`), пересчитывается при смене плотности или размера окна. Карточка показывает объект пула (слот-контейнер с одним дочерним объектом) вместо собственного `canvas.Image`. Вытесненный объект получает `Image = nil`, и Fyne освобождает его текстуру по истечении срока.
- **Тёплый объект.** Объект пула, показанный меньше 30 с назад, считается «тёплым» (его текстура ещё в кэше Fyne). Он ставится в карточку сразу, вне бюджета.
- **Очередь.** Холодная обложка (миниатюра готова, объекта нет или он остыл) ставится в очередь. Очередь сортируется по (строка по направлению прокрутки, колонка). Направление — знак изменения `GetScrollOffset` между тактами.
- **Бюджет.** Пока очередь не пуста, работает `fyne.Animation` (бесконечная, останавливается при пустой очереди). На каждом такте `allowance += rate × dt` (dt — фактическое время с прошлого такта, ограничено 100 мс, чтобы пауза не давала залп). Целое число обложек из `allowance` показывается. Начальные значения `rate`: 60 обложек/с на телефоне, 120 на ПК, уточняются по замеру. Константы общие, платформенная разница через `GridMetrics.mobile`.
- **Без изменений — без работы.** `updateCard` для той же галереи и той же миниатюры, когда карточка уже показывает этот объект пула, ничего не делает (ни `Image =`, ни `Refresh`). Это убирает перезагрузку всех видимых обложек при `GridWrap.Refresh()`.
- **Предзагрузка.** `thumbs.Cache.Prefetch(gs []model.Gallery)` заменяет прежний набор предзагрузки. Задания предзагрузки лежат во втором стеке; воркер берёт их, только когда стек видимых пуст. Задание, выпавшее из нового набора и ещё не начатое, удаляется без декодирования. Результат — только в кэш в памяти (и в каталог, если было декодирование). Окно считает сетка раз за такт презентера и при `updateCard` новых id:

  ```
  первый видимый = floor(offset / высота строки) × колонки
  окно = [видимые − 1 экран, видимые + 2 экрана] в направлении прокрутки
  ```

- **Потоки.** Колбэки `thumbs` приходят через `g.do` (`fyne.Do`). Пул, очередь и анимация — только UI-поток. `Prefetch` и отмена берут `c.mu`.

Альтернатива — ограничить число обложек «на кадр». Отклонено: на 500 Гц обложки появлялись бы в 8 раз быстрее, чем на 60 Гц, а на 60 Гц слишком медленно.

### D4. Читалка: заблаговременная загрузка в GPU

Новый тип `warmer` в `reader` (UI-поток):

- **Очередь.** Принимает `*canvas.Image` уже итогового размера (иначе последующий `Resize` освободит текстуру) и функцию «куда сдвинуть, чтобы объект касался видимой области».
- **Такт.** Работает на `fyne.Animation` с бюджетом в пикселях в секунду (`allowance += rate × dt`). На такте N объект сдвигается (`Move`) так, что пересекает видимую область одной строкой пикселей у края, со стороны, где он и так находится. Отрисовка кадра N загружает текстуру. На такте N+1 объект возвращается на место. В первый кадр Fyne вызывает `TickAnimations` перед отрисовкой (оба драйвера).
- **Порядок отрисовки.** Объекты, которые прогреваются, рисуются под видимыми страницами: в ленте контейнер кусков страницы ниже по порядку, чем видимые страницы. Видимый край экрана показывает на один кадр строку самой страницы, которая и так сразу за краем.
- **Лента.** Пока страница ниже или выше экрана, `apply` отдаёт её куски в `warmer`. Куски видимой страницы не ждут бюджета.
- **Постраничный режим.** Вместо одного `img` — до 4 объектов (текущая и соседние из окна предзагрузки), у каждого размер его страницы при текущем масштабе «по экрану». Соседний объект прогревается в углу под текущей страницей; перелистывание только переключает видимость объектов. Масштабирование (D2 прошлого `render-perf`) меняет размер только у текущего объекта.
- **Начальные бюджеты:** 40 Мпикс/с на телефоне, 120 Мпикс/с на ПК, уточняются по замеру. Кусок 1440×2048 ≈ 2,9 Мпикс.

Альтернатива — отдельный объект-«прогреватель» размером 1×1 px. Отклонено: текстура привязана к объекту, прогретый чужой объект не помогает объекту страницы.

Риск: приём опирается на внутреннее поведение Fyne 2.8 (отсечение по пересечению, `Move` без освобождения текстуры). Тест фиксирует его: проверяет, что после прогрева объект на месте и его `Image` прежний. Само отсутствие `TexImage2D` видно только в замере.

### D5. Поиск и сетка без лишних обновлений

- В оболочке появляется счётчик `libRev`. Он растёт:
  - после сканирования, если список галерей изменился (сравнение ключей и времени изменения с прошлым списком);
  - при `Library.Remove`;
  - при изменении своих или скрытых тегов.
- `Search` запоминает `libRev` при выполнении запроса. `Rerun()` на открытии вкладки и после сканирования выполняет запрос, только если `libRev` изменился. Явный ввод и «Искать по тегу» выполняются всегда.
- `Library.applyScan` не вызывает `grid.SetItems`, если список не изменился.
- `tags.go` вместо прямого `search.Rerun` поднимает `libRev`. Если вкладка «Поиск» открыта, запрос выполняется сразу.

### D6. Кэш обложек в настройках

- `catalog.Covers.Size() (int64, error)` — `SELECT COALESCE(SUM(LENGTH(jpeg)),0) FROM covers`.
- `catalog.Covers.Clear() error` — под `writeMu`: `DELETE FROM covers`, затем `VACUUM`, чтобы файл уменьшился.
- В `internal/app` интерфейс `CoverCache` с этими методами. `Services.Covers` равен `nil`, если каталог в памяти.
- `Settings` получает строку и кнопку в карточке «Библиотека». `UpdateCoverCache()` вызывается из `Tabs.OnSelected` для вкладки «Настройки» и после очистки. Подсчёт и очистка идут в горутине, результат приходит через `fyne.Do`. Пока идёт подсчёт, показывается `…`; во время очистки кнопка недоступна.
- Формат: `i18n` с одним знаком после запятой, разделитель по языку (`9,8 МБ` / `9.8 MB`).
- Строки `settings.covers.*` добавляются в `en.json` и `ru.json`.

### D7. Колесо мыши (ПК)

`wheelSmoother` — виджет, который реализует **только** `fyne.Scrollable`. Он кладётся в Stack над целью (сетка, `container.Scroll` страницы произведения, лента). Для нажатий, наведения и перетаскивания полосы прокрутки он прозрачен.

- `Scrolled(ev)` → `target = clamp(target − ev.Scrolled.DY, 0, max)`. Это то же расстояние, на которое Fyne сдвигал за одно событие.
- Анимация 100 мс (`fyne.AnimationEaseOut`) от текущего смещения к `target`. Новое событие перезапускает анимацию от текущего смещения.
- Цель меняется через `ScrollToOffset` (`GridWrap` и `container.Scroll`). В ленте `ScrollToOffset` должен вызывать `updateVisible`: если `OnScrolled` при программном смещении не вызывается, лента зовёт его сама.
- На телефоне не создаётся (`IsMobile()`). В постраничном режиме не используется: там колесо листает и масштабирует.
- Ctrl+колесо (масштаб в ленте, если он есть) пропускается к цели без сглаживания.

### D8. GC — по замеру

Если поле `gc` замера занимает заметную долю рывков (паузы ≥ 1 мс в сценариях `grid`/`strip`), добавляется `sync.Pool` буферов `[]byte` по классам размеров для `image.RGBA` в `pages` (куски) и `thumbs`. Буфер возвращается в пул при вытеснении из кэша, если на него нет других ссылок: для кусков ленты — когда вытеснен весь `Result`. `GOGC`/`SetMemoryLimit` — только если пула не хватит, с новыми цифрами.

## Risks / Trade-offs

- [Зависимость от внутренностей Fyne 2.8 (отсечение, кэш текстур по объекту, срок 1 мин)] → версия зафиксирована в `go.mod`; поведение описано здесь; при обновлении Fyne перепроверить замером.
- [Одна строка пикселей прогреваемой страницы на краю экрана на кадр] → это строка той же страницы, что и так сразу за краем; при зазоре между страницами (ошибка, «Конец») прогрев откладывается, пока край не занят страницей.
- [Видеопамять: пул обложек на 3 экрана и до 4 страниц постраничного режима] → на телефоне ~30–60 МБ сверх нынешнего; объекты вне пула отпускают `Image`.
- [После долгого чтения (> 1 мин) текстуры скрытых вкладок истекают, и при закрытии читалки видимые обложки загрузятся заново одним кадром] → пользователь не замечал рывка при закрытии; если замер покажет, обложки при показе вкладок пропускаются через бюджет D3.
- [Заглушки при быстром пролёте] → согласовано: плавность важнее мгновенного появления.
- [`VACUUM` большого каталога занимает секунды и держит `writeMu`] → выполняется в фоне; сканирование подождёт.
- [Сценарии `frameprobe` не нагружают путь касаний] → на эмуляторе дополнительно ручные свайпы.

- `GridWrap` держит на экране одну лишнюю карточку (последний индекс включительно) и не вызывает для неё `UpdateItem` при прокрутке — `visibleRange` повторяет его формулу, иначе карточка осталась бы с заглушкой.

### D8 — по замеру

Поле `gc` показывает паузы ≥ 1 мс в `grid` и `strip` (условие задачи 9.1 выполнено), но причина — не поток выделений: в читалке на эмуляторе живая куча 220 МБ при `debug.SetMemoryLimit(192 МБ)` (`cmd/mangareader/app_android.go`). Куча выше предела — сборщик работает непрерывно (~100 пауз в секунду, 4,7 с пауз за 16 с ленты). Кэш страниц читалки (80 МБ на телефоне), миниатюры (до 64 МБ), пул обложек и кэш обложки страницы произведения вместе не помещаются под предел. `sync.Pool` буферов RGBA держит дополнительные буферы живыми и эту причину не устраняет. Решение по 9.1 — за пользователем: предел памяти и лимиты кэшей — в non-goals этого изменения.

## Дополнение после проверки на телефоне (2026-11-02)

Пользователь проверил dev-APK на телефоне. Три замечания: dev-сборка должна вести себя как обычная, а тесты включаться вручную; нужен файл с результатами и «Поделиться»; «Кэш обложек» (4,6 МБ на 83 обложки) не совпадает со статистикой Android («Данные» 11,37 МБ, «Кэш» 115 КБ). Обложки лежали в `library.db`, поэтому Android считал их в «Данных», а «Данные» включают ещё каталог, `user.db`, настройки и профиль GeckoView. Ошибку базы, о которой сообщил пользователь, не удалось воспроизвести ни ему, ни на эмуляторе.

### D10. Обложки — файлами в системном кэше

Возврат к решению Q27 grill-сессии: обложки переезжают из таблицы `covers` каталога в файлы.

- `thumbs.DirStore` (реализует `thumbs.Store` и `app.CoverCache`). Файл `<sha1(ключ)[:20]>_<w>x<h>.jpg` в одной папке. `Save` пишет через временный файл и `rename`, затем удаляет файлы того же ключа с другим размером. `Size` — сумма размеров файлов. `Clear` удаляет все файлы. `Prune(keys)` удаляет файлы, хэш которых не входит в набор ключей.
- Папка: Android — `os.TempDir()/covers` (Fyne выставляет `TMPDIR` = `getCacheDir()`); ПК — `cache/thumbs` в папке приложения. Создаётся при первом сохранении.
- `Services`: `Thumbs.SetStore(dirStore)` и `Covers = dirStore` независимо от каталога. Строка в настройках работает и без SQLite.
- Уборка: `Services.PruneCovers()` после каждого сканирования (из `Library.OnScanned`, в горутине): набор `thumbs.CacheKey` галерей библиотеки. Смена папки на Android вызывает `Clear`.
- Каталог: таблица `covers` удаляется из схемы, `schemaVersion` 4 → 5. Каталог версии 4 не пересоздаётся: при открытии `DROP TABLE covers`, `PRAGMA user_version`, `VACUUM`. Удаление по `rel` из `covers` при сохранении сканирования убирается. Тип `catalog.Covers` удаляется.

### D11. Dev-сборка: «Разработка» в настройках, отчёт в файл, «Поделиться»

- Ничего не запускается само: `startProbe` при старте только подключает раздел «Разработка» (`Settings.AddCard`). Счётчик кадров (бесконечная анимация) работает, только пока идут тесты или ручной замер. Вне них в журнал ничего не пишется.
- Сводки собираются в отчёт (`probeReport`): шапка (версия, устройство `runtime.GOOS`/модель, размер и масштаб холста, «Ограничить 60 Гц», плотность сетки, число галерей, дата) и строки сводок. Каждая строка дублируется в журнал, как раньше.
- Файл: Android — Kotlin `DevReport.save(ctx, tree, name, text)` через `DocumentsContract`: папка `.perf` в дереве SAF создаётся при необходимости. ПК — `perf/` в папке приложения. Ошибка сохранения — уведомление, отчёт остаётся для «Поделиться».
- «Поделиться» (Android) — Kotlin `DevReport.share(ctx, subject, text)`: `Intent.ACTION_SEND`, `text/plain`, `Intent.createChooser`. Текстом, без `FileProvider` (отчёт — несколько КБ, а зависимость androidx не нужна). ПК — «Открыть папку» (`storage.Reveal`).
- JNI — новый пакет `internal/devreport` (Android: C + Go по образцу `internal/display`; остальные платформы — сохранение в файл, `Share` возвращает `ErrUnsupported`). Пакет — в `internal/archtest` и в архитектурные документы. Используется только из `probe_on.go` (тег `frameprobe`), но собирается всегда: так его проверяет `go vet` обычной сборки.
- Строки раздела — ключи `dev.*` в `en.json`/`ru.json` (в `internal/ui` нет кириллицы).
