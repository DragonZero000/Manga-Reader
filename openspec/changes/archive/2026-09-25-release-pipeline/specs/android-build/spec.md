## MODIFIED Requirements

### Requirement: Подпись и обновление поверх установленной версии
APK SHALL подписываться одним и тем же ключом при каждой сборке на одной машине (отладочные сборки — отладочным ключом Android SDK; сборка с ключом проекта задаётся переменными окружения), чтобы новую сборку можно было установить поверх предыдущей без удаления и без потери настроек. APK с большей версией, подписанный тем же ключом, MUST устанавливаться поверх меньшей без удаления, поскольку его `versionCode` больше. Релизы проекта MUST подписываться одним постоянным ключом проекта (см. `release-pipeline`). Release-сборка с флагом `-require-signing` MUST завершаться ошибкой, если ключ не задан, вместо выдачи неподписанного APK.

#### Scenario: Повторная установка
- **WHEN** разработчик дважды собирает и устанавливает APK командой `adb install -r`
- **THEN** вторая установка проходит без удаления приложения, выбранная папка библиотеки сохраняется

#### Scenario: Обновление версии
- **WHEN** установлена сборка `0.1.0`, а затем тем же ключом собрана и установлена `0.2.0`
- **THEN** установка проходит как обновление, настройки и выбранная папка библиотеки сохраняются

#### Scenario: Переход с ручного номера сборки
- **WHEN** установлена сборка с прежним `versionCode` `1`, а затем тем же ключом установлена сборка `0.1.0` с вычисленным `versionCode` `100`
- **THEN** установка проходит как обновление

#### Scenario: Обязательная подпись без ключа
- **WHEN** выполняется `go run ./tools/android-build -release -require-signing`, а `MANGAREADER_KEYSTORE` не задан
- **THEN** сборка завершается ошибкой до запуска Gradle, и APK не создаётся

#### Scenario: Без обязательной подписи
- **WHEN** выполняется `make build-android-release` без `MANGAREADER_KEYSTORE`
- **THEN** создаётся неподписанный release-APK с предупреждением, как и раньше

## ADDED Requirements

### Requirement: Лицензии в APK
Сборка APK SHALL класть `LICENSE` и `THIRD_PARTY_NOTICES.md` из корня проекта в `assets/` APK. Эти копии MUST генерироваться при каждой сборке и MUST NOT храниться в репозитории.

#### Scenario: Состав APK
- **WHEN** выполнен `make build-android`
- **THEN** APK содержит `assets/LICENSE` и `assets/THIRD_PARTY_NOTICES.md`, совпадающие с файлами в корне проекта

#### Scenario: Рабочая копия после сборки
- **WHEN** выполнен `make build-android`, затем `git status`
- **THEN** скопированные в `android/app/src/main/assets/` файлы не показываются как новые
