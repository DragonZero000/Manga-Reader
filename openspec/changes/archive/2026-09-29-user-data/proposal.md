## Why

Готовятся функции, которые хранят данные пользователя о произведениях: свои и скрытые тэги (следующее изменение `custom-tags`), позже — группы произведений и прогресс чтения. Каталог `library.db` для этого не годится: это восстанавливаемый кэш, он пересоздаётся при смене версии схемы, повреждении и смене папки, а пользовательские данные восстановить неоткуда. Кроме того, ключ произведения — путь к файлу, и переименование или перемещение архива разрывает связь с данными.

## What Changes

- Новая база `user.db` рядом с `library.db` (ПК — папка приложения, Android — личная папка приложения). Она никогда не пересоздаётся: схема меняется миграциями. Повреждённая база не удаляется, а откладывается в резервную копию, пользователь получает сообщение.
- Таблица произведений `works` со стабильным внутренним идентификатором `uid`. Будущие пользовательские данные ссылаются на `uid`, а не на путь. Запись создаётся только при первом сохранении данных о произведении.
- Отпечаток содержимого архива: хеш списка картинок (имя, CRC32, размер) из оглавления zip, без `meta.json`. Вычисляется при разборе архива и хранится в галерее. Номер произведения на сайте (`id` из meta.json) для идентичности не используется: у разных сайтов разные номера, и они пересекаются.
- Сверка после каждого успешного сканирования: файлы на месте → снять пометку «сирота»; новый файл с тем же отпечатком, что у ровно одной пропавшей записи, → перенос записи на новый путь; пропавшие → пометить сиротой; сироты старше срока → удалить.
- Защита: неуспешное сканирование или недоступная папка ничего не помечает и не удаляет; пустая папка (ни одного файла) не порождает новых сирот. Процентного порога нет.
- Удаление через меню приложения сразу помечает запись сиротой. Если файл восстановят из корзины, данные вернутся по отпечатку.
- Записи привязаны к папке библиотеки. Очистка касается только текущей папки, поэтому переключение между папками данные не теряет.
- Настройка «Хранить данные удалённых произведений»: 1 день, 1 неделя, 1 месяц (по умолчанию), 3 месяца, 1 год, бессрочно, своё число дней.
- Каталог получает новую версию схемы (галереи с отпечатком) и один раз пересканирует библиотеку целиком.

## Non-goals

- Интерфейс пользовательских данных (тэги, группы, прогресс) — это следующие изменения; здесь только основа и настройка.
- Перенос данных между разными папками библиотеки (Android: «Изменить папку» на другую папку).
- Экспорт и импорт пользовательских данных.
- Архивы, отличные от `.zip` (не поддерживаются приложением).

## Capabilities

### New Capabilities
- `user-data`: база пользовательских данных — расположение, миграции, восстановление после повреждения, записи произведений, сверка со сканированием, перенос по отпечатку, срок хранения сирот и его настройка.

### Modified Capabilities
- `library-scan`: разбор архива вычисляет отпечаток содержимого.
- `library-location`: на ПК в папке приложения появляется `user.db` (требование «Файлы только в папке приложения на ПК»).

## Impact

- Платформы: Windows и Android ведут себя одинаково. На ПК папка библиотеки учитывается как «папка библиотеки приложения», а не как абсолютный путь, чтобы перенос портативной папки не отвязывал данные.
- Код: новый пакет `internal/userdata`; `internal/model` (поле отпечатка); `internal/library` (отпечаток, уведомление о сканировании и удалении); `internal/catalog` (версия схемы 3); `internal/app` (сборка, настройка срока); `internal/ui` (карточка настройки, сообщение о повреждённой базе).
- Зависимости: новых нет (используется `github.com/mattn/go-sqlite3`, уже подключённый).
- Строки: новые ключи в `internal/i18n/locales/*.json`.
- Документация: архитектура и руководство пользователя (en + ru), `internal/archtest`.
