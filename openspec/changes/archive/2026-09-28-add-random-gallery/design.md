## Context

Библиотека и поиск показывают галереи через общую сетку `galleryGrid` (`internal/ui/screens/grid.go`); её `Items()` — ровно то, что видно на экране. Поиск не ограничивает выдачу (`Query.Limit` не задаётся), поэтому `Items()` результата поиска — все найденные галереи. Страница произведения открывается колбэком `open(model.Gallery)` (`Details.Open`), переданным в оба экрана.

## Goals / Non-Goals

**Goals:**
- Кнопка 🎲 в библиотеке и поиске, выбор из того, что показано в сетке.
- Режимы «С повторами / Без повторов» с независимыми кругами для двух экранов.

**Non-Goals:**
- Кнопка «Ещё случайное» на странице произведения.
- Взвешенный выбор (по дате, прочитанности и т. п.).
- Сохранение круга между запусками.

## Decisions

**Выбор из `grid.Items()`, а не из `Source.Galleries()`.** Пользователь ожидает, что 🎲 выбирает из того, что видит. Для поиска это единственный правильный вариант; для библиотеки совпадает с `Source.Galleries()`, но так оба экрана устроены одинаково.

**Отдельный тип `randomPicker` без виджетов.** Состояние: режим, «отпечаток» набора, перемешанный остаток круга, последний выданный ключ. `Pick(items []model.Gallery) (model.Gallery, bool)`:
- «С повторами» — `rand.IntN(len(items))`.
- «Без повторов» — «мешок»: при смене отпечатка или пустом мешке мешок заполняется перемешанными ключами (`rand.Shuffle`); если первый элемент нового круга равен последнему выданному и в наборе больше одного элемента, он меняется местами с другим. Ключи, которых уже нет в наборе, пропускаются.
- Отпечаток набора — число элементов и хеш ключей по порядку (FNV-64). Альтернатива «сравнивать срез целиком» проще, но хранит копию; хеш достаточно надёжен для этой цели.

Picker живёт в UI-потоке (вызывается из обработчика кнопки), синхронизация не нужна. Источник случайности подменяется в тестах (`*rand.Rand` с фиксированным seed).

**Активность кнопки.** Библиотека: после `SetItems` кнопка активна при `len(items) > 0`. Поиск: то же в `apply`; ошибка разбора не трогает сетку, поэтому кнопка сохраняет прежнее состояние. Все изменения — в UI-потоке (`applyScan`, `apply` уже вызываются через `fyne.Do`).

**Настройка.** Ключ `random.mode`: `repeat` (по умолчанию) / `norepeat`, функции `app.RandomMode(settings)` по образцу `app.SearchMode`. Экран «Настройки» получает колбэк `onRandomMode`, который Shell передаёт в оба экрана (`SetRandomMode`) — так же, как сейчас `search.SetMode`. Смена режима сбрасывает круги.

**Размещение.** Библиотека: `AddTool`-подобная вставка в `tools` перед «Браузер»/«Обновить» (иконка `theme.ViewRefreshIcon` занята — берём `theme.MediaReplayIcon` или собственный ресурс кубика). Поиск: в `buttons` после 🔍.

## Risks / Trade-offs

- [Иконка кубика отсутствует в теме Fyne] → своя SVG-иконка в ресурсах (`fyne bundle`), окрашиваемая через `theme.NewThemedResource`.
- [Кнопка на узком экране телефона теснит поле поиска] → кнопка только с иконкой, без подписи; на панели библиотеки подпись тоже не нужна.
- [В режиме «Без повторов» после сканирования круг сбрасывается даже при добавлении одного файла] → приемлемо: так проще и предсказуемо; галерея могла выпасть раньше — это не нарушает требование.

## Platforms

Windows и Android — одинаково; платформенного кода нет, build tags не нужны.
