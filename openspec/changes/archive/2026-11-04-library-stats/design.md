## Context

Все данные для статистики состава уже есть в памяти. `library.Source.Galleries()` отдаёт текущий список с наложенными своими и скрытыми тегами (`Custom`, `Hidden`, `EffectiveTags()`), а `search.Index.Search` возвращает ключи по запросу. Отдельного хранилища для статистики не нужно.

Не хватает трёх вещей:
- признака «в архиве есть `meta.json`»: сейчас его нельзя отличить от архива с пустым `meta.json`;
- условий «нет тега типа» в поиске;
- поддержки цветной подписи у вкладок Fyne (`container.AppTabs`): у `TabItem` есть только `Text` и `Icon`, а цвет подписи берётся из темы.

Сейчас вкладки собираются в `internal/ui/shell.go`: Библиотека, Поиск, Ошибки, Настройки. На Android они внизу, на ПК — слева (`TabLocationLeading`). Изменения библиотеки отмечает `Shell.libRev`, по нему поиск решает, повторять ли запрос.

## Goals / Non-Goals

**Goals:**
- Статистика по требованиям `library-stats` на Windows и Android, без кадров дольше 50 мс при библиотеке в тысячи произведений.
- Подсчёт в сервисном пакете без виджетов, который можно проверить обычными тестами.
- Нажатие на любую строку даёт поисковый запрос с тем же числом найденных, что в строке.
- Вкладка «Ошибки» появляется и исчезает без пересоздания остальных вкладок.

**Non-Goals:**
- Статистика чтения, история, графики, экспорт (см. proposal).
- Подсчёт статистики в SQL каталога.
- Новая платформенная функция. Код общий, stub не нужен.

## Decisions

### 1. Пакет `internal/stats`, подсчёт в Go по списку галерей

`stats.Compute(gs []model.Gallery, opt Options) Result` — чистая функция:
- `Options`: исключения по блокам, режимы топов, границы корзин, включённые блоки, `time.Location` для роста библиотеки;
- `Result`: структуры по блокам, готовые к показу.

Выборку собирает адаптер в `internal/app`:
1. пустой фильтр — `Source.Galleries()`;
2. иначе `search.Parse` → `Index.Search` → ключи, по ним галереи из того же снимка `Galleries()`.

Почему не SQL в `library.db`. Каталог может работать в памяти (`MemIndex`, если SQLite недоступна). Наложение тегов уже применено к галереям в памяти. А один проход по 10 000 галерей с картами по тегам занимает единицы миллисекунд. SQL дал бы вторую реализацию тех же правил и рассинхрон с `EffectiveTags()`.

Альтернатива — считать прямо в `internal/ui/screens`. Отклонена: правила пакетов (archtest) и тестируемость без окна.

### 2. Пересчёт: одна фоновая горутина, отмена устаревшего

`StatsService` в `internal/app` хранит последний запрос (фильтр + опции + `libRev`). Каждый новый запрос отменяет контекст предыдущего, `Compute` проверяет `ctx` между блоками. Результат уходит в UI через `fyne.Do` вместе с номером запроса, и экран отбрасывает результат не последнего запроса.

Экран считает «надо пересчитать», если изменился `libRev`, фильтр, исключения или настройки. При открытии вкладки и при `libRev++` с открытой вкладкой экран просит пересчёт. Пока вкладка закрыта, `libRev` только запоминается. Ввод фильтра проходит через тот же debounce, что поиск в режиме «При вводе». Настройка `search.mode` на фильтр статистики не влияет.

### 3. Хранение настроек — `storage.Settings`, JSON в одном ключе на группу

Ключи в `internal/app` (рядом с остальными `Key…`, проверяются `settings_keys_test.go`):
- `stats.filter` — текст фильтра;
- `stats.excluded` — JSON `{"artist": ["x"], "custom": ["tag:fav"], "hidden": [...]}`: ключ — id блока, значения — канонические строки тегов;
- `stats.blocks` — JSON-список выключенных блоков (отсутствие = всё включено, новые блоки будущих версий видны по умолчанию);
- `stats.modes` — JSON `{"artist": "size", ...}`;
- `stats.bounds.pages`, `stats.bounds.size` — строки границ как ввёл пользователь, после проверки.

Не `user.db`: это настройки отображения, они не привязаны к `uid` произведения и не должны переживать восстановление `user.db`. Битое значение → значение по умолчанию и запись в лог.

### 4. Признак `meta.json`: поле `Gallery.HasMeta`, `schemaVersion` 5 → 6

Сканер ставит `HasMeta = true`, если `meta.json` найден и разобран. Galleries хранятся в каталоге как JSON, поэтому у старых записей поле окажется `false`. Повышение `schemaVersion` пересоздаёт `library.db`, и библиотека один раз пересканируется (как при прошлых сменах формата). `user.db` не затрагивается.

### 5. `missing:` в поиске

В `search/field.go` появляется поле `FieldMissing` (`KindText`, операции `OpHas`/`OpNotHas`), значения проверяются при разборе. В `MemIndex` условие проверяется по `EffectiveTags()` и `HasMeta`. В `catalog`:
- `missing:<тип>` — `NOT EXISTS (SELECT 1 FROM tags WHERE doc = d.id AND type = ? AND src IN (0,1))`;
- `missing:tags` — то же без типа;
- `missing:meta` — новая колонка `docs.has_meta`.

Общие проверки добавляются в `search/indextest`, чтобы обе реализации совпадали.

### 6. Запросы для переходов собирает `stats`, а не экран

`stats.Query(row RowRef, filter string) string` строит текст по правилам из спеки. Теги кавычатся тем же кодом, что на странице произведения (общая функция в `internal/search`). Тест на каждый тип строки сверяет: `Index.Search(Query(row))` возвращает ровно значение строки на тестовой библиотеке. Год загрузки считается в UTC, рост — в `time.Local`, так же, как разбирает даты поиск.

### 7. Экран `screens.Stats`

- Панель сверху (`container.NewBorder` с top): поле фильтра с подсказками (переиспользуется автодополнение поиска), кнопка ✕, кнопка «Настроить», ряд чипов исключений (с переносом строк).
- Блоки в `container.NewVScroll(VBox)`, обёрнутом в `WheelSmoother` (ПК) и кинетическую прокрутку (Android) как остальные списки.
- Строка — `widget`, который рисует подпись, значение и полоску из `canvas.Rectangle` (длина = доля от максимума блока). Нажатие — переход, правый клик / долгое нажатие — меню исключения.
- «Показать все» раскрывает блок на месте (список в `widget.List` фиксированной высоты с полем «Найти в списке»), чтобы тысячи строк `tag` не строились как `VBox`.
- Перестройка блоков при новом результате идёт без `Container.Refresh` над изображениями: на экране нет картинок, поэтому ограничение `fyne-render-gotchas` не мешает, но строки переиспользуются по индексу, а не пересоздаются.
- Обновление виджетов — только из UI-потока: результат подсчёта приходит через `fyne.Do`.

### 8. Вкладки и вкладка «Ошибки»

`Shell` собирает список `TabItem` по платформе (`fyne.CurrentDevice().IsMobile()`):
- ПК: Статистика, Библиотека, Поиск, [Ошибки], Настройки;
- Android: Библиотека, Поиск, Статистика, [Ошибки], Настройки.

`updateErrors` при переходе 0 ↔ >0 вызывает `Tabs.Remove(errorsTab)` или вставляет её в `Tabs.Items` перед «Настройками» и делает `Tabs.Refresh()`. Если удаляется выбранная вкладка, сначала `Select(statsTab)`. Стартовый `Select(libraryTab)` явный, потому что «Библиотека» на ПК больше не первая.

Красная иконка — `theme.NewErrorThemedResource` поверх `BadgeIcon`. Для красной подписи в копии Fyne (`third_party/fyne/container/tabs.go`) к `TabItem` добавляется неэкспортируемая важность с сеттером `SetImportance(widget.Importance)`. `tabButton` уже хранит `importance`, и рендер для `DangerImportance` берёт `theme.ColorNameError`. Правка помечается `// mangareader:` и записывается в `third_party/fyne/PATCHES.md`.

Альтернатива — свой ряд кнопок вместо `AppTabs`. Отклонена: пришлось бы заново делать нижние и боковые вкладки, индикатор, анимации и обработку слоёв.

### 9. Строки и форматы

Новые ключи `stats.*` в `locales/en.json` и `ru.json`. Числа, размеры и даты форматируются через `internal/i18n/format.go`, с теми же функциями, что на странице произведения. Названия блоков в чипах исключений берутся из тех же ключей, что заголовки блоков.

## Risks / Trade-offs

- [Большая библиотека: `Compute` на 20 000 галерей] → один проход, карты по типам, сортировка только у видимых блоков. Бенчмарк в `stats_test.go` с порогом 50 мс на ПК. Ввод фильтра с debounce, отмена устаревшего подсчёта.
- [Тысячи строк в «Показать все»] → `widget.List`, а не `VBox`. Поиск в списке фильтрует уже посчитанный срез без пересчёта статистики.
- [Своё имя совпадает у тегов разных типов → `custom-tag:"x" artist:"x"` может найти чуть больше] → это допущение записано в спеке. Точное условие «свой тег этого типа» потребовало бы нового поля поиска, не стоит того.
- [Пересканирование после смены `schemaVersion`] → один раз, в фоне, как при прошлых сменах. Сетка библиотеки показывает старые данные до конца скана, пользовательские данные не теряются.
- [Патч Fyne расширяет отличия от upstream] → правка маленькая, помечена и описана в `PATCHES.md`. При возврате на upstream подпись просто станет обычного цвета, иконка останется красной.
- [Исчезновение вкладки, пока по ней водят пальцем] → переключение через `fyne.Do` после скана, `Select` до `Remove`.

## Migration Plan

1. Версия каталога 6: при первом запуске `library.db` пересоздаётся, библиотека пересканируется. Откат на старую версию приложения так же пересоздаст каталог (версия не совпадёт), данных пользователя это не касается.
2. Новые ключи настроек появляются при первой правке. Старая версия приложения их игнорирует.
3. `THIRD_PARTY_NOTICES.md` не меняется: новых сторонних компонентов нет, копия Fyne та же.

## Open Questions

- Нет. Все продуктовые решения согласованы. Конкретные пороги производительности уточняются бенчмарком при реализации.

## Доработки после проверки на телефоне

### 10. Временные и постоянные исключения

Экран хранит два набора: временный (в памяти `Stats`, живёт до перезапуска) и постоянный (`stats.excluded`, как раньше, поэтому уже сохранённые исключения становятся постоянными). В подсчёт уходит их объединение, `stats` о видах не знает. Перенос в постоянные убирает тег из временных. Подтверждение — `dialog.NewConfirm`.

### 11. Порядок и «Самые большие»

`Options.Ascending map[BlockID]bool` (топы типов, `custom`, `hidden` и псевдоблок `largest`) и `Options.LargestBy` (`ModeSize` или `ModePages`). `SizeBlock.Largest` теперь вся выборка в нужном порядке (у `Large` есть `Pages`): экран показывает первые 5 и «Показать все». Сортировка 20 000 элементов — миллисекунды. Ключи настроек `stats.order` (JSON `{id: "asc"}`) и `stats.largest`.

Общая часть топа и списка самых больших — `expandList`: 5 строк, «Показать все», «Найти в списке», `widget.List` высотой `min(n, 10)` строк, вычисленной при раскрытии, а не при фильтрации, чтобы высота не прыгала. `TopLimit` = 5.

### 12. Поля Сводки

Видимость — только в UI (`stats.summary.hidden`, список id полей). Если скрыты все поля, Сводка считается выключенной и в `Options.Disabled`. В «Настроить» поля — `widget.Accordion` под галочкой «Сводка», скрытый при снятой галочке.

### 13. Долгое нажатие на телефоне — правка копии Fyne

В `internal/driver/mobile/canvas.go` `tapDown` запускает таймер на `tapSecondaryDelay`. Если к его срабатыванию палец не сдвинулся дальше порога, не начато перетаскивание и касание не остановило бросок, в UI-потоке (`DoFromGoroutine`) вызывается `TappedSecondary` объекта под пальцем, а касание помечается «отработанным». `tapUp` для отработанного касания ничего не вызывает. Обработчик долгого нажатия передаётся из драйвера в `tapDown`. Правка помечается `// mangareader:` и описывается в `PATCHES.md`.

Альтернатива — `mobile.Touchable` на строке статистики для подсветки. Отклонена: Fyne тогда отдаёт перемещение пальца строке, а не прокрутке, и экран перестаёт прокручиваться с этой строки.

Подсветка строки при открытом меню: `showMenu` получает колбэк закрытия (`PopUpMenu.OnDismiss` и выбор пункта), строка держит флаг `menuOpen` и рисует фон наведения.

### 14. Формат объёма

`i18n.SizeDigits(n, digits)`, где `Size` = `SizeDigits(n, 1)`. Экран статистики использует две цифры.
