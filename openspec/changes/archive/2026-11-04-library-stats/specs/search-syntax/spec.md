## MODIFIED Requirements

### Requirement: Условия поле:значение
Элемент вида `поле:значение`, где поле — одно из `title`, `tag`, `artist`, `group`, `parody`, `character`, `language`, `category`, `custom-tag`, `hidden-tag`, `missing`, `id`, `pages`, `uploaded`, `favorites`, `scanlator`, `added`, `size`, SHALL превращаться в фильтр запроса. Имя поля MUST распознаваться без учёта регистра. Значение MAY быть в двойных кавычках. Все условия и слова MUST объединяться логическим «И». `custom-tag` MUST давать фильтр «есть свой тег с этим именем любого типа», `hidden-tag` — «есть скрытый тег с этим именем любого типа». Значение `missing` MUST быть одним из `artist`, `group`, `parody`, `character`, `language`, `category`, `tag` (нет действующего тега этого типа), `tags` (нет действующих тегов вообще) или `meta` (в архиве нет `meta.json`), без учёта регистра; другое значение MUST приводить к ошибке разбора «неизвестное значение».

#### Scenario: Тег в кавычках
- **WHEN** разбирается `tag:"tag 1"`
- **THEN** получается фильтр «есть тег `tag 1` любого типа»

#### Scenario: Тег определённого типа
- **WHEN** разбирается `Artist:"Artist 1"`
- **THEN** получается фильтр «есть тег `artist:artist 1`»

#### Scenario: Условия и слова вместе
- **WHEN** разбирается `school pages:>20 language:japanese`
- **THEN** получаются слово `school` и два фильтра: страниц больше 20 и тег `language:japanese`

#### Scenario: Свой тег
- **WHEN** разбирается `Custom-Tag:"my fav"`
- **THEN** получается фильтр «есть свой тег `my fav` любого типа»

#### Scenario: Скрытый тег
- **WHEN** разбирается `hidden-tag:yuri`
- **THEN** получается фильтр «есть скрытый тег `yuri` любого типа»

#### Scenario: Нет автора
- **WHEN** разбирается `Missing:Artist`
- **THEN** получается фильтр «нет действующего тега типа `artist`»

#### Scenario: Неизвестное значение missing
- **WHEN** разбирается `missing:title` при русском интерфейсе
- **THEN** возвращается ошибка разбора, указывающая на `missing:title`, с причиной «неизвестное значение»

### Requirement: Исключение тегов
Префикс `-` перед условием по тегу (`tag`, `artist`, `group`, `parody`, `character`, `language`, `category`, `custom-tag`, `hidden-tag`) SHALL превращать его в фильтр «нет тега» той же области (действующие, свои или скрытые теги). Префикс `-` перед `missing` MUST давать обратный фильтр: `-missing:artist` — «есть действующий тег типа `artist`», `-missing:tags` — «есть хотя бы один действующий тег», `-missing:meta` — «в архиве есть `meta.json`». Префикс `-` перед другими полями или словами MUST приводить к ошибке разбора «исключение поддерживается только для тегов».

#### Scenario: Исключение
- **WHEN** разбирается `-tag:"tag 3"`
- **THEN** получается фильтр «нет тега `tag 3` любого типа»

#### Scenario: Исключение своего тега
- **WHEN** разбирается `-custom-tag:"my fav"`
- **THEN** получается фильтр «нет своего тега `my fav`»

#### Scenario: Обратный missing
- **WHEN** разбирается `-missing:meta`
- **THEN** получается фильтр «в архиве есть `meta.json`»

#### Scenario: Исключение слова
- **WHEN** разбирается `-school`
- **THEN** возвращается ошибка разбора, указывающая на `-school`
