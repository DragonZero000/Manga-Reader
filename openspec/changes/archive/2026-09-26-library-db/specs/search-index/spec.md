## REMOVED Requirements

### Requirement: Индекс в памяти
**Reason**: Рабочим индексом становится индекс в каталоге библиотеки (SQLite), который переживает перезапуск; `MemIndex` остаётся эталонной реализацией для тестов.
**Migration**: Требования перенесены в «Индекс в каталоге»; поведение поиска не меняется, кроме нормализации символов.

## ADDED Requirements

### Requirement: Индекс в каталоге
Приложение SHALL использовать индекс поиска на SQLite в каталоге библиотеки, реализующий интерфейс `Index`. Индекс MUST обновляться при каждом сканировании (добавленные и изменённые галереи — `Upsert`, удалённые — `Remove`), MUST сохраняться между запусками и MUST быть безопасен для одновременного поиска и обновления из разных горутин. Подстроки из 3 и более символов MUST искаться по полнотекстовому индексу FTS5 с токенизатором trigram, более короткие — сравнением `LIKE`; символы `%`, `_` и `\` в запросе MUST трактоваться буквально. Результаты индекса в каталоге MUST совпадать с результатами `MemIndex` на одном наборе тестов.

#### Scenario: Заполнение при сканировании
- **WHEN** библиотека просканирована и в ней есть `example.zip`
- **THEN** поиск по слову `english` возвращает `local:example.zip`

#### Scenario: Удаление архива
- **WHEN** `example.zip` удалён из папки и библиотека повторно просканирована
- **THEN** поиск по слову `english` не возвращает результатов

#### Scenario: После перезапуска
- **WHEN** библиотека просканирована, приложение перезапущено, и до окончания нового сканирования выполняется поиск `english`
- **THEN** находится `example.zip`

#### Scenario: Короткое слово
- **WHEN** выполняется поиск `gl` (2 символа)
- **THEN** находится `example.zip` (название «english name»)

#### Scenario: Спецсимволы
- **WHEN** выполняется поиск `100%`
- **THEN** находятся только произведения, в полях которых есть подстрока `100%`, а не все, где есть `100`

## MODIFIED Requirements

### Requirement: Совпадение слов
Слово или фраза свободного текста SHALL совпадать с произведением, если оно входит как подстрока хотя бы в одно из полей: основное название, альтернативное название, имя любого тега, тип и имя тега в форме `тип:имя`, сканлейтор, путь файла относительно библиотеки, внешний ID. Сравнение MUST выполняться после одинаковой нормализации поля и запроса: совместимая декомпозиция Unicode (NFKC), нижний регистр, `ё` → `е`. Если в запросе несколько слов, произведение MUST содержать каждое из них (в одном или разных полях).

#### Scenario: Часть слова в названии
- **WHEN** выполняется поиск `glis`
- **THEN** находится `example.zip` (название «english name»)

#### Scenario: Часть слова в теге
- **WHEN** выполняется поиск `japan`
- **THEN** находится `example.zip` (тег `language:japanese` и название «japanease name»)

#### Scenario: Слова в разных полях
- **WHEN** выполняется поиск `english doujin`
- **THEN** находится `example.zip`: «english» в названии, «doujin» в теге `category:doujinshi`

#### Scenario: Нет совпадения одного слова
- **WHEN** выполняется поиск `english manhwa`
- **THEN** `example.zip` не находится

#### Scenario: Кириллица и ё
- **WHEN** у произведения название «Ёлка», и выполняются поиски `ёлка`, `ЕЛКА` и `елк`
- **THEN** произведение находится каждым из них

#### Scenario: Полноширинные символы
- **WHEN** у произведения название «ABC», и выполняется поиск `ＡＢＣ`
- **THEN** произведение находится

### Requirement: Совпадение условий
Фильтры запроса SHALL проверяться так: тег («есть»/«нет») — точное совпадение нормализованного имени, а если тип указан — и типа; `title` — подстрока в основном или альтернативном названии; `scanlator` — подстрока (операция «содержит») или точное совпадение («равно»). Текстовые значения (имена тегов, `title`, `scanlator`) MUST сравниваться после той же нормализации, что и слова (NFKC, нижний регистр, `ё` → `е`). `pages` — по фактическому числу страниц; `favorites`, `id` — по значениям метаданных; `size` — по размеру файла; `uploaded` — по дате загрузки; `added` — по времени изменения файла. Произведение без значения поля (ноль, нулевая дата) MUST NOT удовлетворять числовым и датовым фильтрам по этому полю.

#### Scenario: Тег любого типа
- **WHEN** выполняется поиск `tag:japanese`
- **THEN** находится `example.zip` (тег `language:japanese`)

#### Scenario: Тег точного типа
- **WHEN** выполняется поиск `artist:japanese`
- **THEN** `example.zip` не находится

#### Scenario: Подстрока не совпадает с тегом
- **WHEN** выполняется поиск `tag:japan`
- **THEN** `example.zip` не находится: для тега нужно точное имя

#### Scenario: Исключение
- **WHEN** выполняется поиск `english -tag:"tag 3"`
- **THEN** `example.zip` не находится

#### Scenario: Число страниц
- **WHEN** выполняются поиски `pages:2` и `pages:>2`
- **THEN** `example.zip` находится первым поиском и не находится вторым

#### Scenario: Нет значения
- **WHEN** архив без `meta.json` и выполняется поиск `favorites:<10`
- **THEN** этот архив не находится

#### Scenario: Тег с ё
- **WHEN** у произведения тег `tag:ёжик`, и выполняется поиск `tag:ежик`
- **THEN** произведение находится
