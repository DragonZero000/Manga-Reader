## Context

Сейчас всё состояние библиотеки живёт в памяти процесса:
- `library.Scanner` держит `cache map[rel]cacheEntry` (размер, время изменения, галерея или ошибка). После перезапуска кэш пуст, и первое сканирование открывает **каждый** файл папки.
- `search.MemIndex` строится заново из результатов сканирования, поиск — линейный проход по документам.
- `thumbs.Cache` хранит миниатюры только в памяти; после перезапуска обложки снова декодируются из архивов в полный размер.
- `library.Links` (Android) хранит адреса страниц скачанных файлов в `links.json` в личной папке приложения; на Windows адрес берётся из метки загрузки NTFS (`Zone.Identifier`) при разборе. Копия одна: повреждённый `links.json` читается как пустой, и ссылки пропадают.

`search.Index` — готовый шов: UI зависит только от интерфейса, а поведение поиска подробно закреплено тестами `MemIndex`. Cgo уже обязателен на обеих платформах: Fyne требует gcc на Windows и NDK clang на Android.

## Goals / Non-Goals

**Goals:**
- при запуске библиотека показывается из каталога, открываются только новые и изменённые файлы;
- поиск через SQLite с теми же результатами, что у `MemIndex`, плюс нормализация символов;
- обложки на диске;
- каталог — восстанавливаемый кэш;
- замер запуска до и после.

**Non-Goals:** распаковка архивов, постраничная сетка из БД, изменение синтаксиса поиска.

## Decisions

### D1. Драйвер: `mattn/go-sqlite3` с тегом `sqlite_fts5`

Cgo уже есть, поэтому `mattn` не добавляет требований к сборке. Он быстрее всех, внутри эталонный SQLite 3.4x (trigram появился в 3.34), FTS5 включается тегом `sqlite_fts5`.
- **Отклонено:** `modernc.org/sqlite`: крупнее бинарник, в 1,5–3 раза медленнее, поддержку `GOOS=android` нужно проверять отдельно. `ncruces/go-sqlite3`: WASM и wazero, на Android без гарантий.
- **Тег прописывается везде.** `Makefile` (`TAGS := migrated_fynedo,sqlite_fts5`, в `test` — `go vet/test -tags sqlite_fts5`, в `run` — вместе с `EXTRA_TAGS`), базовые теги `tools/android-build` (`buildTags`), `.github/workflows/ci.yml` и `release.yml`.
- **Защита от сборки без тега.** Файл `internal/catalog/require_tag.go` (`//go:build !sqlite_fts5`) ссылается на неопределённый идентификатор `каталогу_нужен_тег_sqlite_fts5`. Сборка без тега падает с понятной ошибкой, а не с «no such module: fts5» при запуске.
- **Цена.** Первая сборка на каждой платформе компилирует SQLite из C (1–2 мин), потом используется кэш Go. В CI кэш сборки даёт `actions/setup-go`.

### D2. Пакет `internal/catalog`, схема и версия

```sql
meta(key TEXT PRIMARY KEY, value TEXT)            -- root: папка библиотеки
files(rel TEXT PRIMARY KEY, size INTEGER, mtime INTEGER,
      gallery BLOB,                               -- JSON model.Gallery; NULL — ошибка
      err_kind TEXT, err_text TEXT)               -- причина ошибки (D3)
docs(key TEXT PRIMARY KEY, rel TEXT, title_sort TEXT, title_norm TEXT, scan_norm TEXT,
     ext_id INTEGER, pages INTEGER, favorites INTEGER, size INTEGER,
     uploaded INTEGER, added INTEGER)             -- даты: UnixNano, 0 → NULL
docs_fts USING fts5(key UNINDEXED, hay, tokenize='trigram')
tags(key TEXT, type TEXT, name TEXT, PRIMARY KEY(key, type, name))  -- name нормализовано
covers(key TEXT PRIMARY KEY, rel TEXT, w INTEGER, h INTEGER, jpeg BLOB)
-- индексы: tags(name, type), covers(rel), docs(rel)
```

- **Параметры.** `PRAGMA journal_mode=WAL` (читатели не ждут писателя), `synchronous=NORMAL`, `busy_timeout=5000`. `database/sql`, до 4 соединений.
- **Версия.** `PRAGMA user_version = schemaVersion*100 + search.NormVersion`. Если она не совпадает, файл удаляется вместе с `-wal` и `-shm` и создаётся заново. Если `Open` или проверка `PRAGMA quick_check` падают, то же самое. Если не удалась и вторая попытка, приложение работает без каталога: `MemIndex`, кэш сканера только в памяти, обложки только в памяти. Причина пишется в журнал.
- **Папка библиотеки.** `Open(path, root)`: если `meta.root` отличается от `root`, таблицы `files`, `docs`, `docs_fts`, `tags` и `covers` очищаются. `Reset(root)` делает то же для смены папки на Android.

### D3. Кэш сканера в каталоге

В `library` появляется интерфейс без SQL:

```go
type ScanStore interface {
    Load() (map[string]StoredEntry, error)   // по rel
    Save(d ScanDelta) error                   // одна транзакция
}
type StoredEntry struct { Size int64; ModTime time.Time; Gallery model.Gallery; Err error }
type ScanDelta struct { Put map[string]StoredEntry; Delete []string }
```

- **Запуск.** `NewScanner(st, store)` заполняет `cache` из `store.Load()`.
- **Конец `Scan`.** В `Put` попадают новые и изменённые файлы, включая ошибки (кроме временных «занят»). В `Delete` — файлы, которых больше нет. `Save` вызывается одним вызовом, `catalog` пишет это одной транзакцией вместе с индексом (D4) и удалением обложек (D5).
- **Ошибки восстанавливаются с тем же текстом и тем же поведением `errors.Is`.** Для известных причин сохраняется вид (`err_kind`): `empty` → `ErrEmpty`, `no_images` → `ErrNoImages`, `not_zip` → `ErrNotZip`, `unsupported:<kind>:<ext>` → `&UnsupportedError{…}`. Остальные сохраняются как текст (`errors.New`). Список видов закрепляется тестом «сохранить и загрузить» для каждого вида.
- **`Invalidate`** по-прежнему помечает запись временной только в памяти.
- **`Source.LoadCatalog() ScanResult`** отдаёт галереи и ошибки из кэша сканера без обхода папки. `app.newServices` вызывает его синхронно, до создания окна: это чтение из БД (миллисекунды), архивы не открываются. Результат лежит в `Services.Cached`, оболочка показывает его (`Library.ShowCached`) до `AutoRefresh`. Если сканирование, запущенное событием «на переднем плане», успело показать свой результат раньше, `ShowCached` ничего не делает: результат сканирования свежее. Первоначальный вариант с загрузкой в фоне проиграл гонку этому событию на ПК (найдено проверкой на Windows).

Альтернатива — хранить только индекс поиска, а сканер оставить в памяти. Отклонено: тогда главный выигрыш, запуск без открытия архивов, пропадает.

### D4. Индекс поиска в каталоге

`catalog.Index` реализует `search.Index` над таблицами `docs`, `docs_fts` и `tags`.
- **Слова.** Для каждого слова: `d.key IN (SELECT key FROM docs_fts WHERE hay LIKE ? ESCAPE '\')` с `%`, `_` и `\`, экранированными в слове. FTS5 trigram сам использует индекс для шаблонов с подстрокой от 3 символов и сканирует таблицу для более коротких. SQL один, выбор пути делает SQLite. Поле `hay` — нормализованные поля документа через `\n` (слово `\n` не содержит, поэтому совпадение через границу полей невозможно).
- **Теги.** `EXISTS (SELECT 1 FROM tags t WHERE t.key = d.key AND t.name = ? [AND t.type = ?])`, для «нет» — `NOT EXISTS`.
- **`title` и `scanlator`.** `LIKE` по `title_norm` и `scan_norm` с экранированием; «равно» — `scan_norm = ?`.
- **Числа и даты.** `col > 0 AND …` (нуль и `NULL` не проходят), даты в `UnixNano`.
- **Сортировка.** `ORDER BY <поле> [DESC], key COLLATE NATSORT`. Коллация `NATSORT` регистрируется в `ConnectHook` через `model.NaturalLess`; при равенстве порядок всегда по возрастанию, как в `MemIndex`. `title_sort` = `strings.ToLower(Title)`, сравнение `BINARY`, как `strings.Compare` в `MemIndex`.
- **Число совпадений** считается отдельным `COUNT(*)` в той же транзакции чтения.
- **`SuggestTags`.** `GROUP BY type, name` с `name LIKE prefix%`, `ORDER BY count DESC, type || ':' || name`.
- **`Upsert` и `Remove`** вызываются из `Source.updateIndex`, как сейчас. `catalog` делает их частью транзакции `Save` (D3), если индекс и хранилище сканера — один объект каталога. Отдельный вызов `Upsert` вне сканирования тоже работает, в своей транзакции.
- **Согласованность.** Если при открытии `COUNT(docs)` не равно числу галерей в `files`, индекс перестраивается из `files` одной транзакцией.

**Общий набор тестов.** Пакет `internal/search/indextest` с `Run(t, newIndex func(t) search.Index)` переносит все сценарии из `memindex_test.go` и `search_test.go`, включая сортировки, спецсимволы, короткие слова и нормализацию. `MemIndex` и `catalog.Index` прогоняются по одному набору.

### D5. Нормализация

`search.Normalize(s) = strings.ReplaceAll(strings.ToLower(norm.NFKC.String(s)), "ё", "е")` (`golang.org/x/text/unicode/norm`). Константа `search.NormVersion = 1` входит в версию каталога: при изменении функции каталог пересоздаётся.
- **Кто применяет.** Парсер для слов и текстовых значений (`title`, `scanlator`, имена тегов в фильтрах); `MemIndex` для `hay`, `title` и `scan`; `catalog` для `hay`, `title_norm`, `scan_norm` и `tags.name`.
- `model.NewTag` не меняется: он приводит к нижнему регистру для показа, а нормализация для поиска применяется только в индексах.

### D6. Обложки на диске

В `thumbs` появляется интерфейс, `catalog` реализует его без импорта `thumbs`:

```go
type Store interface {
    Load(key string, w, h int) ([]byte, bool)
    Save(key, rel string, w, h int, jpeg []byte)
}
```

- **Воркер `thumbs.Cache`.**
  - До открытия архива: `Load(CacheKey(g), boxW, boxH)` → `jpeg.Decode` → `pages.ToRGBA`. Миниатюра уже нужного размера.
  - Если её нет: декодирование и уменьшение, как сейчас, затем `jpeg.Encode` с качеством 85 и `Save`.
  - Ошибки обложек не сохраняются.
- **Ключ** — `CacheKey(g)`, то есть путь и время изменения. Поля `w`, `h` должны совпасть с текущей областью, иначе обложка не используется и перезаписывается.
- **Очистка.** Обложки файлов из `ScanDelta.Delete` и изменённых файлов из `Put` удаляются в транзакции `Save` сканера (по `rel`).
- **Объём.** Около 30–60 КБ на обложку 358×512, это 30–60 МБ на 1000 произведений. Приемлемо для кэша. Его можно сбросить удалением `library.db`.

### D7. Подключение и расположение

- **Путь к файлу.** ПК: `filepath.Join(paths.AppDir(), "library.db")` (портативно, рядом с `settings.json`). Android: `a.Storage().RootURI().Path()/library.db`, рядом с `links.json`.
- **`root` каталога.** На ПК это путь папки библиотеки, на Android — URI дерева SAF.
- **`app.newServices`** открывает каталог и передаёт его в `library.NewSource(st, idx, store)` как индекс и хранилище сканера, а в `thumbs.Cache.SetStore` — как хранилище обложек. Если каталог недоступен, подставляются `MemIndex` и `nil`.
- **`SetFolder` на Android:** `catalog.Reset(newRoot)` перед `Source.SetStorage`.
- **Закрытие** каталога — в `onStopped` оболочки.

### D10. Ссылки скачанных файлов — две копии

Таблица `links(rel TEXT PRIMARY KEY, url TEXT)` в каталоге — вторая копия адресов страниц скачанных файлов. Решение пользователя: после проверки файла ссылка не должна зависеть от одного файла.

- **Запись.** Когда сканер разобрал файл и ссылка пришла из хранилища (`sourcer`: `links.json` на Android, метка NTFS на Windows), она попадает в `ScanDelta.Links` и пишется в `links` в транзакции `Save`. Ссылки из `meta.json` в таблицу не пишутся: они и так в архиве.
- **Чтение при разборе.** `readEntry`: если в `meta.json` ссылки нет, берётся `sourcer`, а если и там пусто — ссылка из `ScanStore` (`StoredLink(rel)`). Так ссылка переживает потерю метки NTFS.
- **Восстановление `links.json`.** `library.LoadLinks(path, backup)`, где `backup` — интерфейс `LinkBackup { Links() map[string]string }`, его реализует каталог. Если файл отсутствует или не читается, берутся ссылки из каталога и файл сразу записывается.
- **Перенос в новый каталог.** После создания каталога (новый файл или пересоздание, D2) `app` вызывает `catalog.ImportLinks(links.All())`.
- **Удаление.** `ScanDelta.Delete` удаляет строки `links` для удалённых файлов в той же транзакции; `PruneLinks` в `app`, как сейчас, чистит `links.json`.
- **Порядок в `app`.** Открыть каталог → `LoadLinks(path, catalog)` → если каталог новый, `ImportLinks`.

### D8. Потоки

`database/sql` безопасен для горутин. Каталог вызывается только из фоновых горутин: сканирование, поиск, воркеры миниатюр, `LoadCatalog` при запуске. UI-поток каталог не вызывает, результаты приходят через `fyne.Do`, как сейчас. WAL позволяет искать и читать обложки во время записи сканирования.

### D9. Замер

Запуск на S25 Ultra с 300 архивами (данные как в `render-perf`, `scratchpad/perftest`). Замеряются:
- (а) время от запуска до сетки с галереями — по журналу: строка `библиотека: … за N` и новая строка `каталог: загружено N галерей за M`;
- (б) время первого сканирования;
- (в) число открытий архивов при сканировании без изменений (счётчик в журнале).

Замер делается «до» на текущем коде и «после».

## Risks / Trade-offs

- [Сборка без тега `sqlite_fts5` (IDE, `go test ./...` вручную)] → понятная ошибка компиляции (D1); в `building.md` указано, что тег нужен.
- [Каталог поврежден, или приложение убили при записи] → WAL и транзакции; при ошибке открытия каталог пересоздаётся, это кэш.
- [Ссылка у файла, заменённого другим с тем же именем, остаётся прежней] → так же ведёт себя и нынешний `links.json` (по пути); удаление файла чистит обе копии.
- [Портативная копия папки приложения во время работы копирует незавершённый WAL] → при следующем открытии SQLite восстановит его или каталог пересоздастся; документировать: копировать при закрытом приложении.
- [Расхождение `docs` и `files` после сбоя] → проверка при открытии и перестройка (D4).
- [Коллация `NATSORT` на Go вызывается при каждом сравнении при сортировке] → на тысячах строк это миллисекунды; при необходимости можно хранить ключ естественной сортировки как колонку.
- [Размер бинарника +1,5 МБ, APK +~1 МБ] → приемлемо.
- [Нормализация меняет поведение поиска: `е` находит `ё`] → это цель; в спеке есть сценарии.

## Migration Plan

При первом запуске новой версии каталога нет: создаётся пустой, первое сканирование полное, как сейчас. Дальше запуски быстрые. `settings.json` и `problems` (просмотренные ошибки) не меняются; ссылки из `links.json` при первом запуске переносятся в новый каталог (D10). Откат: старая версия просто не знает про `library.db`, файл можно удалить.

Проверки на устройстве:
- Обложки пишутся в каталог: после прокрутки сетки в `covers` 34 обложки для области 384×512, в среднем ~62 КБ.
- `library.db`, заменённый мусором: журнал «file is not a database — создаю заново», полное сканирование (301), следующий запуск снова без открытия архивов (104 мс).
- Windows (`dist/mangareader.exe` во временной папке): `library.db` создаётся рядом с exe, при втором запуске каталог загружается до сканирования, сканирование открывает 0 файлов.

- Поиск с кириллицей (`елка`/`ЁЛКА`) на устройстве через adb не проверить (adb не вводит кириллицу); покрыт общим набором `indextest` для обоих индексов.
