## Context

После `project-base-init` есть модель `Gallery`, папка библиотеки (ПК и Android, обычные `os`-пути), оболочка с `Toast` и интерфейс `search.Index` с `NopIndex`. Архивы — `.zip` с изображениями и `meta.json`, часто внутри корневой подпапки (образец: `testdata/example.zip`). Спайк S2 (SQLite на Android) не завершён, поэтому это изменение не зависит от выбора хранилища индекса.

Сеть, API и rate limiting в этом изменении не используются.

## Goals / Non-Goals

**Goals:**
- Архивы из папки библиотеки видны на ПК и Android.
- Сканирование и декодирование не блокируют UI; прокрутка сетки плавная на сотнях архивов.
- `library.Source` — единственная точка доступа к данным архива; читалка будет использовать его же.

**Non-Goals:**
- Индекс поиска, читалка, дисковый кэш миниатюр, fsnotify, форматы кроме `.zip` (см. proposal).

## Decisions

### D1. Пакеты

```
internal/library/
  meta.go      — структура meta.json и перенос в Gallery
  archive.go   — ReadArchive(path, relPath) → Gallery: поиск meta.json и страниц в zip
  scanner.go   — Scanner: обход папки, кэш по (size, mtime), ошибки, сортировка
  source.go    — Source: Scan(ctx), Get(key), OpenPage(key, page)
internal/thumbs/
  thumbs.go    — декодирование + уменьшение + LRU-кэш в памяти
internal/ui/screens/library.go — сетка, счётчик, обновление, пустое состояние
```

`library` и `thumbs` не зависят от виджетов Fyne (добавляются в `archtest`).

### D2. Чтение zip

`archive/zip.OpenReader(path)` — на ПК и Android путь обычный (решение D6 из `project-base-init`), `io.ReaderAt` есть. Архив открывается на время разбора и закрывается; для страниц — открывается заново на каждый `OpenPage`.

*Альтернатива:* держать `zip.ReadCloser` открытым на всё время жизни галереи. Отклонено: сотни открытых дескрипторов и блокировка файла на Windows (пользователь не сможет удалить/заменить архив). Цена повторного открытия — чтение центрального каталога (единицы КБ), приемлемо.

`OpenPage` читает страницу целиком в память и возвращает `io.ReadCloser` поверх буфера, закрыв архив сразу. Страница манги — сотни КБ, это проще и безопаснее, чем держать архив открытым до закрытия потока.

### D3. Поиск meta.json и страниц

- `meta.json`: среди файлов с базовым именем `meta.json` (без учёта регистра) выбирается с наименьшей глубиной пути.
- Страницы: расширения `jpg/jpeg/png/gif/webp`; исключаются пути с сегментами `__MACOSX` или начинающиеся с `.`.
- `Page.Name` — полный путь внутри архива (`example/1.jpg`), поэтому натуральная сортировка по нему корректно упорядочивает и архивы с вложенными главами-папками.
- Некорректный `meta.json` → галерея без метаданных + предупреждение (`ScanResult.Warnings`), архив не теряется.

### D4. Структура meta.json

```go
type metaJSON struct {
    ID    int64 `json:"id"`
    Title struct{ English, Japanese, Pretty string } `json:"title"`
    UploadDate   int64  `json:"upload_date"`
    NumPages     int    `json:"num_pages"`
    NumFavorites int    `json:"num_favorites"`
    Scanlator    string `json:"scanlator"`
    Tags []struct{ Type, Name string } `json:"tags"`
}
```

Поле `id` в некоторых выгрузках бывает строкой — используется собственный тип `flexInt`, принимающий число или строку с числом. Неизвестные поля игнорируются.

### D5. Инкрементальное сканирование

`Scanner` хранит `map[relPath]entry{size, modTime, gallery}`. Обход `filepath.WalkDir`; для каждого `.zip` сравниваются `Size()` и `ModTime()` из `DirEntry.Info()`; совпадение → переиспользование без открытия архива. Итог сканирования содержит `Added/Changed/Removed` для вызова `Index.Upsert/Remove`. Кэш только в памяти: при запуске приложения первое сканирование полное.

*Альтернатива:* сохранять кэш сканов на диск (JSON/SQLite). Отложено до решения по хранилищу (S2); с памятью первый запуск на сотнях архивов — секунды (читается только центральный каталог и `meta.json`).

### D6. Параллельность и потоки UI (явно)

- `Source.Scan` защищён мьютексом: параллельный вызов не запускает второй обход, а возвращает `ErrScanInProgress`; UI дополнительно блокирует кнопку.
- Сканирование — в горутине экрана; по завершении результат применяется через `fyne.Do` (обновление данных сетки, счётчика, toast).
- Список галерей в `Source` — неизменяемый срез, заменяемый целиком под `sync.RWMutex`; `Get` и `OpenPage` читают под `RLock`.
- Миниатюры: пул из `min(4, NumCPU)` воркеров, очередь запросов; результат применяется через `fyne.Do`. Карточка хранит «ожидаемый ключ»; если к моменту готовности миниатюры карточка переиспользована под другую галерею, результат не применяется (сценарий «Переиспользование карточки»).
- Повторные запросы одной и той же миниатюры, пока она декодируется, объединяются (singleflight на map+chan).

### D7. Миниатюры

- Декодирование `image.Decode` с зарегистрированными `image/jpeg`, `image/png`, `image/gif`, `golang.org/x/image/webp`.
- Уменьшение до большей стороны **320 px** (спецификация требует ≤ 512) через `golang.org/x/image/draw.ApproxBiLinear` — быстро, качество достаточно для карточки 160 px (с запасом на HiDPI).
- Кэш: LRU на 300 записей `*image.NRGBA`. Миниатюра 320×450×4 Б ≈ 0,6 МБ → максимум ≈ 170 МБ, на практике меньше (большинство обложек уже). При 512 px было бы ≈ 440 МБ — неприемлемо для телефона.
- Ключ кэша: `key + modTime` — изменённый архив получает новую обложку.

### D8. Сетка

`widget.GridWrap` (виртуализированная, Fyne ≥ 2.4): `CreateItem` создаёт карточку (`canvas.Image` с `ImageFillContain` фиксированного размера + `widget.Label` с `Truncation`/2 строки), `UpdateItem` запрашивает миниатюру. Размер ячейки: 160×260 на ПК, 150×250 на мобильных — GridWrap сам подбирает число колонок. Нажатие — через `OnSelected`, после показа toast выделение снимается (`UnselectAll`).

*Альтернатива:* `container.NewGridWrap` со всеми карточками. Отклонено — создаёт объекты для всех галерей сразу.

### D9. Автосканирование

- При запуске — после показа окна (`Lifecycle().SetOnStarted`).
- При возврате на передний план — `Lifecycle().SetOnEnteredForeground`. На ПК это срабатывает при фокусе окна; благодаря D5 повторный скан неизменённой папки почти бесплатен (только `stat` файлов). Дополнительно — не чаще раза в 2 секунды.

### D10. Wire-up

`app.Services` получает `Library *library.Source` и `Thumbs *thumbs.Cache`. `Source` создаётся с папкой библиотеки и индексом. Если папка недоступна (`LibraryErr`), `Scan` возвращает ошибку, экран показывает пустое состояние и toast.

## Risks / Trade-offs

- [Память на Android при больших обложках] → декодирование полного JPEG временно занимает ширину×высоту×4 байт (скан 2000×3000 ≈ 24 МБ); ограничено числом воркеров (≤ 4 одновременно) → максимум ~100 МБ пика. При проблемах — уменьшить воркеров до 2 на мобильных.
- [Файлы, скопированные по MTP, могут иметь права, недоступные приложению] → ошибка чтения попадает в список ошибок архивов и toast; проверить на реальном устройстве.
- [Архив копируется в момент сканирования (неполный файл)] → zip не откроется → ошибка; при следующем скане (изменились size/mtime) разберётся заново.
- [`OnEnteredForeground` на ПК срабатывает часто] → троттлинг 2 с + дешёвый инкрементальный скан.
- [Сортировка по mtime: копирование может сохранять исходное время файла] → «недавно добавленные» означает «недавно изменённые»; уточнится, когда появится хранилище с датой добавления.

## Open Questions

- Нужен ли дисковый кэш миниатюр, если первый запуск на реальной библиотеке окажется медленным — решить по результатам проверки на телефоне.

## Implementation notes (2026-09-24)

- **Производительность (Windows, 5.4):** 300 архивов × 20 страниц JPEG 1200×1700 (480 МБ): первое сканирование — 25 мс (файлы в кэше ОС; холодный диск не измерялся), повторное — только `stat`. Быстрая прокрутка сетки без зависаний, обложки подгружаются по мере появления; рабочий набор процесса ≈ 256 МБ.
- **Android (эмулятор API 35, 5.3):** приложение свёрнуто → `adb push` трёх архивов (включая битый) → возврат: карточки появляются без «Обновить» (`OnEnteredForeground`), в логе 2 галереи и 1 ошибка, скан 3 мс. Реальное устройство и копирование по MTP не проверялись.
- **Отклонения от спецификации:**
  - toast об ошибках показывается только для ошибок, найденных в текущем скане (`NewErrors`). Иначе известный битый архив вызывал бы toast при каждом возврате в приложение. Полный список (`Errors`) доступен в результате скана и в логе.
  - Мобильная карточка уменьшена до 128×181, чтобы на телефоне шириной ~430 dp помещались 3 колонки (со 140 px — только 2).
- **Подтверждён риск D-mtime:** `adb push` (и, вероятно, часть способов копирования) сохраняет исходное время файла, поэтому «новый» архив может оказаться не первым. Решается датой добавления в хранилище (изменение `search`/хранилище).
- Время скана пишется в лог: `библиотека: N галерей, новых/изменённых M, ошибок K, за X`.
