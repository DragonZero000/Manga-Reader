## Context

Движок поиска уже сортирует: `search.Query.Sort` (`Field`, `Desc`), `Sortable` в таблице `fields`, `sortColumns` в `catalog/index.go` и `sortDocs` в `search/memindex.go`. UI всегда использует `DefaultSort` (добавлено, убывание). Библиотека показывает результат скана, отсортированный `sortGalleries` по времени изменения. Поиск показывает последнюю выдачу; в UI `Limit` не задаётся, поэтому выдача полная. Настройки хранятся строками (`storage.Settings`).

## Goals / Non-Goals

**Goals:**
- Выбор поля и направления на вкладках «Библиотека» и «Поиск» без обращения к индексу.
- Один порядок и в SQL, и в памяти, без расхождений.
- Глобальная стартовая сортировка в настройках, независимое состояние вкладок в памяти.

**Non-Goals:**
- Изменения движка, синтаксиса запросов, ранжирования.
- Сортировка по «Избранному» и случайный порядок.
- Сохранение сортировки вкладок между запусками.

## Decisions

1. **Функция `search.SortGalleries(gs []model.Gallery, s Sort)`** в пакете `search`, стабильная, на месте. Она использует тот же компаратор, что и `memindex.sortDocs` (его выносим в общую функцию по `*model.Gallery`), поэтому порядок совпадает с движком. Пустое значение (нулевая дата, 0 страниц) наименьшее, отсюда «в начало при возрастании, в конец при убывании». Вторичный порядок: ключ галереи в натуральном порядке, как в SQL (`d.key COLLATE NATSORT`). Альтернатива (отдельная копия в UI) отвергнута: порядок разъедется с движком.
2. **Сортировка локальная.** Вкладка хранит полученный список и при смене сортировки пересортировывает его и обновляет сетку. Альтернатива (новый запрос с `Query.Sort`) отвергнута: нужна задержка и отмена запросов, а в Библиотеке запроса нет вообще. Допущение: `Limit` остаётся 0. Если появится лимит, нужен повторный запрос.
3. **Поля** берутся из `search.fields` с `Sortable`, ограниченные списком UI: название, страницы, размер, добавлено, загружено (в UI подписано «Дата выпуска»). Подпись «Дата выпуска» задаётся в i18n, а не в `FieldInfo.Label`, чтобы не менять синтаксис поиска. `Uploaded` уже заполняется из `meta.json`, а при его отсутствии из `ComicInfo.xml`.
4. **Состояние.** Тип `SortState{Sort, Custom bool}` на вкладку. Стартовое значение читается из настроек (`ui.sort.field`, `ui.sort.desc`) при создании вкладки; при изменении настройки обновляются вкладки с `Custom == false`. Ручной выбор ставит `Custom = true` и в настройки не пишется.
5. **Направление по умолчанию при смене поля:** название по возрастанию, остальные поля по убыванию. Повторный выбор текущего поля инвертирует направление.
6. **Контрол** один виджет-кнопка с меню (Fyne `PopUpMenu`) одинаковый на обеих вкладках. Расположение: ПК — в строке со счётчиком, телефон — отдельная строка под панелью Библиотеки (проверка на эмуляторе показала, что в одной строке с «Браузер» и «Обновить» кнопка сжимается), в Поиске — справа в строке статуса. Подсвечен, когда сортировка вкладки отличается от стартовой. Пункт «По умолчанию» сбрасывает состояние.
7. **Прокрутка** сетки после смены сортировки сбрасывается в начало.

## Risks / Trade-offs

- [Сортировка по названию в памяти может отличаться от SQL `title_sort`] → порядок в UI всегда берётся из `SortGalleries`; тест сверяет оба пути на тестовых данных и фиксирует различия.
- [Пересортировка больших списков на UI-потоке] → `SortGalleries` на сотнях–тысячах записей занимает миллисекунды; при замедлении выносим в горутину с применением через `fyne.Do`.
- [Контрол не помещается на узкой мобильной раскладке] → проверка на эмуляторе, короткие подписи.
- [Вторичный порядок по ключу, а не по названию] → совпадает с движком; записи с равным значением идут в порядке имён файлов.
