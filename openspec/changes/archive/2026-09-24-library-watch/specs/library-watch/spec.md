## ADDED Requirements

### Requirement: Наблюдение за папкой на ПК
На ПК приложение SHALL наблюдать за папкой библиотеки и всеми её вложенными папками, включая папки, созданные после запуска. Создание, изменение, переименование и удаление файла или папки MUST приводить к фоновому пересканированию библиотеки без действий пользователя. Результат MUST применяться к виджетам через `fyne.Do`. Если наблюдение запустить не удалось, приложение MUST продолжить работу со сканированием по событиям жизненного цикла и по кнопке и записать причину в лог.

#### Scenario: Файл скопирован в папку
- **WHEN** приложение открыто, и пользователь копирует `new.zip` в папку библиотеки
- **THEN** в течение нескольких секунд галерея `new.zip` появляется в библиотеке без нажатия «Обновить»

#### Scenario: Новая вложенная папка
- **WHEN** пользователь создаёт папку `series` в папке библиотеки, а затем копирует в неё `vol1.zip`
- **THEN** галерея `series/vol1.zip` появляется без нажатия «Обновить»

#### Scenario: Файл удалён
- **WHEN** пользователь удаляет `old.zip` из папки
- **THEN** галерея `old.zip` исчезает из библиотеки без нажатия «Обновить»

#### Scenario: Наблюдение недоступно
- **WHEN** системе не удалось запустить наблюдение за папкой
- **THEN** приложение работает, ручное обновление и сканирование при запуске работают, причина записана в лог

### Requirement: Проверка файла после окончания загрузки
Когда браузер завершает загрузку (итоговый файл появляется, а `<имя>.part` исчезает), приложение MUST пересканировать папку и тем самым проверить файл: корректный архив — появляется в библиотеке, невалидный — появляется в списке ошибок и увеличивает число на вкладке «Ошибки». Изменения, касающиеся только файлов `*.part`, MUST NOT запускать пересканирование.

#### Scenario: Скачан корректный архив
- **WHEN** загрузка `g-1.zip` завершилась и файл — корректный архив
- **THEN** галерея `g-1.zip` появляется в библиотеке

#### Scenario: Скачан невалидный файл
- **WHEN** загрузка `g-2.zip` завершилась, а содержимое — HTML-страница
- **THEN** появляется toast о новой ошибке, число на вкладке «Ошибки» увеличивается на 1, файл остаётся в папке

#### Scenario: Идёт загрузка
- **WHEN** браузер в течение минуты дописывает `g-3.zip.part`
- **THEN** пересканирование из-за записи в `g-3.zip.part` не запускается

### Requirement: Объединение событий
Пересканирование MUST запускаться, когда в папке 1 секунду не было событий, но не позже чем через 10 секунд после первого события серии. Если события пришли во время сканирования, MUST выполняться ровно одно дополнительное сканирование после его завершения.

#### Scenario: Копирование многих файлов
- **WHEN** пользователь копирует в папку 50 архивов за 3 секунды
- **THEN** выполняется одно пересканирование после окончания копирования (и не более одного дополнительного при событиях во время скана)

#### Scenario: Событие во время сканирования
- **WHEN** во время сканирования в папку добавлен `late.zip`
- **THEN** после окончания текущего сканирования запускается ещё одно, и `late.zip` появляется в библиотеке

### Requirement: Временно занятый файл
Если файл не удалось открыть, потому что он занят другим процессом (нарушение совместного доступа на Windows), сканер MUST NOT добавлять его в ошибки и MUST NOT кэшировать результат; приложение MUST повторить сканирование через 2 секунды, не более 5 раз подряд. Если файл остаётся занятым после всех повторов, он MUST попасть в ошибки с причиной «Файл занят другой программой».

#### Scenario: Антивирус проверяет файл
- **WHEN** сразу после загрузки `g-4.zip` занят антивирусом 3 секунды
- **THEN** ошибка не появляется, а после освобождения файла галерея `g-4.zip` появляется в библиотеке

#### Scenario: Файл занят долго
- **WHEN** `locked.zip` остаётся занятым дольше всех повторов
- **THEN** в ошибках есть запись `locked.zip` с причиной «Файл занят другой программой»
