## Context

`screens.Library.Refresh()` запускает `Source.Scan` в горутине и применяет результат через `fyne.Do`; повторный вызов во время скана игнорируется (`l.scanning`), `Source.Scan` при занятости возвращает `ErrScanInProgress`. `AutoRefresh` ограничивает частоту (2 с) для событий жизненного цикла.

`fsnotify` v1.9 уже есть в `go.sum` (косвенно через Fyne). На Windows он работает через `ReadDirectoryChangesW`; рекурсивного режима в публичном API нет — папки добавляются по одной.

Firefox при загрузке создаёт пустой `name.zip`, пишет в `name.zip.part`, в конце удаляет `name.zip` и переименовывает `.part` → `name.zip` (пропуск этих состояний — в `library-errors`).

Сеть, API и rate limiting не используются. Единственное ограничение частоты — объединение событий (D2).

## Goals / Non-Goals

**Goals:** новые файлы и ошибки видны через ~1–2 с после окончания загрузки; не сканировать на каждую запись в `.part`; не терять события; не превращать временно занятый файл в ошибку.

**Non-Goals:** Android, уведомления ОС (см. proposal).

## Decisions

### D1. `library.Watcher` (без виджетов)

```go
type Watcher struct { /* fsnotify.Watcher, root, debounce, maxWait */ }
func NewWatcher(root string) (*Watcher, error)
func (w *Watcher) Run(ctx context.Context, onChange func())   // блокирует до ctx.Done
```

- При старте обходит `root` и добавляет каждую папку (кроме скрытых). На `Create` папки — добавляет её и её подпапки, затем вызывает серию (в новой папке уже могли появиться файлы).
- Ошибки `fsnotify` (переполнение буфера и т.п.) → лог и вызов `onChange` (полный скан всё исправит).
- `onChange` вызывается из горутины наблюдателя; UI-код оборачивает его в `fyne.Do`.

*Альтернатива:* периодический опрос папки раз в N секунд — отклонено: либо задержка, либо лишние обходы большой библиотеки; fsnotify уже в зависимостях.

### D2. Объединение событий

```
событие ─▶ фильтр: только *.part и op=Write/Create? ─да─▶ игнор
             │нет
             ▼
         таймер тишины 1 с (перезапускается)  +  жёсткий предел 10 с от первого события
             │
             ▼ onChange()
```

Rename `.part` → итоговый файл в fsnotify приходит как `Rename` старого имени + `Create` нового; `Create` итогового файла проходит фильтр. `Remove` `.part` тоже проходит — это безопасно (один лишний повод, серия объединится).

### D3. «Сканировать ещё раз» в экране библиотеки

`Library.RequestScan()` (UI-поток): если идёт скан — `l.pending = true`; иначе `Refresh()`. В `applyScan`: если `pending` — сбросить и вызвать `Refresh()` снова. Так событие во время скана не теряется, и одновременно выполняется не больше одного скана. `AutoRefresh` не меняется.

### D4. Занятый файл

`storage.FS.Open` на Windows возвращает `ERROR_SHARING_VIOLATION` (32) или `ERROR_LOCK_VIOLATION` (33). Новый `storage.ErrBusy` оборачивает эти коды (проверка через `errors.As` на `syscall.Errno` в `fs_windows.go`; на других ОС — не бывает). Сканер:

- `ErrBusy` → запись не кэшируется, не попадает в `Errors`, `ScanResult.Busy++` (или список путей);
- экран: `Busy > 0` → повтор через 2 с (`time.AfterFunc` → `fyne.Do(RequestScan)`), счётчик попыток; после 5-й попытки `Scanner` получает флаг «занятые — в ошибки» с причиной «Файл занят другой программой», счётчик сбрасывается при скане без занятых файлов.

*Альтернатива:* повторять открытие внутри сканера со `sleep` — отклонено: держит `scanMu` и блокирует ручное обновление.

### D5. Жизненный цикл

`app_desktop.go` создаёт `Watcher` после `EnsureDir`; ошибка — лог, `Services.Watcher = nil`. Оболочка в `SetOnStarted` запускает `go w.Run(ctx, func(){ fyne.Do(library.RequestScan) })`; `ctx` отменяется в `SetOnStopped`. На Android `Watcher` всегда `nil`.

## Risks / Trade-offs

- [Переполнение буфера `ReadDirectoryChangesW` при массовом копировании] → fsnotify сообщает ошибку → полный скан; скан инкрементальный, повторно разбираются только изменённые файлы.
- [Сетевые диски и флешки FAT могут не присылать события] → остаётся кнопка «Обновить» и скан при возврате на передний план.
- [Watcher держит дескрипторы папок — папку нельзя переименовать/удалить в Проводнике, пока приложение открыто] → поведение Windows для любой наблюдаемой папки; ограничиваемся папками внутри `manga`.
- [Скан раз в 10 с при непрерывных событиях (долгое копирование)] → скан инкрементальный и дешёвый для неизменённых файлов.
