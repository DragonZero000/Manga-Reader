## Context

`library.Scanner` обходит `storage.Storage.Walk`, отбрасывает всё, кроме `.zip`, и кэширует результат разбора по относительному пути вместе с размером и временем изменения (`cacheEntry`), включая ошибки. `ScanResult.Errors` уже содержит все нечитаемые архивы, `NewErrors` — разобранные в этом скане. UI получает результат в `screens.Library.applyScan` (через `fyne.Do`) и показывает toast по `NewErrors`.

Хранение: `storage.Settings` (строковые ключи) — `settings.json` в папке приложения на ПК, `fyne.Preferences` на Android.

Ограничения Fyne 2.8: у `container.TabItem` нет бейджа; иконка вкладки — любой `fyne.Resource`, заголовок и иконку можно менять с последующим `AppTabs.Refresh()`.

Сеть, API и rate limiting в этом изменении не используются.

## Goals / Non-Goals

**Goals:** каждый файл папки либо галерея, либо ошибка, либо (временно) незавершённая загрузка; список ошибок без дублей; статус просмотра, переживающий перезапуск; число на вкладке.

**Non-Goals:** действия с файлами из вкладки, новые форматы, наблюдение за папкой (см. proposal).

## Decisions

### D1. Сканер проверяет все файлы

```
Walk ─▶ скрытый? ─да─▶ пропуск
          │нет
          ▼
        *.part или (size==0 и есть <имя>.part)? ─да─▶ пропуск (идёт загрузка)
          │нет
          ▼
        кэш совпал (size, modTime)? ─да─▶ прежний результат
          │нет
          ▼
        size==0 ─▶ ErrEmpty
        .zip    ─▶ ReadArchive ─ ErrNotZip ─▶ sniff (уточнить тип, если распознан)
        прочее  ─▶ sniff ─▶ ErrUnsupported{Kind}
```

Проверка «есть `<имя>.part`» требует знать соседей: `Scan` сначала собирает все `Entry` (Walk уже перечисляет всё), строит множество путей, затем обрабатывает. Память — O(число файлов), это приемлемо.

Незавершённая загрузка не попадает в кэш: при следующем скане файл разбирается заново.

*Альтернатива:* игнорировать файлы моложе N секунд — отклонено: зависит от часов и скорости загрузки, `.part` — точный признак Firefox (и Chrome использует `.crdownload`, но браузер у нас Firefox).

### D2. Классификация по сигнатуре

`library/sniff.go`: читает первые 512 байт через `File.ReadAt`, `http.DetectContentType` + собственные сигнатуры, которых нет в stdlib (`Rar!\x1a\x07`, `7z\xbc\xaf\x27\x1c`, `ftyp` в MP4/MOV, Matroska/WebM `\x1a\x45\xdf\xa3`). Результат — `Kind` (Image, Video, Audio, HTML, PDF, OtherArchive, Text, Unknown).

Ошибки — типизированные, чтобы UI и тесты не разбирали строки:

```go
var ErrEmpty = errors.New("пустой файл")
type UnsupportedError struct{ Kind Kind }   // Error() — текст причины из спеки
```

`ErrNotZip` и `ErrNoImages` остаются. Для `.zip`, у которого `zip.NewReader` не сработал, вызывается sniff: распознанный тип даёт `UnsupportedError`, иначе — `ErrNotZip`.

### D3. `ScanError` с размером и временем

`ScanError{RelPath, Size, ModTime, Err}` — данные уже есть в `cacheEntry`. Это ключ идентичности записи для статуса просмотра.

### D4. Пакет `internal/problems` (без виджетов)

```go
type Item struct {
    RelPath string; Size int64; ModTime time.Time; Reason string; Seen bool
}
type Tracker struct { /* mu, items, seen map[string]bool, settings */ }

func New(s storage.Settings) *Tracker          // читает errors.state
func (t *Tracker) Sync(errs []library.ScanError) (added int) // заменяет список, возвращает число новых (неизвестных) записей
func (t *Tracker) Items() []Item               // отсортированы: ModTime desc, путь natural
func (t *Tracker) Unseen() int
func (t *Tracker) MarkAllSeen()
```

- Ключ: `relPath + "\x00" + size + "\x00" + modTime.UnixNano()`.
- `Sync` заменяет список целиком (список = состояние папки → нет дублей, исчезнувшие файлы уходят сами) и обрезает состояние до ключей текущего списка — настройка не растёт.
- Состояние хранится одной настройкой `errors.state` — JSON-объект «ключ → просмотрена» для **всех** известных записей, а не только просмотренных: иначе после перезапуска непросмотренные старые ошибки снова считались бы новыми и давали toast. Запись только при изменении.
- Потокобезопасен (mutex): `Sync` вызывается из UI-потока после скана, но тесты гоняют под `-race`.

*Альтернатива:* отдельный `errors.json` — отклонено: на Android пришлось бы делать второе хранилище; `storage.Settings` уже работает на обеих платформах, а на ПК это тот же портативный `settings.json`.

*Альтернатива:* хранить весь список ошибок — отклонено: он полностью восстанавливается сканом, храним только то, что скан восстановить не может (статус).

### D5. Поток данных и потоки выполнения

```
goroutine: Source.Scan ─▶ fyne.Do ─▶ Library.applyScan(res)
                                        │
                                        ├─ Tracker.Sync(res.Errors) → added
                                        ├─ added>0 → toast «Новые ошибки: N — см. вкладку «Ошибки»»
                                        └─ OnScanned → Shell: errors.Refresh(), обновить иконку вкладки
```

Всё, что трогает виджеты, — в UI-потоке (`fyne.Do` уже есть в `Refresh`). Если вкладка «Ошибки» выбрана в момент `Sync`, оболочка сразу вызывает `MarkAllSeen` (требование «появившиеся при открытой вкладке — просмотрены»).

Toast считается по `added` из `Tracker.Sync` (записи, неизвестные по сохранённому состоянию), а не по `NewErrors`: при перезапуске сканер разбирает все файлы заново и `NewErrors` содержит все старые ошибки — toast повторялся бы при каждом запуске.

### D6. Иконка с числом

`ui/badge.go`: `BadgeIcon(base fyne.Resource, n int) fyne.Resource` — SVG, собранный строкой: иконка `theme.ErrorIcon()` (её SVG через `Content()`) + красный кружок с числом в правом верхнем углу; «99+» при n>99; при n==0 — исходная иконка. Ресурсы кэшируются по n. Цвет иконки задаётся через `theme.NewThemedResource` для базы, кружок — фиксированный цвет `theme.ColorNameError`, вычисленный при создании.

*Альтернатива:* число в заголовке «Ошибки (3)» — проще, но на мобильных нижних вкладках заголовок обрезается; иконка с числом привычнее (как в Telegram).

### D7. Экран `screens.Errors`

`widget.List`: строка — маркер (кружок для непросмотренных), путь (жирный, если не просмотрено), причина, время (`details.FormatDate`-подобный формат). Пустое состояние «Ошибок нет». Список обновляется методом `Refresh()` из оболочки.

## Risks / Trade-offs

- [Посторонние файлы в папке пользователя (обложки, заметки) теперь станут ошибками] → это требование; путь из вкладки явно показывает, что лежит в папке. Скрытые файлы и папки на `.` по-прежнему игнорируются — можно убрать лишнее туда.
- [sniff читает 512 байт каждого нового файла] → только для изменённых файлов; кэш сканера сохраняет результат.
- [Android SAF: открытие каждого неизвестного файла медленнее] → один раз на файл благодаря кэшу; в папке манги посторонних файлов обычно немного.
- [Время изменения на FAT/SAF может округляться] → ключ стабилен между сканами на той же ФС; при смене папки статусы просто сбрасываются.
- [SVG бейджа может неверно отрисоваться в oksvg] → тест рендера иконки в `test` драйвере; запасной вариант — число в заголовке вкладки.

## Migration Plan

Миграция данных не нужна. После обновления при первом скане все существующие посторонние файлы появятся как непросмотренные ошибки — однократно.
