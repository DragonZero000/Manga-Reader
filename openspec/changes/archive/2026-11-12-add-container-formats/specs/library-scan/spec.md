## MODIFIED Requirements

### Requirement: Обнаружение архивов
Сканер SHALL проверять все файлы в папке библиотеки и её вложенных папках. Тип файла MUST определяться по содержимому, а не по расширению: файл, являющийся zip-архивом, MUST разбираться как архив при любом расширении (`.zip`, `.cbz`, `.cbt` и др., без учёта регистра); остальные файлы MUST попадать в список ошибок как неподдерживаемые, причём тип в причине определяется по содержимому. Файлы и папки, имя которых начинается с `.`, MUST пропускаться. Ключ галереи MUST строиться из пути архива относительно папки библиотеки с прямыми слешами (`local:sub/example.zip`).

#### Scenario: Архив в корне папки
- **WHEN** в папке библиотеки лежит `example.zip`
- **THEN** сканер возвращает одну галерею с ключом `local:example.zip`

#### Scenario: Архив во вложенной папке
- **WHEN** архив лежит по пути `<библиотека>/series/vol1.ZIP`
- **THEN** сканер возвращает галерею с ключом `local:series/vol1.ZIP`

#### Scenario: Архив с расширением .cbz
- **WHEN** в папке лежит `testdata/cbz-example.cbz`
- **THEN** сканер возвращает галерею с ключом `local:cbz-example.cbz`, а в ошибках нет записи для этого файла

#### Scenario: Zip с произвольным расширением
- **WHEN** в папке лежит корректный zip-архив с изображениями под именем `book.dat`
- **THEN** сканер возвращает галерею с ключом `local:book.dat`

#### Scenario: Скрытые файлы
- **WHEN** в папке лежат `.hidden.zip` и папка `.trash` с архивом внутри
- **THEN** ни один из них не попадает ни в галереи, ни в ошибки

#### Scenario: Посторонние файлы
- **WHEN** в папке лежит `notes.txt`
- **THEN** галерей не создаётся, а в ошибках есть запись `notes.txt` с причиной «Текстовый файл — поддерживаются только zip-архивы»

#### Scenario: Расширение .zip у не-архива
- **WHEN** в папке лежит файл `fake.zip`, содержимое которого — картинка PNG
- **THEN** в ошибках есть запись `fake.zip` с причиной, указывающей на изображение

#### Scenario: Пустая папка
- **WHEN** папка библиотеки пуста
- **THEN** сканер возвращает пустой список без ошибок

### Requirement: Перепроверка после изменения правил разбора
Каталог библиотеки SHALL хранить ревизию правил разбора архивов, с которой получены сохранённые результаты (отсутствие значения — ревизия 0). Если сохранённая ревизия меньше текущей ревизии приложения, сканирование MUST заново разобрать файлы, сохранённый результат которых может измениться по новым правилам, даже если их размер и время изменения не менялись. Для текущей ревизии это:
- галереи, у которых есть страница с `\` в имени в UTF-8 или с символом замены U+FFFD (имя не в UTF-8, искажённое при прежнем сохранении в каталог), или повторяющиеся имена страниц;
- файлы с ошибкой «нет изображений»;
- файлы с ошибкой неподдерживаемого формата, у которых расширение не `.zip` (например `.cbz`, ранее отклонённые только из-за расширения).

Остальные неизменённые файлы MUST NOT открываться. До перепроверки галереи и ошибки из каталога MUST показываться как прежде. Текущая ревизия MUST сохраняться в каталоге только после успешного сканирования, в котором разобраны все файлы, ожидающие перепроверки; после этого перепроверка MUST NOT повторяться. Если сканирование не завершилось или файл при перепроверке занят другим процессом, перепроверка MUST повториться при следующем сканировании (в том числе после перезапуска). Из-за смены ревизии каталог MUST NOT пересоздаваться и библиотека MUST NOT пересканироваться целиком.

#### Scenario: Перепроверяются только затронутые файлы
- **WHEN** каталог ревизии 0 содержит неизменённые `a.zip` (страницы `ch1\001.jpg`, `ch1\002.jpg`) и `b.zip` (страницы `1.jpg`, `2.jpg`), и библиотека сканируется
- **THEN** открывается только `a.zip`, `b.zip` не открывается

#### Scenario: Ошибка «нет изображений» исправляется
- **WHEN** каталог ревизии 0 хранит для неизменённого `dot.zip` (записи `./001.jpg`, `./002.jpg`) ошибку «нет изображений», и библиотека сканируется
- **THEN** `dot.zip` становится галереей с 2 страницами и исчезает из ошибок

#### Scenario: Искажённые имена восстанавливаются
- **WHEN** каталог ревизии 0 хранит галерею неизменённого `sjis.zip`, имена страниц которой содержат U+FFFD, и библиотека сканируется
- **THEN** `sjis.zip` разбирается заново, и все его страницы открываются

#### Scenario: Ранее отклонённый .cbz
- **WHEN** каталог предыдущей ревизии хранит для неизменённого `old.cbz` ошибку «zip-архив с расширением .cbz», и библиотека сканируется
- **THEN** `old.cbz` становится галереей и исчезает из ошибок, а неизменённый `other.jpg` с ошибкой «изображение» не открывается

#### Scenario: Ревизия сохранена
- **WHEN** перепроверка завершилась, сканер создан заново над тем же каталогом, и папка сканируется снова без изменений файлов
- **THEN** ни один архив не открывается

#### Scenario: Файл занят при перепроверке
- **WHEN** при сканировании с перепроверкой затронутый файл занят другим процессом (Windows)
- **THEN** ревизия не сохраняется, и файл перепроверяется при следующем сканировании

### Requirement: Определение типа неподдерживаемого файла
Для файла, который не является корректной галереей, сканер SHALL определить тип по первым байтам содержимого (не по расширению) и сформировать причину с названием типа: «Изображение», «Видео», «Аудио», «Веб-страница (HTML)», «PDF», «Текстовый файл»; если тип не распознан — «Неподдерживаемый формат». Для файлов, распознанных как изображение, видео, аудио, PDF или текст, к причине MUST добавляться « — поддерживаются только архивы zip, RAR и 7z». Для веб-страницы причина MUST быть «Веб-страница (HTML) вместо архива — вероятно, сайт вернул страницу с ошибкой или проверкой». Для файла, распознанного как zip, RAR или 7z, но не открывающегося как архив, а также для файла с расширением `.zip` с нераспознанным содержимым причина MUST быть «не архив или архив повреждён». Для архива, защищённого паролем, причина MUST быть «архив защищён паролем».

#### Scenario: Картинка с расширением zip
- **WHEN** в папке лежит `g-2.zip`, содержимое которого — JPEG
- **THEN** в ошибках есть запись `g-2.zip` с причиной «Изображение — поддерживаются только архивы zip, RAR и 7z»

#### Scenario: Скачалась веб-страница
- **WHEN** в папке лежит `g-3.zip`, содержимое которого начинается с `<!DOCTYPE html>`
- **THEN** причина ошибки начинается с «Веб-страница (HTML) вместо архива»

#### Scenario: Видео
- **WHEN** в папке лежит `clip.mp4` с содержимым MP4
- **THEN** причина ошибки — «Видео — поддерживаются только архивы zip, RAR и 7z»

#### Scenario: Обрезанный zip
- **WHEN** `part.zip` — первые 100 КБ корректного архива
- **THEN** причина ошибки — «не архив или архив повреждён»

#### Scenario: Архив с паролем
- **WHEN** в папке лежит `password.rar` или `password.7z` с зашифрованным содержимым
- **THEN** причина ошибки — «архив защищён паролем»

## ADDED Requirements

### Requirement: Архивы RAR и 7z
Сканер SHALL разбирать как архивы файлы RAR (`.rar`, `.cbr`) и 7z (`.7z`, `.cb7`), определённые по содержимому, по тем же правилам, что zip: те же расширения страниц, служебные файлы, натуральный порядок, `meta.json` и `ComicInfo.xml`, отпечаток страниц. Страницы solid-архивов RAR MUST читаться через временный кэш ограниченного размера, в который архив распаковывается целиком при первом чтении страницы; кэш MUST очищаться при выходе из приложения и при следующем запуске; архив, не помещающийся в кэш, MUST давать ошибку чтения страницы. Несолидные архивы RAR и все архивы 7z MUST читаться без распаковки в кэш. Архивы с паролем MUST попадать в ошибки с понятной причиной.

#### Scenario: Несолидный RAR
- **WHEN** в папке лежит `book.cbr` (RAR5, не solid) с изображениями `1.jpg`, `2.jpg`
- **THEN** сканер возвращает галерею с ключом `local:book.cbr` и двумя страницами

#### Scenario: Solid-архив
- **WHEN** в папке лежит solid-архив RAR с 30 страницами и читается страница 20
- **THEN** страница возвращается, архив распакован в кэш, а кэш не превышает заданный лимит

#### Scenario: Архив с паролем
- **WHEN** в папке лежит защищённый паролем RAR
- **THEN** он попадает в ошибки с причиной о защите паролем
