## Context

Есть модель запроса (`search.Query`, `Filter`, `Field`, `Op`, `Value`, 9 полей, `Validate`) и интерфейс `Index` (`Upsert`, `Remove`, `Search`, `SuggestTags`) с заглушкой `NopIndex`. `library.Source.Scan` уже вызывает `Index.Upsert/Remove` для добавленных, изменённых и удалённых галерей. Экран «Поиск» — поле ввода и надпись со статусом. Сетка карточек с миниатюрами реализована внутри экрана библиотеки. Страница произведения показывает теги неинтерактивными «чипами».

Решение по хранилищу индекса откладывалось до спайка S2 (SQLite на Android): на эмуляторе x86_64 `modernc.org/sqlite` падает (seccomp), на arm64 не проверено. Сеть, API и rate limiting в этом изменении не используются.

## Goals / Non-Goals

**Goals:** рабочий поиск по части слова во всех полях и по точным условиям; понятный синтаксис с сообщениями об ошибках; одинаковая сетка результатов и библиотеки; переход «тег → поиск».

**Non-Goals:** SQLite, автодополнение, исключение слов, выбор сортировки, нечёткий поиск (см. proposal).

## Decisions

### D1. Индекс в памяти, без SQLite

`search.MemIndex`: `map[model.Key]*doc` под `sync.RWMutex`. `doc` хранит галерею и заранее подготовленные строки для поиска:

```
doc {
  g        model.Gallery
  hay      []string   // нижний регистр: title, alt, "тип:имя" и имя каждого тега,
                      // scanlator, Key.ID, ExternalID (строкой)
  tags     map[model.Tag]bool   // нормализованные, для точного совпадения
  names    map[string]bool      // имена тегов без типа (фильтр «тег любого типа»)
}
```

Поиск — линейный проход по документам с проверкой всех слов и фильтров. Для библиотек в тысячи произведений это единицы миллисекунд; индекс не хранится на диске и строится из сканирования при запуске (сканирование и так читает все `meta.json`).

*Альтернатива:* SQLite + FTS5. Отложено: не подтверждена работа на Android, а объём данных не требует СУБД. Интерфейс `Index` позволяет заменить реализацию без изменения UI.

*Альтернатива:* инвертированный индекс по n-граммам для подстрок. Отложено до реальной потребности — линейный поиск проще и достаточно быстр.

### D2. Модель запроса: слова отдельно от `Text`

В `Query` добавляется `Terms []string` — разобранные слова и фразы в нижнем регистре. `Text` остаётся исходной строкой (для отображения). Индекс использует только `Terms`: запасной разбор `Text` на слова убран при реализации — он превращал условия вроде `pages:2` в слова, если слов в запросе не было. Код, собирающий запрос без парсера, заполняет `Terms` сам. Тег с пустым типом в фильтре означает «любой тип» — `Validate` больше не подставляет тип `tag`.

### D3. Парсер (`search.Parse(s string) (Query, error)`)

1. Токенизация: пробелы разделяют элементы, двойные кавычки объединяют (в том числе внутри `поле:"..."`), незакрытая кавычка закрывается в конце строки.
2. Элемент: необязательный `-`, затем `имя:значение`, если `имя` (без учёта регистра) — поле парсера; иначе — слово.
3. Поля парсера: `title`, `scanlator` → `FieldTitle`/`FieldScanlator` (`OpContains`); `tag` → тег с пустым типом; `artist`, `group`, `parody`, `character`, `language`, `category` → тег этого типа; `id`, `pages`, `favorites`, `size` → числа; `uploaded`, `added` → даты.
4. Числа: `N` → `OpEq` (для `pages`) или `OpBetween N..N` (для полей без `OpEq` — `favorites`, `size`); `>N`/`<N` → `OpGt`/`OpLt`; `>=N`/`<=N` → `OpGt N-1`/`OpLt N+1`; `N..M` → `OpBetween`. Размер: число с дробной частью (`.` или `,`) и суффиксом `b|k|kb|m|mb|g|gb`, округление до байта.
5. Даты: период `ГГГГ[-ММ[-ДД]]` → [начало, конец]; без оператора → `OpBetween начало..конец`; `>` → `OpGt конец`; `<` → `OpLt начало`; `>=` → `OpGt начало−1нс`; `<=` → `OpLt конец+1нс`; `п1..п2` → `OpBetween начало(п1)..конец(п2)`. `uploaded` — UTC, `added` — `time.Local`.
6. После разбора — `Query.Validate()`; ошибки валидации тоже показываются пользователю.
7. Ошибка — `*ParseError{Token, Reason}`, текст «`<фрагмент>`: <причина>».

Синтаксис только для ввода с клавиатуры; панель фильтров для телефона — позже (она будет строить `Query` напрямую, без строки).

### D4. Правила совпадения (`MemIndex.Search`)

- Слово: `strings.Contains` хотя бы в одной строке `doc.hay`.
- Тег «есть/нет»: при типе — `doc.tags[tag]`, без типа — `doc.names[name]`.
- `title`: подстрока в названии или альтернативном названии; `scanlator`: `OpContains` — подстрока, `OpEq` — равенство (без учёта регистра).
- Числа/даты: значение поля берётся из галереи (`len(Pages)`, `Favorites`, `ExternalID`, `File.Size`, `Uploaded`, `File.ModTime`); нулевое значение не проходит ни один фильтр по этому полю.
- Сортировка: по `Query.Sort` (по умолчанию `added` ↓); при равенстве — ключ в натуральном порядке (как в библиотеке). `Limit/Offset` применяются после сортировки; `total` — до.
- `SuggestTags`: подсчёт по всем документам (при каждом вызове; достаточно для объёмов библиотеки).

### D5. Общая сетка карточек

Из `screens/library.go` выносится `galleryGrid` (`screens/grid.go`): `widget.GridWrap` + `galleryCard` + загрузка миниатюр с защитой от переиспользования карточки, методы `SetItems([]model.Gallery)`, колбэк `onOpen`. Библиотека и поиск используют один компонент (одинаковый вид, общий `thumbs.Cache`).

### D6. Экран «Поиск»

- Поле ввода + строка статуса («Найдено: N» / «Ничего не найдено» / ошибка разбора красным) + область результатов (сетка или справка).
- Дребезг: `time.AfterFunc(300мс)` перезапускается при каждом изменении текста; Enter выполняет сразу. Каждому запуску — номер; результат применяется через `fyne.Do` (подменяемый `do`) только если номер последний.
- Выполнение в горутине: `Parse` → `Index.Search` → `Source.Get` для каждого ключа (пропуская отсутствующие) → `SetItems`.
- Справка — набор надписей с примерами (моноширинный шрифт), показывается при пустом поле вместо сетки.
- `Search.SetQuery(text)` — заполнить поле и выполнить сразу (для перехода «тег → поиск»).
- Повторное выполнение: при выборе вкладки (`AppTabs.OnSelected`) и после сканирования. Для второго — у `Library` появляется колбэк `onScanned`, оболочка связывает его с `Search.Rerun`.

### D7. Тег → поиск

Чипы тегов на странице произведения становятся кнопками (`widget.Button` с `LowImportance`, текст — имя тега). Нажатие вызывает `onTag(group.Type, name)`; `Details` формирует запрос (`тип:"имя"` для известных типов, `tag:"имя"` для остальных) и вызывает колбэк оболочки `searchFor(text)`: закрыть страницу произведения, `Tabs.Select(вкладка «Поиск»)`, `Search.SetQuery(text)`.

### D8. Потоки UI (явно)

Поиск, разбор и сбор галерей — в горутине экрана; применение — через `do` (по умолчанию `fyne.Do`) с проверкой номера запроса. `MemIndex` защищён `RWMutex`: `Upsert/Remove` приходят из горутины сканирования, `Search` — из горутины поиска. Таймер дребезга вызывает запуск через `do`.

## Risks / Trade-offs

- [Индекс строится заново при каждом запуске] → сканирование уже читает все метаданные; для сотен архивов — доли секунды (замер из `local-library`: 300 архивов — 25 мс при прогретом кэше ОС).
- [Линейный поиск на очень больших библиотеках (10⁵)] → вне целевых объёмов; при необходимости — n-граммный индекс или SQLite за тем же интерфейсом.
- [Синтаксис неудобен на телефоне] → справка с примерами и переход «тег → поиск»; панель фильтров — отдельное изменение.
- [Имя поля совпадает с началом слова (`title:` в тексте)] → только известные имена полей и только с двоеточием превращаются в условия; прочее — слово.

## Implementation notes (2026-09-24)

- **Скорость поиска** (`BenchmarkSearch300`, 300 произведений по 6 тегов): слово, совпадающее со всеми, — 0,15 мс (основное время — сортировка); `tag:"tag 1" pages:>10 -artist:"artist 3"` — 0,04 мс; слово без совпадений — 0,02 мс. На ПК с 304 архивами результаты появляются без заметной задержки.
- **Запасной разбор `Text` убран** (см. D2): иначе запрос только из условий (`pages:2`) превращался в слово и ничего не находил.
- **Текст ошибки**: `«фрагмент» — причина`, например `«pages:>lots» — ожидается неотрицательное целое число, получено "lots"`.
- **Известное ограничение Android (Fyne 2.8):** символы, приходящие как события клавиш (физическая/Bluetooth-клавиатура, `adb shell input`), задваиваются в поле ввода (`ppaaggeess`). Ввод с экранной клавиатуры корректен. Это поведение мобильного драйвера Fyne, не кода приложения; приложение от него не защищается.
- **Проверено:** Windows — справка, поиск по слову, фраза, `tag:`, исключение, ошибка разбора с сохранением результатов, «Ничего не найдено», тег → поиск; эмулятор Android 15 — справка, ввод с экранной клавиатуры, результат → страница произведения → «Назад» к результатам, тег → поиск.
