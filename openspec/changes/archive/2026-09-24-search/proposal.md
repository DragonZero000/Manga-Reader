## Why

Экран «Поиск» пока ничего не находит: индекс — заглушка (`NopIndex`), а строка запроса передаётся как есть. Модель запроса по параметрам произведения (`search.Query`, 9 полей) и контракт индекса уже есть — не хватает реализации индекса, разбора строки запроса и выдачи результатов.

## What Changes

- **Индекс в памяти** (`search.MemIndex`), реализующий существующий интерфейс `Index`: заполняется при сканировании библиотеки, выполняет запросы, подсказки тегов. SQLite отложен (спайк S2 на Android не завершён); интерфейс позволяет заменить реализацию позже.
- **Поиск по слову**: каждое слово или фраза в кавычках ищется как часть слова без учёта регистра во всех текстовых полях — основном и альтернативном названии, именах тегов любого типа, сканлейторе, имени файла, ID. Несколько слов — «И»: произведение должно содержать каждое слово (в любых полях). Выдаются все совпавшие произведения.
- **Точные условия в строке запроса**: `поле:значение`, например `pages:>20`, `tag:"tag 1"`, `artist:"artist 1"`, `-tag:"tag 3"`, `language:japanese`, `uploaded:2024`, `uploaded:>2024-06`, `size:>10mb`, `favorites:100..500`, `id:535147`, `title:name`, `scanlator:group`. Можно сочетать со словами: `school pages:>20 -tag:yuri`. Ошибки разбора показываются под полем ввода с указанием проблемного фрагмента.
- **Экран «Поиск»**: поле запроса, поиск по мере ввода (с задержкой) и по Enter, счётчик «Найдено: N», сетка карточек как в библиотеке, нажатие открывает страницу произведения; при пустом запросе — краткая справка по синтаксису.
- **Теги на странице произведения становятся нажимаемыми**: нажатие открывает «Поиск» с запросом по этому тегу (`artist:"artist 1"`).
- Сетка карточек библиотеки выносится в общий компонент для библиотеки и поиска.

## Non-goals

- SQLite и сохранение индекса на диск (индекс строится при каждом запуске из сканирования).
- Автодополнение тегов в поле ввода и панель фильтров для телефона (метод `SuggestTags` реализуется, но UI для него — позже).
- Исключение слов свободного текста (`-слово`); исключение поддерживается только для тегов.
- Сортировка результатов на выбор пользователя: порядок как в библиотеке (недавно изменённые сверху).
- Нечёткий поиск (опечатки), морфология, транслитерация.

## Capabilities

### New Capabilities
- `search-syntax`: синтаксис строки запроса — слова и фразы, условия `поле:значение`, операторы для чисел, дат и размеров, исключение тегов, сообщения об ошибках.
- `search-index`: индекс в памяти — правила совпадения (часть слова во всех полях, точные теги, числа и даты), обновление при сканировании, порядок и подсчёт результатов, подсказки тегов.
- `search-screen`: экран поиска — ввод, выполнение, результаты, пустое состояние и справка, переход к странице произведения.

### Modified Capabilities
- `search-query`: контракт индекса получает рабочую реализацию; фильтр по тегу без типа означает «тег любого типа».
- `gallery-details`: нажатие на тег открывает поиск по этому тегу.

## Impact

- Новый код: `internal/search/memindex.go`, `internal/search/parse.go` (+ тесты); `internal/ui/screens/grid.go` (общая сетка); переработка `internal/ui/screens/search.go`.
- Изменения: `internal/app` (`MemIndex` вместо `NopIndex`), `internal/search/query.go` (тег без типа), `internal/ui/details` (нажимаемые теги), `internal/ui/shell.go` (переход «тег → поиск»: закрыть страницу произведения, открыть вкладку «Поиск» с запросом).
- Зависимости не добавляются.
