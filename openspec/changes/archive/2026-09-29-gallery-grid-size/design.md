## Context

`galleryGrid` использует `widget.GridWrap`. Размер ячейки GridWrap берёт из `MinSize()` шаблонной карточки (`itemMin`), а число колонок — `floor((width + pad) / (itemW + pad))` (`GridWrap.ColumnCount`, Fyne 2.8). `itemMin` пересчитывается в `gridWrapRenderer.Refresh()` при каждом `GridWrap.Refresh()` — это проверено по исходникам Fyne 2.8 и позволяет менять размер ячейки на лету.

Сейчас размер ячейки фиксирован: `coverSizeDesktop = 160×226`, `coverSizeMobile = 128×181` (`card.go`); карточка запекает размер при создании (`cover.SetMinSize`, `GridWrapLayout` у названия). Область обложки передаётся кэшу миниатюр через `thumbs.SetBox` в физических пикселях; смена области очищает кэш в памяти, а каталог хранит обложки для конкретного размера.

## Goals / Non-Goals

**Goals:**
- N колонок в портретной ориентации на Android, заполняющие ширину.
- Размер S/M/L на ПК.
- Применение на лету к библиотеке и поиску.

**Non-Goals:**
- Размер шрифта названия и число строк названия (остаются две строки обычным шрифтом).
- Отдельные настройки для библиотеки и поиска.
- Отдельная настройка для альбомной ориентации и планшетов.
- Изменение предела `thumbs.MaxSide` (см. риски).

## Decisions

**Общий объект размера `gridMetrics`.** Хранит текущий `coverSize` и режим (колонки N или размер S/M/L). Обе сетки получают один и тот же указатель; карточки читают размер из него, а не хранят копию. `galleryCard.MinSize()` вычисляется из `gridMetrics` при каждом вызове; `GridWrapLayout` у названия заменяется собственной раскладкой, которая берёт ширину из метрик.

**Расчёт ширины на Android.** В `galleryGrid.Resize` (обёртка над GridWrap или отслеживание размера через собственный контейнер):

```
short := min(canvas.Size().Width, canvas.Size().Height)   // короткая сторона окна
avail := short - (боковые отступы и полоса прокрутки сетки)
cardW := floor((avail - pad*(N-1)) / N) - ε               // ε = 0.5, чтобы ColumnCount дал ровно N
coverH := cardW * 1.414
```

Берётся короткая сторона окна, а не ширина сетки: тогда в альбомной ориентации ширина карточки та же, а колонок GridWrap насчитает больше сам. `ε` компенсирует погрешность float в `ColumnCount`.

Альтернатива — собственная раскладка вместо GridWrap с ровно N колонками. Отклонена: потеряем виртуализацию и переиспользование карточек GridWrap.

**Защита от цикла.** Пересчёт делается только когда вычисленный `cardW` отличается от текущего больше чем на 0,5; тогда метрики обновляются и вызывается `grid.Refresh()` (пересчёт `itemMin`) и `thumbs.SetBox`. `Refresh` из `Resize` безопасен при таком условии: следующий `Resize` с тем же размером ничего не меняет.

**ПК.** Размеры S/M/L = ширина обложки 130 / 160 / 200, высота × 1.414 (M совпадает с текущими 160×226).

**Настройки.** `grid.columns` = `2|3|4` (по умолчанию `3`), `grid.size` = `s|m|l` (по умолчанию `m`); функции чтения в `internal/app`. Экран «Настройки» показывает раздел «Сетка» только с нужной для платформы настройкой (`IsMobile`). Смена настройки вызывает колбэк Shell, который обновляет общий `gridMetrics` и вызывает `Refresh` у обеих сеток.

**Потоки.** Всё выполняется в UI-потоке: `Resize` и обработчики настроек вызываются Fyne в UI-потоке; загрузка обложек по-прежнему в фоне с возвратом через `g.do` (`fyne.Do`).

**Смена размера и миниатюры.** Старая миниатюра не растягивается: `SetBox` очищает кэш, карточки при `updateCard` показывают заглушку и запрашивают новую миниатюру (существующая логика). Обе сетки используют один кэш и одинаковую область — конфликта нет.

## Risks / Trade-offs

- [При «2» на экране 1080–1440 px область обложки 520–700 px, а `MaxSide = 512` — миниатюра будет увеличиваться и выглядеть мягче] → проверить на устройстве; если заметно, отдельным изменением поднять `MaxSide` (память кэша ограничена в байтах, поэтому рост размера лишь уменьшит число миниатюр в кэше).
- [Смена настройки пересоздаёт все обложки в каталоге] → смена редкая; декодирование идёт только для видимых карточек.
- [Поворот экрана вызывает `Resize` с другой шириной, но той же короткой стороной] → `cardW` не меняется, пересчёта и сброса кэша нет.
- [Ширина полосы прокрутки/отступов на разных версиях Fyne] → отступы берутся из темы (`theme.Padding()`), тест проверяет `ColumnCount() == N` для нескольких ширин.

## Platforms

Android — колонки N; Windows — размер S/M/L. Выбор по `fyne.CurrentDevice().IsMobile()`; платформенных файлов и build tags нет. На Linux (в планах) будет поведение ПК.
