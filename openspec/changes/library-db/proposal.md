## Why

Сейчас приложение ничего не помнит между запусками. Каждый запуск открывает каждый архив библиотеки, чтобы прочитать его оглавление и `meta.json`. Индекс поиска строится в памяти заново. Обложки декодируются в полный размер при первом показе. С сотнями архивов запуск и первая прокрутка библиотеки становятся заметно медленнее, особенно на Android, где архивы читаются через SAF. Нужен каталог на диске: при запуске библиотека показывается сразу из него, а открываются только новые и изменённые архивы.

## What Changes

- **Каталог библиотеки в SQLite** (`mattn/go-sqlite3`, cgo, с FTS5) на ПК и Android. Он хранит:
  - разобранные галереи: метаданные, список страниц, ссылка на сайт;
  - ошибочные файлы с причиной;
  - уменьшенные обложки (JPEG);
  - поисковые данные.

  На ПК файл `library.db` лежит в папке приложения рядом с `settings.json` (портативный режим), на Android — в личной папке приложения.
- **Запуск без повторного разбора.** Галереи и ошибки из каталога показываются сразу, до сканирования. Сканирование при запуске, по «Обновить» и при изменениях в папке сверяет список файлов с каталогом по пути, размеру и времени изменения. Разбираются только новые и изменённые файлы, записи удалённых удаляются. Архив, скачанный встроенным браузером, попадает в каталог после разбора, как сейчас.
- **Поиск через каталог.** Индекс `search.Index` реализован на SQLite: подстрока от 3 символов ищется по индексу FTS5 (trigram), короче — через `LIKE`; фильтры и сортировка — SQL. Синтаксис и результаты поиска не меняются; это закрепляет общий набор тестов для обоих индексов.
- **Поиск без учёта формы символов.** Текст и запрос одинаково нормализуются в Go: NFKC, нижний регистр, `ё` = `е`. Поиск `елка` находит «Ёлка», `ＡＢＣ` находит `ABC`.
- **Ссылки скачанных файлов хранятся в двух местах.** Адрес страницы, с которой скачан файл, после проверки файла записывается и в прежнее место (`links.json` на Android, метка загрузки NTFS на Windows), и в каталог. Если `links.json` повреждён или удалён, ссылки восстанавливаются из каталога и файл пишется заново. Если пересоздан каталог, ссылки переносятся в него из `links.json`. Если у файла пропала метка NTFS (например, после копирования), ссылка берётся из каталога.
- **Обложки на диске.** Миниатюра, уменьшенная до размера карточки, сохраняется в каталог. При следующем показе, в том числе после перезапуска, она читается оттуда без разбора архива.
- **Каталог — это кэш.** Если файл каталога повреждён или его схема устарела, он создаётся заново, а библиотека пересканируется. При смене папки библиотеки на Android каталог очищается.

Платформы: одинаково на Windows и Android. Сборка на обеих требует тега `sqlite_fts5`: он добавляется в Makefile, `tools/android-build` и CI.

## Non-goals

- Распаковка архивов: страницы, как и раньше, читаются прямо из zip.
- Постраничная загрузка сетки из БД: список галерей остаётся в памяти, это несколько МБ на тысячи произведений.
- Изменение синтаксиса поиска.

## Capabilities

### New Capabilities

- `library-catalog`: файл каталога и его расположение, загрузка при запуске, сверка с папкой, версия схемы и пересоздание, очистка при смене папки, обложки на диске, резервная копия ссылок скачанных файлов.

### Modified Capabilities

- `library-scan`: «Инкрементальное повторное сканирование» — неизменённые архивы не открываются и после перезапуска приложения.
- `search-index`: «Индекс в памяти» заменяется требованием «Индекс в каталоге» (SQLite, FTS5 trigram + `LIKE`); в «Совпадение слов» и «Совпадение условий» появляется нормализация символов.
- `search-query`: «Контракт индекса поиска» — рабочая реализация теперь индекс в каталоге.
- `library-view`: «Загрузка миниатюр» — миниатюра берётся из каталога без разбора архива.
- `library-location`: «Файлы только в папке приложения на ПК» — к `settings.json` добавляется `library.db`.

## Impact

- **Новый пакет `internal/catalog`:** схема, открытие и пересоздание, хранилище сканера, `search.Index`, хранилище обложек. Нужно добавить его в `internal/archtest` и архитектурные документы.
- **`internal/library`:** `Scanner` берёт кэш из каталога и сохраняет изменения, `Source` загружает галереи до сканирования, `Links` восстанавливается из каталога.
- **`internal/search`:** общая функция `Normalize`, парсер и `MemIndex` на ней (MemIndex остаётся для тестов), общий набор тестов индекса.
- **`internal/thumbs`:** хранилище обложек на диске через интерфейс, JPEG.
- **`internal/app`:** открытие каталога и путь к файлу на каждой платформе.
- **Сборка:** тег `sqlite_fts5` в Makefile, `tools/android-build`, а также в шагах `go vet`/`go test` в `.github/workflows/ci.yml` и `release.yml`. Сборки APK в CI идут через `tools/android-build`, пакет Windows — через Makefile. Работа CI проверяется реальным запуском GitHub Actions.
- **Зависимости:** `github.com/mattn/go-sqlite3` (MIT, включает SQLite — public domain); `golang.org/x/text` становится прямой. Обновить `THIRD_PARTY_NOTICES.md`.
- **Документация:** user-guide (каталог, поиск без учёта ё и ширины символов), building (тег сборки, первая сборка компилирует SQLite), architecture — на обоих языках.
