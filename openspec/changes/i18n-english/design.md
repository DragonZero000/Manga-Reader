## Context

- Около 1000 строковых литералов с кириллицей в Go (~43 КБ), из них примерно половина видна пользователю (в основном `internal/ui`), остальное — логи и тексты ошибок сервисных пакетов. В Kotlin-браузере ~64 строки прямо в коде, ресурсов `res/values*` нет.
- Пакет Fyne `lang` (2.5+) переводит свои встроенные тексты по языку системы; публичного способа задать язык нет (`setupLang` приватная). `go-locale` читает язык системы через Win32 (Windows) и JNI (Android) — переменные окружения там не действуют, поэтому подменить язык Fyne через `LANG` нельзя.
- Каталог уже хранит вид ошибки сканирования (`files.err_kind`, `library.ErrorKind` / `RestoreError`), а также текст (`err_text`) — сейчас русский. Список ошибок (`problems.Item.Reason`) формируется из `err.Error()`.
- Каталог пересоздаётся с полным сканированием при смене `PRAGMA user_version` (`catalog.schemaVersion`).

## Goals / Non-Goals

**Goals:**
- English + Русский; новые языки — добавлением файлов.
- Язык выбирается в приложении и одинаков для наших текстов, встроенных текстов Fyne и браузера Android.
- Смена языка корректно отражается на сохранённых ошибках.

**Non-Goals:**
- Firefox на Windows (`firefox-locale`).
- Смена языка без перезапуска: экраны собираются один раз в `NewShell`, пересборка всей оболочки не оправдана.
- Перевод комментариев; перевод синтаксиса запросов.

## Decisions

### 1. Пакет `internal/i18n` поверх go-i18n

`go-i18n/v2` и `golang.org/x/text/language` уже входят в сборку через Fyne — новых байт библиотек нет, есть формы множественного числа CLDR. Пакет не импортирует Fyne-виджеты (попадает в список `archtest`).

```
internal/i18n/
  locales/en.json      "_name": "English", ключи → тексты (go-i18n формат, plural one/other)
  locales/ru.json      "_name": "Русский", plural one/few/many/other
  fyne/base.en.json    копии встроенных переводов Fyne (BSD-3)
  fyne/base.ru.json
  i18n.go              Init(lang), T(key, args...), N(key, count, args...), Lang(), Available()
  format.go            Size(bytes), Date(t), DateTime(t) по языку
```

API: `i18n.T("library.count", n)` с именованными ключами (а не `lang.L("исходный текст")`): ключи стабильны при правке формулировок, а тест полноты проверяет их набор. Язык задаётся один раз при запуске (`Init`) до создания окна; до `Init` действует English.

Альтернатива — `fyne.io/fyne/v2/lang` для своих строк: язык берётся только из системы, выбор в приложении невозможен.

### 2. Определение языка

```
ui.language = auto | en | ru | …        (настройка, по умолчанию auto)
     │
 auto → go-locale.GetLocales() → базовый язык первой локали ∈ Available()? → он : en
 явный → он (если нет в Available() — en)
```

Выполняется в `cmd/mangareader` / `internal/app` до `NewShell`. `Available()` строится из встроенных `locales/*.json`, раздел настроек показывает `_name` каждого файла.

### 3. Встроенные тексты Fyne на выбранном языке

Fyne выбирает перевод, сопоставляя языки системы со списком загруженных переводов. Приём: после `i18n.Init(L)` вызвать `lang.AddTranslationsForLocale(<fyne/base.L.json>, fyne.Locale(<системная локаль>))`. go-i18n добавляет сообщения к тегу системного языка с перезаписью одинаковых ключей, поэтому Fyne, выбрав «системный» язык, получает тексты языка L. Если язык системы уже L — вызов безвреден.

Хрупкость: приём опирается на поведение go-i18n и Fyne. Защита — тест: при системной локали `ru` и L = `en` строка Fyne «Cancel» переводится как «Cancel». При поломке после обновления Fyne пострадают только несколько встроенных кнопок, а тест это покажет.

### 4. Типизированные ошибки, перевод в UI

- Сервисные пакеты не зависят от языка: `err.Error()` — английский технический текст, который пишется в лог.
- Существующие виды (`library.UnsupportedError{Kind, Ext}`, `ErrEmpty`, `ErrNoImages`, `ErrNotZip`, `storage.ErrUnavailable`, `storage.ErrBusy`) остаются; добавляются `search.ParseError{Code, Field, Fragment}`, ошибки браузера (`browser.NotFoundError{Path}`) и другие ошибки, которые видит пользователь.
- В UI функция `errText(err) string` (`internal/ui/messages.go`) сопоставляет вид через `errors.As/Is` с ключом перевода и параметрами. Неизвестная ошибка → `T("error.generic")` + `err.Error()` (для ошибок ОС это системный текст).
- `problems.Item` хранит `Err error` вместо `Reason string`; вкладка «Ошибки» вызывает `errText`. Статусы просмотра в настройках от текста не зависят (ключ — путь/размер/время) — менять их не нужно.
- `catalog.schemaVersion` повышается → старый каталог с русскими `err_text` пересоздаётся, библиотека сканируется целиком один раз.

Альтернатива — переводить в сервисах: сервисы зависят от языка UI, а в каталоге остаётся текст на языке момента сканирования; неизменённые файлы не перечитываются, и после смены языка причины остались бы на старом языке.

### 5. Логи

Все `log.Printf` (51 вызов) и Kotlin `Log.*` (~10) переводятся на английский. Текст для пользователя никогда не собирается из текста лога.

### 6. Браузер Android

- Строки Kotlin → `res/values/strings.xml` (English, по умолчанию) и `res/values-ru/strings.xml`; в коде `getString(R.string.…)`.
- Язык передаётся из Go: поле `Lang` в `mobilebrowser.Settings` (уже передаётся при каждом открытии). `BrowserActivity` и `DownloadService` применяют его в `attachBaseContext` через `createConfigurationContext` с нужной `Locale` — системный выбор языка приложения появился только в Android 13, а минимальная версия — 11.
- `GeckoRuntimeSettings.locales = [lang]` — Accept-Language и служебные страницы движка следуют языку приложения, как в Firefox (там `intl.accept_languages` по умолчанию берётся из языка интерфейса).

### 7. Форматы

`i18n.Size`: «1,5 МБ» / «1.5 MB»; `i18n.Date/DateTime`: «02.01.2006 15:04» / «Jan 2, 2006 15:04». `details.FormatDateTime` и форматирование размера переходят на них. Разбор размеров в запросе (`1,5mb` и `1.5mb`) не меняется.

## Размер

| Что | Размер |
|---|---|
| Библиотеки | 0 (уже в сборке) |
| `ru.json` + `en.json` | ≈ 50–65 КБ |
| Строки, убранные из кода | ≈ −20 КБ |
| Копии переводов Fyne | ≈ 4 КБ |
| Строки Android | ≈ 4 КБ на язык |
| **Итого** | **≈ +30–50 КБ** к exe (56 МБ) и apk |

Следующий язык: ≈ 30 КБ + 4 КБ (+ языковой пакет Firefox ≈ 0,5 МБ на Windows, см. `firefox-locale`).

## Risks / Trade-offs

- [Приём с переводами Fyne сломается после обновления Fyne] → тест из п. 3; в худшем случае несколько встроенных кнопок будут на языке системы.
- [Пересоздание каталога после обновления — долгое первое сканирование большой библиотеки] → однократно; библиотека из прежнего каталога не показывается, пока идёт сканирование — показать в release notes.
- [55 тестовых файлов с русскими строками] → общий `TestMain`/хелпер `i18n.SetForTest("ru")`; тесты сравнивают с `i18n.T(key)` там, где проверяют именно перевод.
- [Английские тексты длиннее или короче — подписи обрезаются] → пройти по экранам на обоих языках на ПК и телефоне (задача проверки).
- [Русские `err_text` от ошибок без вида в каталоге старой версии] → снимается пересозданием каталога.
- [`go-locale` на Android требует JVM-контекст до `Init`] → вызывать определение языка после старта драйвера Fyne (в `main` до `NewShell`, где JVM уже доступна), проверить на устройстве.

## Platforms

- Windows и Android: `internal/i18n`, UI, ошибки, логи — общий код без build tags.
- Android: Kotlin-ресурсы и передача языка в `BrowserActivity`/`DownloadService`/GeckoView (`*_android.go` в `mobilebrowser` — только новое поле настроек).
- Linux (в планах): язык системы из `LANG`/`LC_*` через `go-locale` — работает без доработок.
- Firefox на Windows остаётся на языке своей сборки до изменения `firefox-locale`.

## Migration Plan

1. Выпуск с повышенной версией каталога: при первом запуске каталог пересоздаётся, библиотека сканируется целиком.
2. Настройка `ui.language` отсутствует → «Системный»; русскоязычные пользователи на русской системе видят прежний интерфейс.
3. Ссылки скачанных файлов переживают пересоздание каталога: они переносятся из `links.json` (Android) или метки загрузки NTFS (Windows), см. «Ссылки скачанных файлов в каталоге» (`library-catalog`).
4. Откат: предыдущая версия увидит каталог другой версии и тоже пересоздаст его; архивы, настройки и ссылки не теряются.
