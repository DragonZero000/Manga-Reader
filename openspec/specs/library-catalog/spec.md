# library-catalog Specification

## Purpose

Каталог библиотеки в SQLite (`library.db`): расположение файла, показ библиотеки при запуске без открытия архивов, сверка с папкой, версия и восстановление, смена папки, кэш обложек на диске (вне каталога: файлы в системном кэше) и вторая копия ссылок скачанных файлов.

## Requirements
### Requirement: Файл каталога
Приложение SHALL хранить каталог библиотеки в одном файле SQLite: на ПК — `library.db` в папке приложения рядом с `settings.json`, на Android — `library.db` в личной папке приложения. Каталог содержит разобранные галереи, ошибочные файлы с причиной и поисковые данные для папки библиотеки, для которой он создан; уменьшенные обложки хранятся отдельно, в кэше обложек (см. «Обложки в каталоге»). Каталог MUST NOT храниться в папке библиотеки.

#### Scenario: ПК
- **WHEN** приложение на Windows запущено и библиотека просканирована
- **THEN** рядом с `mangareader.exe` есть `library.db`, в папке `manga` новых файлов нет

#### Scenario: Android
- **WHEN** приложение на Android запущено с выбранной папкой `Download/manga`
- **THEN** каталог создан в личной папке приложения, в `Download/manga` новых файлов нет

### Requirement: Библиотека из каталога при запуске
При запуске приложение SHALL показывать галереи и ошибочные файлы из каталога до окончания первого сканирования, без открытия архивов. Затем сканирование MUST сверить список файлов папки с каталогом по пути, размеру и времени изменения: новые и изменённые файлы разбираются и записываются в каталог, записи удалённых файлов удаляются. Результат сканирования MUST записываться в каталог одной транзакцией.

#### Scenario: Быстрый запуск
- **WHEN** библиотека из 300 архивов просканирована, приложение закрыто и запущено снова без изменений в папке
- **THEN** сетка библиотеки показывает 300 галерей до окончания сканирования, и сканирование не открывает ни одного архива

#### Scenario: Изменения, пока приложение закрыто
- **WHEN** пока приложение было закрыто, в папку добавлен `b.zip`, изменён `c.zip` и удалён `a.zip`
- **THEN** после сканирования при запуске в библиотеке есть `b.zip` и новая версия `c.zip`, нет `a.zip`; открывались только `b.zip` и `c.zip`

#### Scenario: Ошибочный файл
- **WHEN** в папке лежит `page.html` вместо архива и приложение перезапущено
- **THEN** файл сразу виден на вкладке «Ошибки» с прежней причиной и не открывается повторно, пока не изменится

### Requirement: Версия и восстановление каталога
Каталог SHALL хранить номер версии схемы и нормализации текста. Если файл каталога не открывается, повреждён или его версия отличается от ожидаемой, приложение MUST удалить его, создать заново и пересканировать библиотеку целиком. Работа приложения MUST NOT прерываться. Если каталог недоступен для записи, приложение MUST работать как без каталога (всё в памяти) и записывать причину в журнал.

#### Scenario: Повреждённый файл
- **WHEN** `library.db` заменён файлом с мусором и приложение запущено
- **THEN** каталог создаётся заново, библиотека сканируется целиком и показывается как обычно

#### Scenario: Новая версия схемы
- **WHEN** приложение с новой версией схемы запускается с каталогом прежней версии
- **THEN** каталог пересоздаётся, поиск и библиотека работают

### Requirement: Смена папки библиотеки
Каталог SHALL относиться к одной папке библиотеки. При смене папки (Android: «Изменить папку») каталог MUST очищаться, а новая папка — сканироваться целиком.

#### Scenario: Другая папка
- **WHEN** на Android выбрана другая папка библиотеки
- **THEN** галереи прежней папки не показываются и не находятся поиском, новая папка сканируется целиком

### Requirement: Ссылки скачанных файлов в каталоге
Адрес страницы, с которой скачан файл, SHALL храниться в двух местах: в прежнем (Android — `links.json` в личной папке приложения, Windows — метка загрузки файла NTFS) и в каталоге, по пути файла относительно папки библиотеки. Ссылка записывается в каталог, когда файл после загрузки проверен и разобран. Если одного из мест нет или оно повреждено, ссылка MUST браться из другого:
- `links.json` отсутствует или повреждён — ссылки MUST восстанавливаться из каталога, файл MUST записываться заново;
- каталог создан заново — ссылки MUST переноситься в него из `links.json`;
- у файла нет метки загрузки — MUST использоваться ссылка из каталога.

Ссылка из `meta.json` по-прежнему имеет приоритет. Записи для файлов, которых больше нет в папке, MUST удаляться из обоих мест.

#### Scenario: Повреждённый links.json
- **WHEN** на Android архив скачан встроенным браузером, `links.json` заменён мусором, и приложение перезапущено
- **THEN** у галереи есть кнопка «Открыть в браузере» с той же ссылкой, а `links.json` снова содержит эту ссылку

#### Scenario: Пересозданный каталог
- **WHEN** архив скачан встроенным браузером, `library.db` удалён, и приложение перезапущено
- **THEN** после сканирования у галереи та же ссылка, и она снова есть в каталоге

#### Scenario: Потеря метки загрузки
- **WHEN** на Windows архив скачан встроенным браузером, у файла удалена метка загрузки (`Zone.Identifier`), и файл изменён так, что его разбирают заново
- **THEN** у галереи сохраняется прежняя ссылка из каталога

#### Scenario: Удалённый файл
- **WHEN** скачанный архив удалён из папки и библиотека пересканирована
- **THEN** его ссылки нет ни в `links.json`, ни в каталоге

### Requirement: Обложки в каталоге
Уменьшенные обложки SHALL храниться не в каталоге, а файлами JPEG в кэше обложек: на Android — в системной папке кэша приложения (`getCacheDir()/covers`), на ПК — в папке `cache/thumbs` рядом с исполняемым файлом. Имя файла строится из ключа галереи (путь, время изменения архива) и размера области обложки. Когда нужна миниатюра, которой нет в памяти, приложение MUST сначала взять её из кэша обложек и только при её отсутствии декодировать первую страницу архива; созданная миниатюра MUST сохраняться в кэш обложек. При сохранении обложки другого размера для той же галереи прежний файл MUST удаляться; обложка другого размера области MUST NOT использоваться. После каждого сканирования файлы обложек галерей, которых больше нет в библиотеке (удалённые и изменённые архивы), MUST удаляться вне UI-потока. При смене папки библиотеки (Android) кэш обложек MUST очищаться. Каталог прежней версии с таблицей обложек MUST открываться без повторного сканирования: таблица удаляется, место в файле освобождается.

#### Scenario: Обложка после перезапуска
- **WHEN** обложки библиотеки показаны, приложение перезапущено и сетка прокручена
- **THEN** обложки показываются из кэша обложек, архивы для обложек не открываются

#### Scenario: Изменённый архив
- **WHEN** архив заменён другим с новой первой страницей и библиотека пересканирована
- **THEN** карточка показывает новую обложку, файл прежней обложки удалён

#### Scenario: Системный кэш (Android)
- **WHEN** на Android показано 83 обложки
- **THEN** их объём учитывается системой в «Кэше» приложения, а не в «Данных», и «Очистить кэш» в настройках Android их удаляет

#### Scenario: Переход с каталога прежней версии
- **WHEN** приложение запускается с каталогом, в котором обложки хранились в таблице
- **THEN** библиотека показывается из каталога без повторного сканирования, таблица обложек удалена, файл каталога уменьшился

### Requirement: Размер и очистка кэша обложек
В «Настройках» SHALL быть строка «Кэш обложек» с объёмом файлов кэша обложек (в МБ с одним знаком после запятой) и кнопкой «Очистить». Объём MUST подсчитываться вне UI-потока при каждом открытии вкладки «Настройки» и после очистки; пока подсчёт идёт, вместо числа MUST показываться «…».

Кнопка «Очистить» MUST без диалога подтверждения удалять все файлы кэша обложек. По окончании MUST показываться уведомление «Кэш обложек очищен». Очистка MUST выполняться вне UI-потока; миниатюры в памяти MUST NOT удаляться, поэтому видимые карточки не меняются. Удалённые обложки создаются заново из архивов по мере показа карточек. Пока очистка идёт, кнопка MUST быть недоступна. Кэш обложек MUST работать и без каталога (SQLite недоступен).

#### Scenario: Показ объёма
- **WHEN** в кэше 200 обложек по 50 КБ, и пользователь открывает вкладку «Настройки»
- **THEN** сначала показывается «…», затем «Кэш обложек: 9,8 МБ»

#### Scenario: Очистка
- **WHEN** пользователь нажимает «Очистить»
- **THEN** файлы обложек удалены, показано уведомление «Кэш обложек очищен», строка показывает «0 МБ», а сетка библиотеки показывает прежние обложки из памяти

#### Scenario: Обложки после очистки
- **WHEN** после очистки приложение перезапущено и сетка прокручена
- **THEN** обложки создаются из архивов и снова сохраняются в кэш обложек
