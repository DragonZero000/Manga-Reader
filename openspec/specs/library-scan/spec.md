# library-scan Specification

## Purpose

Обнаружение zip-архивов в папке библиотеки, разбор архива с meta.json в единую модель Gallery, инкрементальное повторное сканирование, обработка ошибок архивов и доступ к страницам через источник библиотеки.
## Requirements
### Requirement: Обнаружение архивов
Сканер SHALL проверять все файлы в папке библиотеки и её вложенных папках. Файлы с расширением `.zip` (без учёта регистра) MUST разбираться как архивы; все остальные файлы MUST попадать в список ошибок как неподдерживаемые. Файлы и папки, имя которых начинается с `.`, MUST пропускаться. Ключ галереи MUST строиться из пути архива относительно папки библиотеки с прямыми слешами (`local:sub/example.zip`).

#### Scenario: Архив в корне папки
- **WHEN** в папке библиотеки лежит `example.zip`
- **THEN** сканер возвращает одну галерею с ключом `local:example.zip`

#### Scenario: Архив во вложенной папке
- **WHEN** архив лежит по пути `<библиотека>/series/vol1.ZIP`
- **THEN** сканер возвращает галерею с ключом `local:series/vol1.ZIP`

#### Scenario: Скрытые файлы
- **WHEN** в папке лежат `.hidden.zip` и папка `.trash` с архивом внутри
- **THEN** ни один из них не попадает ни в галереи, ни в ошибки

#### Scenario: Посторонние файлы
- **WHEN** в папке лежит `notes.txt`
- **THEN** галерей не создаётся, а в ошибках есть запись `notes.txt` с причиной «Текстовый файл — поддерживаются только zip-архивы»

#### Scenario: Пустая папка
- **WHEN** папка библиотеки пуста
- **THEN** сканер возвращает пустой список без ошибок

### Requirement: Разбор архива с meta.json
Для каждого архива система SHALL построить `Gallery` по правилам:
- для правил ниже имя записи оглавления zip приводится к пути: в имени в UTF-8 `\` считается разделителем (в имени не в UTF-8 байт `\` может быть частью символа, например в Shift-JIS, и разделителем не считается), пустые сегменты и сегменты `.` пропускаются; записи с именами не в UTF-8 (например, Shift-JIS или CP866 без флага UTF-8) MUST обрабатываться наравне с остальными; имя страницы в галерее MUST побайтно совпадать с именем записи в оглавлении, в том числе после сохранения галереи в каталог библиотеки и загрузки из него;
- `meta.json` ищется на любой глубине архива; если их несколько, используется наименее вложенный;
- страницы — файлы с расширениями `.jpg`, `.jpeg`, `.png`, `.gif`, `.webp` (без учёта регистра) на любой глубине, кроме служебных (сегмент `__MACOSX` или сегмент, начинающийся с `.`, в том числе `..`);
- если несколько записей оглавления имеют одинаковое имя, страницей MUST становиться первая из них, остальные MUST пропускаться с предупреждением сканирования;
- страницы упорядочиваются в натуральном порядке по полному пути внутри архива;
- название выбирается по правилу `ChooseTitle` (english → japanese → имя файла);
- из `meta.json` переносятся `id`, `upload_date` (Unix-время, секунды), `num_pages`, `num_favorites`, `scanlator` и теги с типами (нормализованные);
- в `File` сохраняются путь, размер и время изменения архива.

#### Scenario: Эталонный архив
- **WHEN** сканируется `testdata/example.zip`
- **THEN** галерея имеет название «english name», альтернативное «japanease name», внешний ID 535147, 2 страницы (`example/1.jpg`, `example/2.jpg`), обложку `example/1.jpg`, 8 тегов, среди которых `artist:artist 1` и `language:japanese`, дату загрузки 2024-10-15 (UTC)

#### Scenario: Много страниц
- **WHEN** архив содержит страницы `1.jpg` … `12.jpg`
- **THEN** страница `2.jpg` идёт перед `10.jpg`, обложка — `1.jpg`

#### Scenario: Архив без meta.json
- **WHEN** архив `my manga.zip` содержит только изображения
- **THEN** галерея создаётся с названием «my manga», без тегов и внешнего ID

#### Scenario: Некорректный meta.json
- **WHEN** `meta.json` в архиве не является корректным JSON
- **THEN** галерея создаётся как для архива без `meta.json`, а проблема фиксируется в предупреждениях сканирования

#### Scenario: Расхождение числа страниц
- **WHEN** `num_pages` в `meta.json` равно 5, а изображений в архиве 3
- **THEN** список страниц содержит 3 элемента, а `NumPages` хранит значение 5 из метаданных

#### Scenario: Разделитель «\»
- **WHEN** архив содержит записи `ch1\meta.json`, `ch1\001.jpg` и `ch1\002.jpg`
- **THEN** галерея имеет 2 страницы с именами `ch1\001.jpg` и `ch1\002.jpg`, а название и теги взяты из `ch1\meta.json`

#### Scenario: Служебные файлы с разделителем «\»
- **WHEN** архив содержит записи `001.jpg` и `__MACOSX\._001.jpg`
- **THEN** галерея имеет одну страницу `001.jpg`

#### Scenario: Имена не в UTF-8
- **WHEN** архив содержит записи `<папка в Shift-JIS>/001.jpg` и `<папка в Shift-JIS>/002.jpg` без флага UTF-8
- **THEN** галерея имеет 2 страницы, имена которых совпадают с именами записей побайтно

#### Scenario: Байт «\» внутри символа Shift-JIS
- **WHEN** архив без флага UTF-8 содержит записи `<«表紙» в Shift-JIS, второй байт 0x5C>.jpg` и `001.jpg`
- **THEN** галерея имеет 2 страницы, имена которых совпадают с именами записей побайтно

#### Scenario: Имена с «./» в начале
- **WHEN** архив содержит только записи `./001.jpg` и `./002.jpg`
- **THEN** создаётся галерея с 2 страницами, а не ошибка «нет изображений»

#### Scenario: Повторяющиеся имена
- **WHEN** оглавление архива содержит две записи `001.jpg` и одну запись `002.jpg`
- **THEN** галерея имеет 2 страницы (`001.jpg`, `002.jpg`), а в предупреждениях сканирования есть сообщение о повторяющемся имени

### Requirement: Ошибки архивов не прерывают сканирование
Если файл не удаётся открыть как галерею (не открывается, не является zip-архивом, в архиве нет изображений, файл неподдерживаемого формата или пустой), сканер MUST пропустить его, добавить запись в список ошибок (относительный путь, размер, время изменения и причина) и продолжить обработку остальных файлов. Как и для корректных архивов, неизменённый ошибочный файл MUST NOT открываться повторно.

#### Scenario: Повреждённый архив
- **WHEN** в папке лежат `example.zip` и `broken.zip` (не zip-файл)
- **THEN** результат содержит одну галерею и одну ошибку для `broken.zip`

#### Scenario: Архив без изображений
- **WHEN** архив содержит только `meta.json`
- **THEN** архив не попадает в список галерей и отражается в ошибках с причиной «нет изображений»

#### Scenario: Пустой файл
- **WHEN** в папке лежит `empty.zip` размером 0 байт и рядом нет `empty.zip.part`
- **THEN** в ошибках есть запись `empty.zip` с причиной «Пустой файл»

### Requirement: Инкрементальное повторное сканирование
Повторное сканирование MUST переиспользовать ранее разобранную галерею или причину ошибки, если размер и время изменения файла не изменились, и MUST заново разбирать изменённые файлы. Исключение — однократная перепроверка после изменения правил разбора (см. «Перепроверка после изменения правил разбора»). Удалённые файлы MUST исчезать из результата. Ранее разобранные результаты MUST браться из каталога библиотеки, поэтому это действует и после перезапуска приложения (см. `library-catalog`).

#### Scenario: Без изменений
- **WHEN** папка сканируется дважды без изменений файлов
- **THEN** при втором сканировании ни один архив не открывается повторно, результат тот же

#### Scenario: Новый и удалённый архив
- **WHEN** между сканированиями добавлен `b.zip` и удалён `a.zip`
- **THEN** второй результат содержит `b.zip` и не содержит `a.zip`

#### Scenario: Без изменений после перезапуска
- **WHEN** папка просканирована, сканер создан заново над тем же каталогом, и папка сканируется снова без изменений файлов
- **THEN** ни один архив не открывается, результат тот же

### Requirement: Перепроверка после изменения правил разбора
Каталог библиотеки SHALL хранить ревизию правил разбора архивов, с которой получены сохранённые результаты (отсутствие значения — ревизия 0). Если сохранённая ревизия меньше текущей ревизии приложения, сканирование MUST заново разобрать файлы, сохранённый результат которых может измениться по новым правилам, даже если их размер и время изменения не менялись. Для текущей ревизии это:
- галереи, у которых есть страница с `\` в имени в UTF-8 или с символом замены U+FFFD (имя не в UTF-8, искажённое при прежнем сохранении в каталог), или повторяющиеся имена страниц;
- файлы с ошибкой «нет изображений».

Остальные неизменённые файлы MUST NOT открываться. До перепроверки галереи и ошибки из каталога MUST показываться как прежде. Текущая ревизия MUST сохраняться в каталоге только после успешного сканирования, в котором разобраны все файлы, ожидающие перепроверки; после этого перепроверка MUST NOT повторяться. Если сканирование не завершилось или файл при перепроверке занят другим процессом, перепроверка MUST повториться при следующем сканировании (в том числе после перезапуска). Из-за смены ревизии каталог MUST NOT пересоздаваться и библиотека MUST NOT пересканироваться целиком.

#### Scenario: Перепроверяются только затронутые файлы
- **WHEN** каталог ревизии 0 содержит неизменённые `a.zip` (страницы `ch1\001.jpg`, `ch1\002.jpg`) и `b.zip` (страницы `1.jpg`, `2.jpg`), и библиотека сканируется
- **THEN** открывается только `a.zip`, `b.zip` не открывается

#### Scenario: Ошибка «нет изображений» исправляется
- **WHEN** каталог ревизии 0 хранит для неизменённого `dot.zip` (записи `./001.jpg`, `./002.jpg`) ошибку «нет изображений», и библиотека сканируется
- **THEN** `dot.zip` становится галереей с 2 страницами и исчезает из ошибок

#### Scenario: Искажённые имена восстанавливаются
- **WHEN** каталог ревизии 0 хранит галерею неизменённого `sjis.zip`, имена страниц которой содержат U+FFFD, и библиотека сканируется
- **THEN** `sjis.zip` разбирается заново, и все его страницы открываются

#### Scenario: Ревизия сохранена
- **WHEN** перепроверка завершилась, сканер создан заново над тем же каталогом, и папка сканируется снова без изменений файлов
- **THEN** ни один архив не открывается

#### Scenario: Файл занят при перепроверке
- **WHEN** при сканировании с перепроверкой затронутый файл занят другим процессом (Windows)
- **THEN** ревизия не сохраняется, и файл перепроверяется при следующем сканировании

#### Scenario: Прежние результаты видны до перепроверки
- **WHEN** приложение запускается с каталогом ревизии 0, в котором есть галерея `a.zip` со страницами через `\`
- **THEN** `a.zip` показывается в библиотеке из каталога до окончания первого сканирования

### Requirement: Порядок галерей
Сканер SHALL возвращать галереи отсортированными по времени изменения файла по убыванию (новые сверху); при равном времени — по ключу в натуральном порядке.

#### Scenario: Недавно добавленный сверху
- **WHEN** `old.zip` изменён раньше, чем `new.zip`
- **THEN** `new.zip` идёт первым

### Requirement: Доступ к страницам через источник
Источник библиотеки SHALL предоставлять открытие страницы галереи по ключу и имени страницы и возвращать поток байтов изображения. Страница MUST открываться по записи оглавления zip, имя которой побайтно совпадает с именем страницы, независимо от кодировки имени и разделителей в нём; при повторяющихся именах — по первой такой записи. Открытие несуществующей галереи или страницы MUST возвращать ошибку. Одновременное открытие страниц из разных горутин MUST быть безопасным.

#### Scenario: Открытие обложки
- **WHEN** запрашивается страница `example/1.jpg` галереи `local:example.zip`
- **THEN** возвращается поток, из которого читаются все байты `1.jpg` из архива

#### Scenario: Неизвестная страница
- **WHEN** запрашивается страница `example/99.jpg`
- **THEN** возвращается ошибка, приложение не падает

#### Scenario: Страница с разделителем «\»
- **WHEN** запрашивается страница `ch1\001.jpg` галереи, в оглавлении которой есть запись `ch1\001.jpg`
- **THEN** возвращаются все байты этой записи

#### Scenario: Страница с именем не в UTF-8
- **WHEN** запрашивается страница, имя которой — имя записи в Shift-JIS без флага UTF-8
- **THEN** возвращаются все байты этой записи

#### Scenario: Страница с «/» в начале
- **WHEN** запрашивается страница `/001.jpg` галереи, в оглавлении которой есть запись `/001.jpg`
- **THEN** возвращаются все байты этой записи

#### Scenario: Имена не в UTF-8 после перезапуска
- **WHEN** архив с записями `<папка A в Shift-JIS>/001.jpg` и `<папка B в Shift-JIS>/001.jpg` разобран, сканер создан заново над тем же каталогом, и страницы галереи из каталога открываются
- **THEN** каждая страница возвращает байты своей записи, имена двух страниц различаются

### Requirement: Передача в индекс поиска
После каждого сканирования система MUST передавать каждую найденную или изменённую галерею в `search.Index.Upsert` и вызывать `Remove` для удалённых. Ошибки индекса MUST логироваться и MUST NOT прерывать сканирование.

#### Scenario: Сканирование с пустым индексом
- **WHEN** используется `NopIndex`
- **THEN** сканирование завершается успешно и библиотека отображается

### Requirement: Размеры страниц
Источник библиотеки SHALL возвращать размеры (ширину и высоту в пикселях) всех страниц галереи в порядке страниц, читая только заголовки изображений, без полного декодирования. Заголовки MUST читаться из тех же записей оглавления, что и при открытии страниц (см. «Доступ к страницам через источник»). Архив MUST открываться для этого один раз. Для страницы, размер которой определить не удалось, MUST возвращаться нулевой размер и признак ошибки, а остальные страницы MUST обрабатываться.

#### Scenario: Размеры эталонного архива
- **WHEN** запрашиваются размеры страниц `local:example.zip`
- **THEN** возвращаются 2 размера, совпадающие с размерами изображений `example/1.jpg` и `example/2.jpg`

#### Scenario: Битая страница
- **WHEN** одна из страниц архива не является изображением
- **THEN** для неё возвращается нулевой размер с ошибкой, для остальных — корректные размеры

#### Scenario: Неизвестная галерея
- **WHEN** запрашиваются размеры страниц несуществующей галереи
- **THEN** возвращается ошибка

#### Scenario: Имена с разделителем «\» и не в UTF-8
- **WHEN** запрашиваются размеры страниц галереи, записи которой названы через `\` или не в UTF-8
- **THEN** для каждой страницы возвращается её размер без ошибки

### Requirement: Незавершённые загрузки
Сканер MUST пропускать, не считая ни галереей, ни ошибкой: файлы с расширением `.part` (без учёта регистра) и файл размером 0 байт, рядом с которым в той же папке лежит файл `<его имя>.part`.

#### Scenario: Идёт загрузка
- **WHEN** в папке лежат `g-1.zip` размером 0 байт и `g-1.zip.part`
- **THEN** сканер не возвращает для них ни галерей, ни ошибок

#### Scenario: Загрузка завершилась
- **WHEN** `g-1.zip.part` исчез, а `g-1.zip` стал корректным архивом, и библиотека повторно просканирована
- **THEN** сканер возвращает галерею `local:g-1.zip`

### Requirement: Определение типа неподдерживаемого файла
Для файла, который не является корректной галереей, сканер SHALL определить тип по первым байтам содержимого (не по расширению) и сформировать причину с названием типа: «Изображение», «Видео», «Аудио», «Веб-страница (HTML)», «PDF», «Архив RAR/7z», «Текстовый файл»; если тип не распознан — «Неподдерживаемый формат». Для файлов, распознанных как изображение, видео, аудио, PDF, RAR/7z или текст, к причине MUST добавляться « — поддерживаются только zip-архивы». Для веб-страницы причина MUST быть «Веб-страница (HTML) вместо архива — вероятно, сайт вернул страницу с ошибкой или проверкой». Для файла с расширением `.zip`, содержимое которого не является zip и не распознано, причина MUST оставаться «не zip-архив или архив повреждён».

#### Scenario: Картинка с расширением zip
- **WHEN** в папке лежит `g-2.zip`, содержимое которого — JPEG
- **THEN** в ошибках есть запись `g-2.zip` с причиной «Изображение — поддерживаются только zip-архивы»

#### Scenario: Скачалась веб-страница
- **WHEN** в папке лежит `g-3.zip`, содержимое которого начинается с `<!DOCTYPE html>`
- **THEN** причина ошибки начинается с «Веб-страница (HTML) вместо архива»

#### Scenario: Видео
- **WHEN** в папке лежит `clip.mp4` с содержимым MP4
- **THEN** причина ошибки — «Видео — поддерживаются только zip-архивы»

#### Scenario: Обрезанный zip
- **WHEN** `part.zip` — первые 100 КБ корректного архива
- **THEN** причина ошибки — «не zip-архив или архив повреждён»

### Requirement: Ссылка из meta.json
При разборе `meta.json` сканер SHALL искать ссылку на произведение в полях верхнего уровня `url`, `source`, `link`, `source_url`, `gallery_url` в этом порядке и MUST использовать первое значение, которое является строкой с абсолютным адресом `http` или `https`. Поля другого типа или с некорректным адресом MUST пропускаться без предупреждения.

#### Scenario: Поле url
- **WHEN** `meta.json` содержит `"url": "https://site.example/g/535147/"`
- **THEN** ссылка галереи — `https://site.example/g/535147/`

#### Scenario: Первое поле некорректно
- **WHEN** `meta.json` содержит `"url": "не ссылка"` и `"source": "https://site.example/g/1/"`
- **THEN** ссылка галереи — `https://site.example/g/1/`

#### Scenario: Ссылки нет
- **WHEN** `meta.json` не содержит ни одного из полей
- **THEN** ссылка из `meta.json` пустая, предупреждений нет

### Requirement: Отпечаток содержимого архива
При разборе архива система SHALL вычислять отпечаток содержимого `Gallery.Fingerprint`: SHA-256 (строка в шестнадцатеричном виде) от списка страниц, упорядоченного по полному пути внутри архива побайтно, где для каждой страницы учитываются полный путь, CRC32 и несжатый размер из оглавления zip. Для отпечатка MUST использоваться только оглавление архива, без распаковки. `meta.json`, служебные файлы и файлы не-изображения MUST NOT влиять на отпечаток. Отпечаток MUST NOT зависеть от имени и расположения файла архива и от внешнего ID из `meta.json`.

#### Scenario: Переименованная копия
- **WHEN** `testdata/example.zip` скопирован как `other/copy.zip`
- **THEN** отпечатки обеих галерей совпадают

#### Scenario: Изменён только meta.json
- **WHEN** в архиве изменено содержимое `meta.json`, картинки не менялись
- **THEN** отпечаток не изменился

#### Scenario: Изменена страница
- **WHEN** в архиве заменено содержимое `example/2.jpg`
- **THEN** отпечаток изменился

#### Scenario: Порядок записей в архиве
- **WHEN** два архива содержат одинаковые страницы, записанные в оглавление в разном порядке
- **THEN** их отпечатки совпадают
