# android-build Specification

## Purpose

Сборка Android-пакета через Gradle: Go-часть в libmangareader.so через NDK, Java-классы Fyne из модуля нужной версии, Android 11+, архитектуры из одного списка, стабильная подпись и неизменное поведение приложения.
## Requirements
### Requirement: Сборка Android-пакета через Gradle
`make build-android` SHALL собирать `dist/mangareader.apk` Gradle-проектом из папки `android/`: Go-часть — в `libmangareader.so` для каждой заданной архитектуры, Java-классы Fyne — из модуля Fyne той версии, что указана в `go.mod`. Сборка MUST работать из PowerShell, cmd и Git Bash при установленных Android SDK (Platform API 35 или новее, NDK 27, Command-line Tools) и Android Studio; отдельная установка Kotlin и Gradle MUST NOT требоваться. JDK MUST браться из Android Studio (JBR), если `JAVA_HOME` указывает на JDK старше 17.

#### Scenario: Сборка на машине разработчика
- **WHEN** разработчик с Android Studio, NDK 27 и SDK Platform 35 выполняет `make build-android`
- **THEN** создаётся `dist/mangareader.apk`, при этом Kotlin и Gradle отдельно не устанавливались

#### Scenario: Старый JAVA_HOME
- **WHEN** `JAVA_HOME` указывает на JDK 11, а в Android Studio есть JBR 21
- **THEN** сборка использует JBR 21 и завершается успешно

#### Scenario: Нет NDK
- **WHEN** NDK не установлен
- **THEN** сборка останавливается с сообщением, какой NDK установить и где (SDK Manager → SDK Tools)

### Requirement: Состав APK
APK SHALL иметь идентификатор приложения `io.github.mangareader.app`, `versionName` — версию из `FyneApp.toml`, `versionCode` — вычисленный из этой версии (см. `app-versioning`), минимальную версию Android 11 (API 30) и содержать нативные библиотеки только для заданных архитектур; по умолчанию — только `arm64-v8a`. Список архитектур MUST задаваться в одном месте сборки.

#### Scenario: Архитектура по умолчанию
- **WHEN** собран APK без изменения настроек
- **THEN** в APK есть `lib/arm64-v8a/libmangareader.so` и нет каталогов других архитектур

#### Scenario: Добавление архитектуры
- **WHEN** в список архитектур добавлена `armeabi-v7a` и выполнена сборка
- **THEN** APK содержит библиотеки для `arm64-v8a` и `armeabi-v7a`

#### Scenario: Старая версия Android
- **WHEN** APK устанавливается на Android 10
- **THEN** система отказывает в установке из-за минимальной версии

#### Scenario: Версия в APK
- **WHEN** собран APK при `Version = "0.2.0"` в `FyneApp.toml`
- **THEN** `aapt dump badging` показывает `versionName='0.2.0'` и `versionCode='200'`

### Requirement: Подпись и обновление поверх установленной версии
APK SHALL подписываться одним и тем же ключом при каждой сборке на одной машине (отладочные сборки — отладочным ключом Android SDK; сборка с ключом проекта задаётся переменными окружения), чтобы новую сборку можно было установить поверх предыдущей без удаления и без потери настроек. APK с большей версией, подписанный тем же ключом, MUST устанавливаться поверх меньшей без удаления, поскольку его `versionCode` больше. Релизы проекта MUST подписываться одним постоянным ключом проекта (см. `release-pipeline`). Release-сборка с флагом `-require-signing` MUST завершаться ошибкой, если ключ не задан, вместо выдачи неподписанного APK.

#### Scenario: Повторная установка
- **WHEN** разработчик дважды собирает и устанавливает APK командой `adb install -r`
- **THEN** вторая установка проходит без удаления приложения, выбранная папка библиотеки сохраняется

#### Scenario: Обновление версии
- **WHEN** установлена сборка `0.1.0`, а затем тем же ключом собрана и установлена `0.2.0`
- **THEN** установка проходит как обновление, настройки и выбранная папка библиотеки сохраняются

#### Scenario: Переход с ручного номера сборки
- **WHEN** установлена сборка с прежним `versionCode` `1`, а затем тем же ключом установлена сборка `0.1.0` с вычисленным `versionCode` `100`
- **THEN** установка проходит как обновление

#### Scenario: Обязательная подпись без ключа
- **WHEN** выполняется `go run ./tools/android-build -release -require-signing`, а `MANGAREADER_KEYSTORE` не задан
- **THEN** сборка завершается ошибкой до запуска Gradle, и APK не создаётся

#### Scenario: Без обязательной подписи
- **WHEN** выполняется `make build-android-release` без `MANGAREADER_KEYSTORE`
- **THEN** создаётся неподписанный release-APK с предупреждением, как и раньше

### Requirement: Поведение приложения не меняется
Приложение, собранное через Gradle, SHALL вести себя так же, как собранное `fyne package`: запуск на экране «Библиотека», системный выбор папки и постоянный доступ к ней, чтение архивов, экранная клавиатура в поле поиска, кнопка «Назад» (закрытие слоёв, затем сворачивание), иконка приложения и его название «MangaReader».

#### Scenario: Первый запуск
- **WHEN** приложение запускается впервые после установки
- **THEN** открывается системный выбор папки, после выбора `Download/manga` библиотека показывает её архивы

#### Scenario: Чтение и «Назад»
- **WHEN** пользователь открывает произведение, читалку и дважды нажимает «Назад»
- **THEN** закрываются читалка, затем страница произведения; третье «Назад» сворачивает приложение

#### Scenario: Клавиатура
- **WHEN** пользователь нажимает на поле поиска
- **THEN** появляется экранная клавиатура, ввод попадает в поле

### Requirement: Лицензии в APK
Сборка APK SHALL класть `LICENSE` и `THIRD_PARTY_NOTICES.md` из корня проекта в `assets/` APK. Эти копии MUST генерироваться при каждой сборке и MUST NOT храниться в репозитории.

#### Scenario: Состав APK
- **WHEN** выполнен `make build-android`
- **THEN** APK содержит `assets/LICENSE` и `assets/THIRD_PARTY_NOTICES.md`, совпадающие с файлами в корне проекта

#### Scenario: Рабочая копия после сборки
- **WHEN** выполнен `make build-android`, затем `git status`
- **THEN** скопированные в `android/app/src/main/assets/` файлы не показываются как новые

### Requirement: Dev-сборка
`make build-android-dev` SHALL собирать `dist/mangareader-dev.apk` — отдельное приложение «MangaReader Dev» с ID `io.github.mangareader.app.dev` и версией с суффиксом `-dev`. Оно MUST ставиться рядом с обычным приложением, со своими настройками, папкой библиотеки, каталогом и данными браузера. Поведение dev-сборки MUST совпадать с обычной, кроме раздела «Разработка» в «Настройках»; ничего из инструментов разработки MUST NOT запускаться само.

В разделе «Разработка» SHALL быть:
- кнопка «Запустить тесты» — сценарии автопрокрутки замера кадров (библиотека, поиск, страница произведения, настройки, лента, постраничный режим, вкладки, плотность сетки) и программного броска (`fling-grid`, `fling-strip`: три броска вниз со скоростью 3000 dp/с, каждый до остановки, затем один вверх; на телефоне и ПК); пока они идут, кнопки раздела недоступны, а по окончании выбранная вкладка и настройки возвращаются;
- кнопка «Ручной замер» / «Остановить замер» — запись интервалов кадров, пока пользователь сам листает; при остановке — одна сводка `manual`;
- по окончании тестов или ручного замера отчёт MUST сохраняться в файл: на Android — в скрытую папку `.perf` в папке библиотеки (сканер её пропускает), на ПК — в папку `perf` рядом с исполняемым файлом; имя `perf-ГГГГММДД-ЧЧММСС.txt`;
- кнопка «Поделиться» (Android) — системное меню «Поделиться» с текстом последнего отчёта; на ПК вместо неё «Открыть папку» с отчётами.

Отчёт MUST содержать версию, устройство, размер и масштаб экрана, частоту экрана (`refresh`, Гц), режим темпа кадров (`pacing`: `choreographer`, `vsync`, `dwm` или `timer`), источник времени показа (`present`: `egl`, `swap` или `dwm`), настройку «Ограничить 60 Гц» (Android), плотность сетки и число галерей, затем по строке сводки на каждый сценарий. Интервалы сводки MUST считаться между показами кадров на экране, а не между тактами цикла. Поля сводки: `n`, `p50`, `p95`, `max`, `slow`, `>25ms`, `1v` (доля кадров, показанных ровно через один vsync после предыдущего), `miss` (доля пропущенных vsync; промежутки длиннее 8 vsync считаются простоем и не учитываются), `dy` (неровность скорости прокрутки: среднее отклонение скорости за vsync от средней двух соседних, делённое на среднюю скорость; смещение берётся в момент рисования кадра, плавный разгон и торможение его не увеличивают), `dyt` и `dyf` (та же неровность только по кадрам с пальцем на экране и по кадрам инерции; `-`, если таких кадров нет), `gc`, `gcmax`, `heap`; в сводках, где палец был на экране (Android), — `tlat` (задержка пересчёта касаний на время кадра). Обычная сборка (`make build-android`) раздела «Разработка» MUST NOT содержать.

#### Scenario: Установка рядом
- **WHEN** на телефоне стоит MangaReader, и пользователь ставит `mangareader-dev.apk`
- **THEN** в списке приложений два приложения: «MangaReader» и «MangaReader Dev», данные обычного не затронуты

#### Scenario: Тесты по кнопке
- **WHEN** пользователь запускает dev-сборку
- **THEN** сценарии не запускаются, пока он не нажмёт «Запустить тесты» в «Настройках» → «Разработка»

#### Scenario: Отчёт в файл и «Поделиться»
- **WHEN** тесты закончились на Android с папкой библиотеки `Download/Manga`
- **THEN** создан файл `Download/Manga/.perf/perf-….txt`, показано уведомление с его именем, а «Поделиться» открывает системное меню с текстом отчёта

#### Scenario: Обычная сборка
- **WHEN** собран `make build-android`
- **THEN** в «Настройках» нет раздела «Разработка»

#### Scenario: Показ кадров в отчёте
- **WHEN** на телефоне 120 Гц приложение рисует кадры по таймеру 60 Гц, и идёт сценарий `grid`
- **THEN** в шапке `refresh: 120`, а в сводке `1v` заметно меньше 100% и `miss` около 50%

#### Scenario: Палец и инерция отдельно
- **WHEN** пользователь в ручном замере листает сетку бросками
- **THEN** в сводке `manual` есть `dyt` по кадрам, пока палец на экране, и `dyf` по кадрам инерции
