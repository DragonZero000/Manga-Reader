# search-index Specification

## Purpose

Индекс поиска в памяти: заполнение при сканировании, правила совпадения слов и условий, порядок и полнота выдачи, подсказки тегов.

## Requirements

### Requirement: Индекс в памяти
Приложение SHALL использовать индекс поиска в памяти, реализующий интерфейс `Index`. Индекс MUST заполняться при каждом сканировании библиотеки (добавленные и изменённые галереи — `Upsert`, удалённые — `Remove`) и MUST быть безопасен для одновременного поиска и обновления из разных горутин.

#### Scenario: Заполнение при сканировании
- **WHEN** библиотека просканирована и в ней есть `example.zip`
- **THEN** поиск по слову `english` возвращает `local:example.zip`

#### Scenario: Удаление архива
- **WHEN** `example.zip` удалён из папки и библиотека повторно просканирована
- **THEN** поиск по слову `english` не возвращает результатов

### Requirement: Совпадение слов
Слово или фраза свободного текста SHALL совпадать с произведением, если оно входит как подстрока (без учёта регистра) хотя бы в одно из полей: основное название, альтернативное название, имя любого тега, тип и имя тега в форме `тип:имя`, сканлейтор, путь файла относительно библиотеки, внешний ID. Если в запросе несколько слов, произведение MUST содержать каждое из них (в одном или разных полях).

#### Scenario: Часть слова в названии
- **WHEN** выполняется поиск `glis`
- **THEN** находится `example.zip` (название «english name»)

#### Scenario: Часть слова в теге
- **WHEN** выполняется поиск `japan`
- **THEN** находится `example.zip` (тег `language:japanese` и название «japanease name»)

#### Scenario: Слова в разных полях
- **WHEN** выполняется поиск `english doujin`
- **THEN** находится `example.zip`: «english» в названии, «doujin» в теге `category:doujinshi`

#### Scenario: Нет совпадения одного слова
- **WHEN** выполняется поиск `english manhwa`
- **THEN** `example.zip` не находится

### Requirement: Совпадение условий
Фильтры запроса SHALL проверяться так: тег («есть»/«нет») — точное совпадение нормализованного имени, а если тип указан — и типа; `title` — подстрока в основном или альтернативном названии; `scanlator` — подстрока (операция «содержит») или точное совпадение («равно») без учёта регистра; `pages` — по фактическому числу страниц; `favorites`, `id` — по значениям метаданных; `size` — по размеру файла; `uploaded` — по дате загрузки; `added` — по времени изменения файла. Произведение без значения поля (ноль, нулевая дата) MUST NOT удовлетворять числовым и датовым фильтрам по этому полю.

#### Scenario: Тег любого типа
- **WHEN** выполняется поиск `tag:japanese`
- **THEN** находится `example.zip` (тег `language:japanese`)

#### Scenario: Тег точного типа
- **WHEN** выполняется поиск `artist:japanese`
- **THEN** `example.zip` не находится

#### Scenario: Подстрока не совпадает с тегом
- **WHEN** выполняется поиск `tag:japan`
- **THEN** `example.zip` не находится: для тега нужно точное имя

#### Scenario: Исключение
- **WHEN** выполняется поиск `english -tag:"tag 3"`
- **THEN** `example.zip` не находится

#### Scenario: Число страниц
- **WHEN** выполняются поиски `pages:2` и `pages:>2`
- **THEN** `example.zip` находится первым поиском и не находится вторым

#### Scenario: Нет значения
- **WHEN** архив без `meta.json` и выполняется поиск `favorites:<10`
- **THEN** этот архив не находится

### Requirement: Выдача результатов
Поиск SHALL возвращать все совпавшие произведения (без ограничения, если в запросе не задан лимит) и их общее число. Порядок MUST соответствовать сортировке запроса; по умолчанию — время изменения файла по убыванию, при равенстве — ключ в натуральном порядке. Пустой запрос (без слов и фильтров) MUST возвращать все произведения.

#### Scenario: Все совпадения
- **WHEN** в библиотеке 3 произведения с тегом `tag 1` и выполняется поиск `tag:"tag 1"`
- **THEN** возвращаются все 3 ключа и общее число 3

#### Scenario: Пустой запрос
- **WHEN** выполняется поиск с пустым запросом
- **THEN** возвращаются все произведения библиотеки

### Requirement: Подсказки тегов
Индекс SHALL возвращать теги, имя которых начинается с заданного префикса (без учёта регистра), с числом произведений для каждого тега, отсортированные по убыванию числа, затем по имени; при заданном типе — только теги этого типа; не более заданного лимита.

#### Scenario: Подсказка по префиксу
- **WHEN** запрашиваются подсказки для префикса `tag` без типа с лимитом 10
- **THEN** возвращаются `tag:tag 1`, `tag:tag 2`, `tag:tag 3` с числом 1 у каждого
