# Архитектура

MangaReader — одно Go-приложение на [Fyne](https://fyne.io) для Windows и Android. Встроенный браузер на Windows — отдельный процесс портативного Firefox ESR, на Android — GeckoView внутри APK с экранами на Kotlin.

## Карта репозитория

```text
cmd/mangareader/     точка входа; метаданные приложения для Android
internal/            код приложения (см. «Пакеты»)
tools/               утилиты сборки: android-build, fetch-firefox, version
android/             Gradle-проект Android; экраны браузера на Kotlin
openspec/            спецификации и история изменений (OpenSpec)
docs/                документация (en, ru, images)
testdata/            example.zip — пример архива
.github/workflows/   CI и релизы
FyneApp.toml         метаданные приложения и единственный источник версии
```

## Пакеты

| Пакет | Назначение |
|---|---|
| `cmd/mangareader` | Точка входа: создаёт приложение Fyne, собирает зависимости (`internal/app`), запускает оболочку UI |
| `internal/app` | Сборка зависимостей без виджетов: папка библиотеки, хранилище, сканер, индекс поиска, браузер, ключи настроек |
| `internal/paths` | Папка приложения на ПК (портативный режим): рядом с exe, при `go run` — рабочая папка |
| `internal/storage` | Доступ к файлам библиотеки и настройки: файловая система на ПК, Storage Access Framework (JNI) на Android; метки источника загрузки (NTFS-поток, `Zone.Identifier`) |
| `internal/library` | Сканирование папки, разбор zip и `meta.json`, определение типа файлов, отслеживание изменений (fsnotify), размеры страниц |
| `internal/model` | Модель: `Gallery`, `Tag`, `Key`, наложение тегов пользователя (`EffectiveTags`, `TagViews`), натуральная сортировка |
| `internal/search` | Поля поиска, разбор запроса, `Query`, интерфейс `Index` и индекс в памяти |
| `internal/problems` | Список ошибок библиотеки и статус их просмотра |
| `internal/thumbs` | Миниатюры обложек: декодирование в фоне, уменьшение, кэш в памяти |
| `internal/pages` | Загрузка страниц для читалки с приоритетами и геометрия отображения |
| `internal/browser` | Встроенный браузер Windows: профиль Firefox, расширение-мост, запуск, привязка окна, уборка реестра |
| `internal/mobilebrowser` | Мост к браузеру Android (JNI): открыть, очистить данные, получить сообщения о загрузках |
| `internal/catalog` | Каталог библиотеки в SQLite (`library.db`, FTS5, тег `sqlite_fts5`): результаты сканирования между запусками, индекс поиска (`search.Index`), обложки на диске, копия ссылок скачанных файлов; восстанавливаемый кэш |
| `internal/userdata` | Пользовательские данные о произведениях в SQLite (`user.db`): записи произведений со стабильным `uid`, миграции схемы, резервная копия повреждённого файла, сверка со сканированием и перенос записей по отпечатку содержимого, свои и скрытые теги, позиция чтения |
| `internal/i18n` | Язык интерфейса: переводы из `locales/<язык>.json` (go-i18n), формы множественного числа, форматы дат, чисел и размеров, выбор языка при запуске, встроенные тексты Fyne на языке приложения |
| `internal/display` | Частота экрана окна приложения на Android (JNI, `DisplayRate.kt`): ограничение 60 Гц; на других платформах — заглушка |
| `internal/appversion` | Версия из `FyneApp.toml` и номер сборки Android |
| `internal/ui` | Оболочка: окно, вкладки, toast-уведомления, связь экранов с сервисами |
| `internal/ui/screens` | Экраны: библиотека, поиск, ошибки, настройки |
| `internal/ui/details` | Страница произведения |
| `internal/ui/reader` | Читалка: постраничный режим и лента |
| `internal/archtest` | Тесты архитектурных границ и структуры документации |
| `tools/android-build` | Сборка APK: `libmangareader.so` через NDK, Java-классы Fyne, лицензии в `assets/`, Gradle |
| `tools/fetch-firefox` | Скачивание и распаковка закреплённой версии Firefox ESR (проверка SHA-256) |
| `tools/version` | Печать версии и номера сборки для Makefile и CI |

## Границы пакетов

Виджеты Fyne (`fyne.io/fyne/v2/widget`, `container`) используются **только** в `internal/ui/...`. Сервисные пакеты (`app`, `library`, `search`, `storage`, `browser` и др.) от виджетов не зависят и тестируются без окна. Это проверяет `internal/archtest` для `GOOS=windows` и `GOOS=android`.

Новый пакет в `internal/` нужно добавить в список в [`internal/archtest/imports_test.go`](../../internal/archtest/imports_test.go) и в таблицу выше — на обоих языках.

## Платформы и build-теги

Платформенный код разделён по тегам и суффиксам файлов:

| Тег | Файлы | Пример |
|---|---|---|
| `windows` / `!windows` | `*_windows.go`, `*_other.go` / `stub_other.go` | окно и реестр браузера, NTFS-потоки |
| `android` / `!android` | `*_android.go`, `other.go`, `*_other.go` | SAF, JNI-мост к GeckoView, частота экрана, метаданные приложения |
| `frameprobe` / `!frameprobe` | `frameprobe_on.go`, `frameprobe_off.go` | замер кадров для разработки (`make … EXTRA_TAGS=frameprobe`) |

На платформах, где функции нет, работает заглушка: например, `internal/browser` на Android сообщает, что браузер не поддерживается, а UI не показывает Windows-настройки браузера. Новая платформенная функция всегда сопровождается заглушкой для остальных платформ.

Linux пока не поддерживается.

## Потоки и UI

Приложение мигрировано на `fyne.Do` (`[Migrations] fyneDo = true` в `FyneApp.toml`): виджеты меняются **только** из основного потока. Сканирование, декодирование миниатюр и страниц, поиск и события браузера выполняются в горутинах и возвращают результат в UI через `fyne.Do`. `make run` запускает приложение с проверками потоков Fyne; релизные сборки — с тегом `migrated_fynedo`, без проверок.

## Пользовательские данные

Приложение хранит два файла SQLite рядом друг с другом (на ПК — рядом с exe, на Android — в личной папке приложения):

| Файл | Пакет | Характер |
|---|---|---|
| `library.db` | `internal/catalog` | Кэш: восстанавливается из архивов. Пересоздаётся при смене версии схемы или повреждении, очищается при смене папки библиотеки |
| `user.db` | `internal/userdata` | Пользовательские данные (свои и скрытые теги, позиция чтения; в будущем группы): из архивов не восстановить. Никогда не пересоздаётся: схема меняется миграциями (`PRAGMA user_version`); повреждённый файл переименовывается в `user.db.broken-<ГГГГММДД-ЧЧММСС>` и создаётся новый; файл более новой версии приложения не трогается, пользовательские данные в этом запуске недоступны |

Запись произведения (`works`) хранит стабильный `uid`, ключ папки библиотеки, путь относительно неё, отпечаток содержимого и время «сироты» (файл не найден). Пользовательские данные ссылаются на `uid`, а не на путь. Запись создаётся только при первом сохранении данных о произведении. Ключ папки на ПК — `app:manga` (перенос портативной папки данные не отвязывает), на Android — tree-URI SAF.

Отпечаток (`Gallery.Fingerprint`) — SHA-256 списка страниц из оглавления zip (путь, CRC32, размер); вычисляется при разборе архива без распаковки, `meta.json` и имя файла архива на него не влияют.

Сверка: `library.Source` уведомляет `Observer` после каждого успешного сканирования (до публикации списка и индекса) и после удаления через приложение; адаптер в `internal/app` вызывает `userdata.Store.Reconcile` одной транзакцией:

1. записи, файл которых найден, теряют отметку «сирота» (изменившийся отпечаток обновляется);
2. новый файл забирает запись пропавшего, если отпечаток совпадает ровно у одной пропавшей записи и ровно у одного нового файла (переименование или перемещение);
3. остальные пропавшие записи становятся сиротами — если только сканирование нашло хоть один файл;
4. сироты старше срока хранения (настройка `userdata.retention`, по умолчанию 30 дней, 0 — бессрочно) удаляются вместе с данными.

Неуспешное сканирование ничего не меняет; затрагиваются только записи текущей папки. Ошибочные и занятые файлы считаются найденными.

### Наложение тегов

`Gallery.Tags` — теги из `meta.json`, они кэшируются в `library.db`, как раньше. Изменения пользователя — отдельное наложение: `Gallery.Custom` (свои теги в порядке добавления) и `Gallery.Hidden` (скрытые оригинальные), оба `json:"-"`, поэтому в кэш сканера не попадают. Их источник — таблица `user_tags(uid, kind, type, name, seq)` в `user.db`, она удаляется вместе с записью произведения. `EffectiveTags()` — оригинальные теги без скрытых плюс свои; `TagViews()` возвращает все теги с происхождением для режима редактирования. Запись о скрытом теге, которого больше нет в `meta.json`, не учитывается.

`library.Source` применяет наложение через интерфейс `library.Overlay` (адаптер в `internal/app` читает `userdata.Store.Overlays` для текущего ключа папки):

- `Scan`: обход → `Observer.Scanned` (сверка, перенос по отпечатку) → `Overlay.Apply` ко всем, новым и изменённым галереям → публикация и обновление индекса. Файл, перенесённый по отпечатку, приходит как новый и индексируется со своими тегами в том же сканировании;
- `LoadCatalog`: `Apply` к галереям из каталога; индекс уже хранит наложение;
- `Refresh(k)` после правки перечитывает наложение одной галереи, заменяет её в списке (копирование при записи) и обновляет в индексе; `Reindex` делает то же для всех галерей. Оба берут блокировку сканирования, поэтому устаревший результат сканирования не перезапишет правку; сканирование, начатое в это время, ждёт их, а не пропускается.

`Services.EditTags` (только не в UI-потоке) проверяет имя (пустое, длиннее 100 символов, `"` → `ErrTagInvalid`) и дубликаты среди оригинальных тегов, включая скрытые, и своих (`ErrTagExists`), затем вызывает `userdata.Ensure`, операцию и `Source.Refresh`. Страница произведения работает с ним через интерфейс `details.TagEditor`, реализованный в `Shell`; после успешной правки текущий поиск повторяется.

В индексе поиска у тега есть происхождение: `tags.src` — 0 у видимого оригинального, 1 у своего, 2 у скрытого. Слова (`docs_fts.hay`) и подсказки используют только 0 и 1. `search.Value.Scope` задаёт область фильтра тега: действующие теги для `tag:` и полей типов, свои для `custom-tag:`, скрытые для `hidden-tag:`. `MemIndex` хранит те же три множества и проходит те же проверки `search/indextest`.

Индекс в `library.db` хранит результат наложения, поэтому он должен соответствовать `user.db`. При создании `user.db` получает случайную эпоху (`meta.epoch`); `library.db` запоминает эпоху, с которой построен индекс (`meta.overlay_epoch`, `none` — без пользовательских данных). При запуске, если они различаются (`user.db` восстановлен из копии, пересоздан после повреждения, недоступен), после `LoadCatalog` библиотека в фоне переиндексируется и эпоха записывается. Перестройка индекса из кэша сканера и смена папки библиотеки сбрасывают сохранённую эпоху.

Позиция чтения — таблица `progress(uid, page, page_index, total, finished, updated_at)` в `user.db`, одна строка на произведение: имя файла страницы в архиве, её номер и число страниц на момент сохранения, отметка «дочитано». `app.ProgressService` держит позиции текущей папки в памяти (их читают кнопка «Продолжить» и меню в UI-потоке) и пишет в базу одной фоновой горутиной по очереди, поэтому «дочитано» не перезаписывается более ранней позицией; после сверки со сканированием и смены папки позиции перечитываются. `app.Resume` выбирает страницу для «Продолжить»: сначала по имени, затем по номеру (позиция может быть неточной); у дочитанного — первая страница после последней прочитанной, если она появилась. Оболочка сохраняет позицию через секунду после смены страницы, при закрытии читалки и при уходе приложения в фон.

## Локализация

Тексты для пользователя лежат в `internal/i18n/locales/<язык>.json` (английский — язык по умолчанию) и берутся через `i18n.T` / `i18n.N` только в `internal/ui`; тест падает на строковом литерале с кириллицей в коде UI, другой — на ключе, которого нет в каком-то языке. Язык выбирается один раз при запуске (настройка `ui.language`, иначе язык системы, иначе английский) до построения экранов; смена применяется после перезапуска. Сервисные пакеты языка не знают: их ошибки несут вид и параметры, `err.Error()` — технический текст на английском для журнала, а UI переводит известные виды (`screens.ErrorText`, `screens.ProblemText`). Логи — на английском. Встроенные тексты Fyne переводятся на язык приложения загрузкой его переводов под тегом системной локали (`i18n.ApplyToFyne`). Браузер Android получает язык в настройках и берёт строки из `res/values*/strings.xml` на этом языке.

Новый язык: `internal/i18n/locales/<язык>.json`, копия `base.<язык>.json` Fyne в `internal/i18n/fyne/`, `android/app/src/main/res/values-<язык>/strings.xml`.

## Встроенный браузер

### Windows

```text
MangaReader ──запуск──▶ firefox.exe -profile browser\profile
     ▲                        │
     │  127.0.0.1 + токен     │ расширение bridge@mangareader.app
     └────────────────────────┘ (адрес страницы загрузки, команды)
```

- `tools/fetch-firefox` распаковывает установщик Firefox ESR (`/ExtractDir`) в `browser\firefox`; версия и SHA-256 закреплены в коде.
- При каждом запуске приложение перезаписывает `browser\profile\user.js` (папка загрузок = папка библиотеки, отключённые обновления и телеметрия, тёмная тема) и пересобирает расширение `bridge@mangareader.app.xpi` из `internal/browser/ext`.
- Расширение сообщает приложению адрес страницы, с которой начата загрузка, по `127.0.0.1` с одноразовым токеном; приложение пишет его в NTFS-поток `:mangareader.source` файла.
- Окно Firefox находится по процессу и получает окно приложения владельцем (Win32): поверх приложения, сворачивается вместе с ним, без кнопки на панели задач.
- После закрытия браузера удаляются служебные значения Firefox в `HKCU\Software\Mozilla\Firefox`, относящиеся к встроенному экземпляру.

### Android

- GeckoView подключён в `android/app/build.gradle.kts`; экраны браузера — Kotlin в `android/app/src/main/kotlin/io/github/mangareader/app/browser/` (`BrowserActivity`, `BrowserEngine`, `DownloadManager`, `DownloadService` и др.).
- Go вызывает Kotlin и получает события через JNI (`internal/mobilebrowser`, `GoBridge.kt`): открыть браузер, очистить данные, сообщить о загрузке (путь и адрес страницы).
- Загрузки пишутся в выбранную SAF-папку через `DownloadService` (foreground-сервис с уведомлением), во время загрузки — `имя.part`.

## Версия, сборка и CI

- Версия — только `FyneApp.toml`; `internal/appversion` проверяет формат и вычисляет `versionCode`. Подробно — [building.md](building.md#версия).
- `Makefile` — обёртка над `go build`, `tools/android-build` и `tools/fetch-firefox`; работает из PowerShell, cmd и Git Bash (на Windows команды выполняет `cmd.exe`).
- CI и релизы — [`.github/workflows/`](../../.github/workflows/); порядок выпуска и ключи — [building.md](building.md#выпуск-релиза).
- Сторонние компоненты, которые попадают в пакеты, перечислены в [`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md).

## OpenSpec

Требования и история решений хранятся в [`openspec/`](../../openspec/) ([OpenSpec](https://github.com/Fission-AI/OpenSpec)):

- `openspec/specs/<возможность>/spec.md` — действующие требования (что приложение должно делать), со сценариями;
- `openspec/changes/archive/` — завершённые изменения: предложение, дизайн с альтернативами, задачи;
- `openspec/config.yaml` — контекст проекта и правила для новых изменений (их читают и люди, и AI-ассистенты).

Порядок работы над изменением — в [CONTRIBUTING](../../CONTRIBUTING.ru.md).
